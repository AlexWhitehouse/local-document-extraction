# Session-Only Workspace Live Updates Over Durable Object WebSockets

Category: enhancement
Status: completed

## Parent

.scratch/workspace-product-data-scale-out/PRD.md

## What to build

Add Workspace-scoped live updates for the SPA using Durable Object WebSocket Hibernation. The SPA should open one session-only live update connection for the accepted Workspace context. The Worker validates the WebSocket upgrade request and session Workspace membership before proxying to the Workspace product store. The Workspace product store broadcasts versioned batch-envelope job lifecycle notifications after authoritative state changes.

The frontend should use live updates to keep the document list and selected live jobs fresh without one-second polling while a live connection is active. Completed job details and reconnect recovery still use HTTP because WebSocket notifications are not durable history and do not carry Extraction results.

## Agent Brief

**Category:** enhancement
**Summary:** Add session-only Workspace live updates for Extraction job lifecycle changes over Durable Object WebSocket Hibernation.

**Current behavior:**
Workspace product data is now authoritative inside the per-Workspace product store. Document submission creates queued Extraction jobs through that store, and the Extraction processor claims, completes, and fails Extraction jobs through authoritative Workspace product data. Job list and detail reads are still HTTP-only. The SPA refreshes live selected Extraction jobs with one-second polling while a job is queued or processing.

There is no Workspace live update WebSocket route yet. The Workspace product store does not currently accept hibernatable WebSockets or broadcast lifecycle events after persisted job changes. The existing workspace-scoped product API authentication supports both signed-in sessions with an accepted Workspace context and Workspace API keys; this feature needs a narrower session-only authorization path.

**Desired behavior:**
The backend should expose `GET /v1/workspaces/:workspaceId/live` as a session-only WebSocket upgrade route for accepted Workspace contexts. The Worker should reject non-GET requests, missing or invalid WebSocket upgrade requests, unauthenticated callers, non-members, and Workspace API key callers before handing the request to the Workspace product store.

The Workspace product store should terminate live update sockets with the Durable Object WebSocket Hibernation API. It should use serialized WebSocket attachments for minimal per-connection state, keep constructor work lightweight, and avoid application-level heartbeat timers so idle objects can hibernate.

After authoritative Workspace product data changes are persisted for Extraction job lifecycle transitions, the Workspace product store should broadcast a versioned batch message envelope to connected Workspace live update clients. Each envelope may contain one or more logical job lifecycle events. Job events should include enough summary fields for the SPA to update the document list and selected live jobs, but must not include Extraction results, extracted answers, evidence, API keys, account emails, Source file binary contents, or Document contents.

The frontend should open exactly one live update connection for the current accepted Workspace context. It should close and replace the connection when the accepted Workspace context changes, the user signs out, or access is lost. While the live update connection is active, the SPA should not use the one-second selected-live-job polling path. After reconnecting, the SPA should revalidate authoritative job state over HTTP because Workspace live updates are not durable history. Completed Extraction job details should still be fetched over HTTP when opened.

**Key interfaces:**
- `GET /v1/workspaces/:workspaceId/live` — new session-only Workspace live update WebSocket upgrade route.
- Session Workspace authorization — should validate Better Auth session membership for the path Workspace ID and should not accept Workspace API keys for this route.
- `WorkspaceProductStoreRpc` / Workspace product store methods — should expose a domain operation for accepting live update sockets and should broadcast lifecycle notifications after persisted state changes.
- Extraction job lifecycle operations — queued, processing, completed, failed, and queue-send-failed transitions should emit live update events only after authoritative product state is written.
- Workspace live update message envelope — should be versioned, batched, and safe to extend without breaking clients.
- Document controller live-update integration — should own connection lifecycle, document list updates, selected live Extraction job updates, reconnect revalidation, and polling fallback behavior.
