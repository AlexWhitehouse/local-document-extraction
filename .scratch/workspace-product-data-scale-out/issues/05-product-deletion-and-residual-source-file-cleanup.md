# Product Deletion and Residual Source File Cleanup

Category: enhancement
Status: completed

## Parent

.scratch/workspace-product-data-scale-out/PRD.md

## What to build

Complete deletion and cleanup behavior for Workspace product data after the authoritative store move. Job deletion, Template deletion cascades, successful processing cleanup, and Workspace deletion residual cleanup should all coordinate with the Workspace product store and R2 without relying on legacy global D1 product rows as the authority.

Normal successful Extraction job processing should delete the Source file binary and mark cleanup in authoritative product data. Workspace deletion cleanup should be a background, idempotent residual sweep for Source files that normal lifecycle cleanup did not delete, such as failed, queued, processing, or cleanup-failed jobs.

## Acceptance criteria

- [x] Job deletion removes authoritative job/result metadata from Workspace product data and deletes any remaining Source file binary idempotently.
- [x] Template deletion removes or hides the Template through Workspace product data and handles associated product data consistently with existing user-visible behavior.
- [x] Successful processing cleanup deletes the R2 Source file binary after completion and records cleanup state in authoritative Workspace product data.

- [x] Workspace deletion initiates residual Source file cleanup rather than relying on inline reads from legacy global D1 product tables.
- [x] Residual Source file cleanup processes remaining R2 keys in batches and is safe to retry.
- [x] Residual Source file cleanup skips already-deleted Source files safely.
- [x] Legacy global D1 product tables are not used as the authoritative source for product deletion or Source file cleanup.
- [x] Tests cover job deletion, Template deletion behavior, successful processing cleanup, cleanup failure tolerance, and idempotent residual cleanup.

## Agent Brief

**Category:** enhancement
**Summary:** Complete product-data deletion and Source file cleanup through the Workspace product store.

**Current behavior:**
The Template and Extraction processor product-data slices are complete enough for this cleanup slice to proceed. Authoritative Template, Extraction job, Extraction result, and Source file metadata now live in the Workspace product store for the main create/read/lifecycle paths.

Deletion and cleanup behavior is still incomplete after the authority move. Job deletion and Workspace deletion cleanup still rely on legacy global D1 product tables to discover or delete product rows and Source file keys. Successful Extraction processing deletes the Source file binary from R2 after completion, but it does not persist cleanup state back to authoritative Workspace product data. Existing Source file metadata can therefore drift from R2 cleanup outcomes, and Workspace deletion cannot reliably sweep residual Source files from the new authority.

**Desired behavior:**
Job deletion should remove the authoritative Extraction job metadata and any completed Extraction results from the Workspace product store, then idempotently delete any remaining Source file binary from R2. Deleting a missing job should keep the current public not-found behavior.

Template deletion should continue to use authoritative Workspace product data and preserve existing user-visible behavior. If existing behavior treats Template deletion as hiding/removing the Template from normal reads, keep that contract. Associated Extraction job/result/Source file behavior should be handled consistently with the product-data authority and should not fall back to legacy global D1 product rows as the source of truth.

Successful Extraction processing should delete the R2 Source file binary after the job has been completed and Extraction results have been persisted. The cleanup outcome should be recorded in authoritative Workspace product data. Cleanup failure must not corrupt or roll back completed Extraction results; it should leave durable state that makes residual cleanup retryable.

Workspace deletion should initiate residual Source file cleanup using authoritative Workspace product data rather than reading Source file keys from legacy global D1 product tables. Residual cleanup is for Source files that normal lifecycle cleanup did not delete, including queued, processing, failed, or cleanup-failed Extraction jobs. The cleanup path should be batched, idempotent, safe to retry, and safe when R2 objects are already missing.

Legacy global D1 product tables may remain for rollback/archive, but this issue should stop using them as the authoritative source for product deletion or Source file cleanup.

**Key interfaces:**
- `WorkspaceProductStoreRpc` — add domain-specific operations for deleting Extraction jobs, discovering residual Source files, marking Source file cleanup success/failure, and any Template deletion cascade behavior this slice owns.
- Extraction job lifecycle cleanup contract — completed jobs keep durable results even if Source file cleanup fails, and cleanup status is stored separately from the completed Extraction result.
- Source file metadata contract — Source file metadata remains in Workspace product data, Source file binaries remain in R2, and cleanup markers make deletion idempotent and retryable.
- Workspace deletion flow — control-data deletion remains responsible for Workspace membership/invitation/workspace records, while residual product Source file cleanup routes through the Workspace product store instead of legacy product tables.
- R2 deletion helper behavior — deleting an already-missing Source file should be treated as safe/idempotent.
