# Require Account Email Verification for Email Password Auth

Category: enhancement
Status: completed

## Parent

.scratch/account-email-verification/PRD.md

## What to build

Configure Better Auth so email/password users must complete **Account email verification** before application access. Email/password sign-up should send a verification email without granting access, unverified sign-in should be blocked while sending a fresh verification link, and successful verification should return to the application root and sign the user in automatically.

- [x] The verification callback returns the user to the application root.

## Agent Brief

**Category:** enhancement
**Summary:** Require Account email verification before email/password users can access the application.

**Current behavior:**
Email/password account creation and sign-in do not require **Account email verification** before application access. Better Auth already stores user email verification state, and the Worker now has reusable transactional email rendering/scheduling infrastructure for the **Account email verification** message, but Better Auth is not yet configured to send or enforce the verification flow.

**Desired behavior:**
Email/password sign-up should create the Better Auth account and send an **Account email verification** email without granting usable application access. Email/password sign-in should be blocked while the user's email is unverified, and that blocked sign-in attempt should send a fresh verification link. Successful verification should return the user to the application root and sign the user in automatically. Existing unverified email/password users should not be backfilled as verified and should be blocked on future sign-in, but existing sessions should not be forcibly invalidated by this slice.

**Key interfaces:**
- Better Auth email verification configuration — should provide the send hook, send-on-sign-up behavior, send-on-sign-in behavior, required verification for email/password sign-in, automatic sign-in after verification, and application-root callback behavior.
- **Account email verification** email renderer — should be used to render the verification message that contains the Better Auth verification URL.
- Transactional email scheduling contract — auth-triggered verification email sends should use Worker scheduling when the request path can provide it, so sign-up and sign-in responses are not blocked by email delivery latency.
- Auth route setup — should make any scheduling context needed by Better Auth verification hooks available without forcing simple session-read paths to require Worker scheduling context.

**Acceptance criteria:**
- [x] Email/password sign-up triggers **Account email verification** without granting usable application access.
- [x] Email/password sign-in is blocked when the account email is unverified.
- [x] An unverified email/password sign-in attempt sends a fresh **Account email verification** link.
- [x] The verification callback returns the user to the application root.
- [x] Successful **Account email verification** signs the user in automatically.
- [x] Existing unverified email/password users are not backfilled as verified and are blocked on future sign-in.
- [x] Existing sessions are not forcibly invalidated by this slice.
- [x] Auth behavior tests cover sign-up verification send and unverified sign-in blocking/resend behavior.

**Out of scope:**
- Moving personal **Workspace** bootstrap after **Account email verification**; that is covered by a separate issue.
- Updating the frontend **Account verification prompt** or unverified sign-in messaging.
- Adding a separate resend verification control.
- Adding password reset email sending or a forgot-password flow.
- Adding a durable email queue, audit table, provider abstraction, or retry orchestration.
