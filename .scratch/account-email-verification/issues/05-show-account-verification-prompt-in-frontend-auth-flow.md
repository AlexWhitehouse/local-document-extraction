## Agent Brief

**Category:** enhancement
**Summary:** Show Account verification prompt and unverified sign-in messaging in the frontend auth flow.

**Current behavior:**
The frontend email/password sign-up flow still treats successful account creation like an immediately usable session path: it can refetch the session and continue toward Workspace resolution after `signUp.email` succeeds. The auth screen has no dedicated **Account verification prompt** telling the user to check their email before account access is available. Email/password sign-in failures are shown through a generic safe failure message, so an unverified account sign-in does not clearly tell the user to verify their email or that a fresh verification link was sent.

**Desired behavior:**
After successful email/password sign-up, the frontend should show an **Account verification prompt** on the auth screen telling the user to check their email before signing in. That success path must not refetch the session, resolve a **Workspace**, or otherwise enter the authenticated app shell. When an unverified email/password user attempts sign-in and the backend reports the verification-required failure, the frontend should show a user-facing message explaining that they need to verify their email and that a new verification link was sent. This slice should rely on sign-in retry as the recovery path and should not add a separate resend verification control.

**Key interfaces:**
- Auth profile/controller state — should represent an **Account verification prompt** as auth-screen state after successful email/password sign-up.
- Auth screen presentation props — should render the prompt as user-visible auth-screen content without requiring an authenticated session.
- Email/password sign-up handler — should clear password fields after success, avoid session refetch, and leave the user outside Workspace resolution.
- Email/password sign-in error handling — should map the backend's unverified-email/verification-required auth error to the agreed verification message while keeping other sign-in failures generic and safe.
- Frontend auth tests — should verify user-visible outcomes for the prompt and unverified sign-in message rather than private implementation details.

**Acceptance criteria:**
- [x] Successful email/password sign-up shows an **Account verification prompt** telling the user to check their email before signing in.
- [x] Successful email/password sign-up does not refetch session or attempt to resolve a **Workspace**.
- [x] Unverified email/password sign-in displays a message telling the user to verify their email and that a new verification link was sent.
- [x] The frontend does not add a separate resend verification control in this slice.
- [x] Frontend auth tests cover the sign-up prompt and unverified sign-in message as user-visible behavior.

**Out of scope:**
- Changing Better Auth backend verification configuration or email sending behavior.
- Moving personal **Workspace** bootstrap after **Account email verification**.
- Adding a separate resend verification button or flow.
- Adding password reset email sending or a forgot-password flow.
- Adding a dedicated verification-success route or page.
