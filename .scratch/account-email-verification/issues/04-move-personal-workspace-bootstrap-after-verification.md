# Move Personal Workspace Bootstrap After Verification

Category: enhancement
Status: completed

## Parent

.scratch/account-email-verification/PRD.md

## What to build

Move personal **Workspace** creation so it happens only after **Account email verification** gives the user account access, while preserving verified social sign-in as a complete onboarding path. Bootstrap should be idempotent and should not be suppressed by pending **Workspace invitations**.

## Acceptance criteria

- [x] Email/password account creation no longer creates a personal **Workspace** before **Account email verification**.
- [x] Successful **Account email verification** creates a personal **Workspace** when the user has no accepted **Workspace membership**.
- [x] Successful **Account email verification** does not create a duplicate personal **Workspace** when the user already has accepted **Workspace membership**.
- [x] Pending **Workspace invitations** do not suppress post-verification personal **Workspace** creation.
- [x] A trusted social provider's verified email claim satisfies **Account email verification** without sending a separate verification email.
- [x] Verified Google social sign-in can still create a personal **Workspace** when needed.
- [x] Tests cover idempotent bootstrap and the pending-invitation case.

## Agent Brief

**Category:** enhancement
**Summary:** Move personal Workspace bootstrap so it happens only after Account email verification grants account access.

**Current behavior:**
Email/password account creation can still create durable personal **Workspace** state before **Account email verification** has completed. Better Auth is already configured to require verification for email/password access, and reusable Workspace bootstrap policy already exists, but the bootstrap trigger is still tied to account creation rather than the point where verified account access is granted. The existing bootstrap policy is idempotent for accepted **Workspace membership**, and pending **Workspace invitations** do not count as accepted access.

**Desired behavior:**
Email/password sign-up should create the Better Auth user and send the **Account email verification** email without creating a personal **Workspace**. When successful **Account email verification** gives the user account access, the backend should create a personal **Workspace** only if the user has no accepted **Workspace membership**. Retried verification or an already accepted **Workspace membership** must not create duplicates. Pending **Workspace invitations** must not suppress personal **Workspace** creation because they are not accepted access. A trusted social provider's verified email claim should continue to satisfy **Account email verification**, and verified Google social sign-in should still create a personal **Workspace** when the user needs one.

**Key interfaces:**
- Better Auth account lifecycle configuration — account creation should no longer be the trigger that creates a personal **Workspace** for email/password users before verification.
- Better Auth email verification success path — successful **Account email verification** should invoke the idempotent personal **Workspace** bootstrap behavior for the verified user.
- Social provider sign-in behavior — trusted provider-verified email should remain a complete onboarding path and should create a personal **Workspace** when the user has no accepted **Workspace membership**.
- Workspace bootstrap policy — should continue to check accepted **Workspace membership** before creating a personal **Workspace** and starter **Template**.
- Pending **Workspace invitation** handling — pending invitations should remain separate from accepted **Workspace membership** and must not prevent bootstrap.

**Acceptance criteria:**
- [x] Email/password account creation no longer creates a personal **Workspace** before **Account email verification**.
- [x] Successful **Account email verification** creates a personal **Workspace** when the user has no accepted **Workspace membership**.
- [x] Successful **Account email verification** does not create a duplicate personal **Workspace** when the user already has accepted **Workspace membership**.
- [x] Pending **Workspace invitations** do not suppress post-verification personal **Workspace** creation.
- [x] A trusted social provider's verified email claim satisfies **Account email verification** without sending a separate verification email.
- [x] Verified Google social sign-in can still create a personal **Workspace** when needed.
- [x] Tests cover idempotent post-verification bootstrap and the pending-invitation case.

**Out of scope:**
- Configuring Cloudflare Email Sending or reusable transactional email rendering; those are covered by earlier account email verification issues.
- Reworking frontend **Account verification prompt** or unverified sign-in messaging.
- Adding a separate resend verification control.
- Adding password reset email sending or a forgot-password flow.
- Adding a durable email queue, audit table, provider abstraction, or retry orchestration.
