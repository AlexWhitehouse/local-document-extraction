## Agent Brief

**Category:** enhancement
**Summary:** Add reusable transactional email sending, scheduling, and the Account email verification template.

**Current behavior:**
The Worker has a Cloudflare Email Sending binding named `EMAIL`, and generated Worker environment types expose that binding. Backend auth code does not yet have a reusable transactional email sending module, a non-blocking scheduling contract for auth-triggered sends, or a code-owned **Account email verification** template. Better Auth email verification behavior is intentionally separate and should be wired in a later issue.

**Desired behavior:**
Backend code should expose a small generic transactional email interface that can send a caller-provided message immediately through the Worker email binding. It should also expose a scheduling interface that uses Worker scheduling when available, logs send failures, and does not synchronously fail the caller when scheduled delivery fails. A code-owned **Account email verification** template should render the agreed sender, subject, HTML body, plain-text body, verification URL, and unexpected-recipient guidance.

**Key interfaces:**
- Generic transactional email message shape — accepts sender identity, recipient, subject, plain-text body, and optional HTML body from callers rather than reading a global sender.
- Immediate email sending function — sends the generic message through the generated Cloudflare Email Sending binding shape.
- Scheduled email sending function — accepts an optional Worker scheduling context such as `waitUntil`, uses it when present, and logs asynchronous send failures without throwing synchronously.
- **Account email verification** template renderer — pure rendering contract that accepts a verification URL and returns sender, subject, HTML body, and plain-text body.

**Acceptance criteria:**
- [ ] A generic email sending interface accepts caller-provided sender identity, recipient, subject, text body, and optional HTML body.
- [ ] An immediate send path sends through the generated `EMAIL` binding shape without hand-rolled Worker binding types.
- [ ] A scheduling interface uses Worker scheduling when provided and logs send failures without throwing synchronously.
- [ ] The **Account email verification** template renders from `Document Extraction <no-reply@extract.t3m.uk>` with subject `Verify your Document Extraction account`.
- [ ] The **Account email verification** template includes the verification URL in both HTML and plain text.
- [ ] The **Account email verification** template tells unexpected recipients they can ignore the email.
- [ ] Focused tests cover template rendering and non-blocking scheduling behavior.

**Out of scope:**
- Configuring Better Auth email verification hooks or sign-in/sign-up verification behavior.
- Moving personal **Workspace** bootstrap after **Account email verification**.
- Updating frontend auth flow or **Account verification prompt** behavior.
- Adding a durable email queue, retry orchestration, audit table, provider abstraction, password reset email, or Workspace invitation email.
