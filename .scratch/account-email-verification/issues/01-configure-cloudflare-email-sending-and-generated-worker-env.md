## Agent Brief

**Category:** enhancement
**Summary:** Configure Cloudflare Email Sending and generated Worker environment types for Account email verification.

**Current behavior:**
The Worker does not expose a Cloudflare Email Sending binding, so backend code cannot send **Account email verification** emails through the platform binding. Generated Wrangler Worker types already provide a global Worker environment shape, but application domain types still manually export Worker binding fields. This means adding new bindings risks hand-rolled type drift instead of relying on generated Wrangler types.

**Desired behavior:**
The Worker should have a Cloudflare Email Sending binding named `EMAIL`, with local development configured to use the real Cloudflare Email Sending service. Wrangler-generated Worker types should include that binding, and backend code should compile against generated Worker `Env` for platform bindings while keeping application domain types such as **Workspace** and queue message payloads available separately.

**Key interfaces:**
- Worker configuration shape — should include a `send_email` binding named `EMAIL` and the local-development setting needed to send through the real service.
- Generated Worker `Env` — should be regenerated by Wrangler and should include `EMAIL` rather than being manually extended.
- Application domain types module — should no longer be the source of truth for Worker platform binding fields, but should continue exporting domain-level types used by backend code.
- Backend type imports — should distinguish generated Worker environment types from application domain types.

**Acceptance criteria:**
- [x] The Worker configuration includes a Cloudflare Email Sending binding named `EMAIL` and local development uses the real Cloudflare Email Sending service.
- [x] Wrangler-generated Worker types include the `EMAIL` binding.
- [x] Application domain types no longer manually export Worker binding fields that should come from generated Wrangler types.
- [x] Existing backend code compiles against generated Worker `Env` without losing application domain types such as **Workspace** and queue message types.
- [x] Backend typecheck passes after generated types are updated.

**Out of scope:**
- Implementing the reusable transactional email module.
- Rendering or sending the **Account email verification** template.
- Configuring Better Auth email verification behavior.
- Moving personal **Workspace** bootstrap after verification.
- Updating frontend auth messaging.
