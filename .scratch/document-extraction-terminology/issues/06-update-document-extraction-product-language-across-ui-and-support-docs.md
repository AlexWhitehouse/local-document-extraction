## Agent Brief

**Category:** enhancement

**Summary:** Update authored UI, support documentation, and API examples to use Document Extraction, Document, and Source file terminology.

**Current behavior:**
Some authored product-facing UI and support material still uses legacy image-only language even though the product supports PDFs as well as PNG, JPEG, and WebP source formats. The canonical submission field is now `document`, and existing implementation slices have already moved core submission, source metadata, source-size limits, Cloudflare resource naming, and workflow naming toward the resolved glossary.

Generated files, platform API vocabulary, standards-level MIME strings, and required HTML or Cloudflare vocabulary may still contain `image` where that term is externally owned.

**Desired behavior:**
Authored UI copy, README/support documentation, and Postman/API examples should consistently use **Document Extraction**, **Document**, and **Source file** terminology where the application owns the wording. API examples should submit the source as the `document` multipart field and should not advertise legacy `image` or generic `file` submission fields. Any remaining `image` references should be limited to standards-level MIME strings, generated files, platform vocabulary, or other externally required terminology.

Built frontend output should not be hand-edited; it should change only through the normal frontend build process if build artifacts are regenerated.

**Key interfaces:**
- User-facing document queueing and detail UI copy — should describe submitted items as **Documents** and original binaries as **Source files** where applicable.
- API examples and support docs — should use the **Document Extraction** product/API label and submit sources through the `document` multipart field.
- Postman collections or examples — should avoid legacy product labels and should not show `image` or `file` as accepted submission field names.
- Terminology verification searches — should distinguish application-owned legacy wording from allowed generated, platform, and standards references.

**Acceptance criteria:**
- [ ] User-facing UI copy uses **Document** and **Source file** terminology instead of legacy image-only wording.
- [ ] Product/API labels in authored docs and Postman collections use **Document Extraction**.
- [ ] Postman examples submit the source as `document`.
- [ ] Authored docs no longer advertise legacy `image` or generic `file` submission fields.
- [ ] Remaining `image` references are standards-level MIME strings, generated files, platform vocabulary, or otherwise externally required terminology.
- [ ] Generated frontend build output is not hand-edited.
- [ ] Frontend production build succeeds.

**Out of scope:**
- Changing supported Document source formats.
- Changing the already-established `document` multipart submission-field contract.
- Reintroducing legacy `image` or generic `file` compatibility aliases.
- Renaming persistence schema, source metadata response fields, workspace source-size limits, Cloudflare resources, R2 buckets, queues, or workflow resources already covered by completed prerequisite issues.
- Rewriting historical D1 migration files.
- Hand-editing generated Cloudflare platform types or built frontend assets.
- Removing standards-level MIME strings such as `image/png`.
- Changing Cloudflare platform API option keys or generated types that require image vocabulary.
