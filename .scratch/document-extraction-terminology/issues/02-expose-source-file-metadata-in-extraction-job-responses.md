## Agent Brief

**Category:** enhancement

**Summary:** Rename **Extraction job** source metadata to **Source file** terminology in persistence, API responses, search, and frontend consumption.

**Current behavior:**
**Extraction job** source metadata still uses legacy image terminology in persisted schema names, backend response fields, search, tests, and frontend document state. Job list and detail responses expose `image_name`, and callers use that field to identify submitted Documents.

**Desired behavior:**
**Extraction job** source metadata should use **Source file** terminology throughout application-owned persistence and API contracts. New **Extraction jobs** should persist source metadata using source-oriented schema names. Job list and detail responses should expose `source_name` and should not emit `image_name`. Search should continue to match **Extraction jobs** by **Source file** name. Frontend document history and selected document views should consume the new response names.

This should be done with a new forward D1 migration. Historical migration files must remain unchanged.

**Key interfaces:**
- **Extraction job lifecycle** creation interface — should accept and persist **Source file** key, MIME type, and name using source terminology.
- Job list/detail API responses — should expose `source_name` and remove legacy `image_name` aliases.
- Job search query contract — should continue matching job id, **Source file** name, template id, and status where applicable.
- Frontend document history state — should consume and render `source_name` from backend responses.
- D1 migrations — should add a forward migration for renaming existing job source metadata columns without rewriting historical migrations.

**Acceptance criteria:**
- [x] A forward migration renames persisted **Extraction job** source metadata to **Source file** terminology.
- [x] New **Extraction jobs** persist source key, MIME type, and name using the new schema names.
- [x] Job list responses expose `source_name` and do not emit `image_name`.
- [x] Job detail responses expose `source_name` and do not emit `image_name`.
- [x] Job search still matches by **Source file** name.
- [x] Frontend document history and selected document views consume the new source metadata names.
- [x] Tests verify `source_name` is returned and legacy `image_name` is not returned.
- [x] Backend typecheck and frontend build succeed.

**Out of scope:**
- Changing the `document` multipart submission-field contract from issue 1.
- Renaming workspace **Source file** byte limits.
- Renaming Cloudflare resources, R2 buckets, queues, workflow resources, or D1 database names.
- Renaming the document processing workflow.
- Emitting transitional legacy response aliases.
- Rewriting historical migration files.
- Hand-editing generated files or built frontend assets.
- Removing standards-level MIME strings such as `image/png`.
