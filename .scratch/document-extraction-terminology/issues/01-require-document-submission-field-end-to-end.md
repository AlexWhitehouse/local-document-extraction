## Agent Brief

**Category:** enhancement

**Summary:** Require `document` as the only accepted multipart field for **Document** submission.

**Current behavior:**
The extraction submission path still accepts legacy and generic source field names. Clients may submit a source as `image`, `file`, or `document`, and validation errors advertise those alternatives. The frontend document queueing flow still sends the source using legacy `image` naming. Authored API examples and support docs may also advertise legacy source field names.

**Desired behavior:**
`POST /v1/extract` should accept a supported **Document** source only when it is sent as the `document` multipart field. Requests that provide only `image` or only `file` as the source field should be rejected. Validation errors should use **Document** or **Source file** terminology and should not advertise `image` or `file` as accepted alternatives. The frontend should submit queued Documents as `document`, and authored API examples should do the same.

Supported source formats are unchanged: PNG, JPEG, WebP, and PDF remain valid **Document** formats. Standards-level MIME values may still contain `image` where required by the MIME standard.

**Key interfaces:**
- Extraction request validation — should parse multipart form data, require `template_id`, require `document`, reject missing or invalid source parts, preserve supported MIME and byte-limit validation, and parse extraction options.
- Document queueing UI flow — should append the submitted **Document** to form data as `document`.
- Authored API examples and support docs — should show `document` as the source field and stop advertising `image` or `file` alternatives.
- Validation error shape — should preserve existing HTTP error conventions while updating error codes/messages where they currently refer to legacy image terminology.

**Acceptance criteria:**
- [x] `POST /v1/extract` accepts a supported source format when it is sent as the `document` multipart field.
- [x] `POST /v1/extract` rejects requests that send only `image` as the source field.
- [x] `POST /v1/extract` rejects requests that send only `file` as the source field.
- [x] Validation errors mention `document` as the required source field and do not advertise `image` or `file` alternatives.
- [x] Frontend document queueing sends the submitted **Document** as `document`.
- [x] Authored API examples and support docs no longer show `image` or `file` as accepted submission fields.
- [x] Tests cover accepted `document` submission and rejected legacy field submissions.
- [x] Backend typecheck succeeds.

**Out of scope:**
- Renaming persisted **Extraction job** source metadata response fields or D1 columns.
- Renaming workspace **Source file** byte limits.
- Renaming Cloudflare resources, R2 buckets, queues, workflow resources, or D1 database names.
- Renaming `documentProcessingWorkflow` or workflow symbols.
- Hand-editing generated files or built frontend assets.
- Removing standards-level MIME strings such as `image/png`.
- Changing supported source formats.
