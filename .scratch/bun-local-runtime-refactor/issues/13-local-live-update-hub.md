## What to build

Replace Durable Object WebSocket fanout with a **Local live update hub** keyed by Workspace ID. The existing Workspace live update route remains session-only, validates accepted **Workspace context**, and pushes **Extraction job lifecycle** updates from local product operations to connected browser clients. Clients still recover missed updates through HTTP revalidation.

## Acceptance criteria

- [x] The Bun server supports the existing Workspace live update WebSocket route shape.
- [x] Only session-authenticated users with accepted **Workspace membership** can open live update sockets.
- [x] **Workspace API keys** cannot open live update sockets.
- [x] The **Local live update hub** broadcasts lifecycle messages only to sockets subscribed to the affected Workspace ID.
- [x] Lifecycle messages are sent after authoritative **Workspace product data** changes are persisted.
- [x] Live update payloads exclude extracted answers, evidence, Source file binary contents, account emails, API keys, and Document contents.
- [x] Frontend opens one live update connection for the accepted Workspace context, replaces it on Workspace switch, closes it on sign-out, updates job list state from messages, and revalidates over HTTP after reconnect.
- [x] Tests cover authorization, broadcast isolation, payload privacy, frontend state updates, and reconnect revalidation.
