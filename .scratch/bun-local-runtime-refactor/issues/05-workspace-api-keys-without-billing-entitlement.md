# Workspace API Keys Without Billing Entitlement

Category: enhancement
Status: completed

## Parent

## What to build

Preserve **Workspace API key** generation and bearer-token access for local product routes, while removing the old paid entitlement dependency. Owners and admins can generate or rotate keys, key material remains one-time visible and hash-at-rest, and API keys authenticate external local clients for product routes only.

## Acceptance criteria

- [ ] Workspace owners/admins can generate a new **Workspace API key** through the Bun API and receive one-time visible key material.
- [ ] Rotating a **Workspace API key** invalidates the previous key.
- [ ] Key hashes are stored in **Workspace control data**; existing key material is never returned after the one-time display window.
- [ ] **Workspace API keys** authenticate Template product routes without paid entitlement checks.
- [ ] **Workspace API keys** are rejected from session-only routes such as profile, membership, invitations, Workspace deletion, API key generation, auth, admin, and live update WebSockets.
- [ ] The frontend **Workspace API key display** continues to show generation/rotation/copy behavior without billing messaging.
- [ ] Tests cover generation, rotation, product-route access, session-only route rejection, and no paid-entitlement dependency.
