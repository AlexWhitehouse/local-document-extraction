## What to build

Move **Workspace control data** onto local SQLite while preserving the accepted **Workspace context** behavior. Users should be able to create, list, select, rename, and delete Workspaces through the Bun runtime with **Workspace membership** authorization intact. The frontend should keep resolving and storing accepted Workspace selection as before, but backed by local control persistence rather than Cloudflare D1.

## Acceptance criteria

- [ ] Local control migrations create the no-billing schema for users, sessions, Workspaces, Workspace memberships, Workspace invitations, and Workspace API key lookup.
- [ ] Local migrations are idempotent and can run against an empty local state directory.
- [ ] Signed-in users can create and list Workspaces through the Bun API.
- [ ] Accepted **Workspace context** resolution works for authenticated users and repairs the zero-accepted-Workspace invariant where the product requires it.
- [ ] Workspace rename and deletion flows continue to enforce **Workspace policy**.
- [ ] The frontend continues to show **Loading workspace context**, **Workspace resolution error**, and accepted Workspace selection behavior appropriately.
- [ ] Tests cover Workspace policy behavior against local control persistence without asserting raw SQL internals.
