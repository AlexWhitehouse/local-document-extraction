# Runner Startup Recovery And Retry Semantics

Category: enhancement
Status: completed

## Parent

.scratch/bun-local-runtime-refactor/PRD.md

## What to build

Harden the **Local extraction runner** so accepted work survives Bun server restarts and transient failures. On startup the runner scans local **Workspace product data** for resumable `queued` jobs and stale `processing` jobs, retries transient failures within bounds, and keeps retry metadata out of durable user-visible **Extraction job lifecycle** states.

## Acceptance criteria

- [x] Runner startup scans all local Workspace product stores for resumable `queued` jobs.
- [x] Runner startup identifies stale `processing` jobs and makes them eligible for retry or terminal failure according to bounded retry rules.
- [x] Server restart simulation does not permanently strand an accepted **Extraction job** that has not reached `completed` or `failed`.
- [x] Retry attempts and runner instance details are stored or tracked as processor metadata, not additional lifecycle states.
- [x] Duplicate or stale attempts cannot overwrite terminal `completed` or `failed` state.
- [x] Transient **Model gateway** failures are retried within configured bounds.
- [x] Tests cover queued recovery, stale processing recovery, bounded retries, duplicate attempts, and terminal-state protection.
