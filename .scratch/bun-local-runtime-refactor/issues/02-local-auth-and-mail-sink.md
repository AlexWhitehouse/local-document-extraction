# Local Auth And Mail Sink

Category: enhancement
Status: completed

## Parent

.scratch/bun-local-runtime-refactor/PRD.md

## What to build

Make authentication usable in the local Bun runtime. Email/password remains the reliable local sign-in path, Better Auth continues to own account sessions, and **Account email verification** plus **Account password reset** links are captured through a **Local mail sink** instead of Cloudflare Email. Google OAuth remains optional and only appears or works when local OAuth configuration is present.

## Acceptance criteria

- [ ] Email/password sign-up, verification, sign-in, and password reset work through the Bun server.
- [ ] The **Local mail sink** captures verification and password reset messages in local daily JSONL records and prints actionable links to the server log.
- [ ] Verification is not bypassed; unverified email/password users remain blocked until they use a captured verification link.
- [ ] Password reset request responses do not reveal whether the submitted email belongs to an email/password account.
- [ ] Google OAuth is optional and does not block email/password usage when local OAuth credentials are absent.
- [ ] Transactional email templates remain code-owned and reusable.
- [ ] Tests cover the mail sink behavior and the local auth flows that consume captured verification/reset links.
