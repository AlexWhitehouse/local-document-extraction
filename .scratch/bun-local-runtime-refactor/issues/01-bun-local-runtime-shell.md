## What to build

Create the first local-only runtime slice: a Bun server that can start the app locally, initialize the local state directory, serve API requests through the existing Fetch-style routing shape, serve built frontend assets with SPA fallback, and expose local setup commands. This slice should prove that normal local use no longer requires Wrangler for the HTTP server path, while keeping Vite available for frontend development convenience.

## Acceptance criteria

- [ ] A Bun server starts from the active local command surface and handles Fetch-style `Request`/`Response` routing without adding a web framework.
- [ ] `GET /v1/health` works through the Bun server.
- [ ] Built frontend assets are served by the Bun server for normal local use, including SPA fallback for non-API `GET` and `HEAD` requests.
- [ ] Local runtime state directories are created under the repo-root local state directory when needed.
- [ ] Frontend development can still run through Vite with API proxying to the Bun backend.
- [ ] Root and app package scripts advertise Bun local commands rather than Wrangler local runtime commands for this slice.
- [ ] Focused tests or smoke checks cover health routing and SPA fallback through the Bun runtime.
