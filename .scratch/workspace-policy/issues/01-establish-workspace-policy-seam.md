## Agent Brief

**Category:** enhancement
**Summary:** Establish a Workspace policy module seam for workspace-scoped access authorization.

**Current behavior:**
Workspace-scoped request authorization is currently owned by callers in the auth path. Session-based requests load workspace membership rows directly to decide access, and workspace API key requests hash and look up API keys directly against workspaces. This scatters workspace access rules outside the intended Workspace policy module.

**Desired behavior:**
Workspace-scoped authorization should route through a Workspace policy interface that accepts the caller intent and returns the authorized workspace context. Session-based access should still require a valid Better Auth session and an explicit workspace id. Workspace API key access should still resolve a workspace from a bearer API key without requiring user membership context. Existing HTTP error semantics must be preserved for missing workspace context, missing or invalid API keys, and forbidden workspace access.

**Key interfaces:**
- `Workspace policy` module/interface - should own durable D1 reads needed for workspace access decisions and expose intent-shaped authorization for session workspace access and workspace API key access.
- Auth context shape - should continue to provide the authorized workspace, auth mode, and optional user id expected by workspace-scoped route handlers.
- Workspace policy errors - should be typed internally enough for callers to map them to current HTTP status codes, error codes, and messages at the edge.

**Acceptance criteria:**
- [ ] Workspace-scoped session requests still require a valid session and workspace id.
- [ ] Workspace API key requests still resolve the correct workspace without requiring user membership context.
- [ ] Callers no longer load workspace membership rows directly for the workspace access decision.
- [ ] Workspace policy errors map to the current HTTP error semantics for missing workspace context, invalid API key, and forbidden workspace access.
- [ ] Backend typecheck succeeds.

**Out of scope:**
- Moving workspace listing, creation, settings, API key rotation, invitations, user management, deletion eligibility, or new-user bootstrap behind Workspace policy.
- Changing public API response contracts or auth route contracts.
- Changing the database schema.
- Introducing a generic persistence layer or generic D1 store abstraction.
