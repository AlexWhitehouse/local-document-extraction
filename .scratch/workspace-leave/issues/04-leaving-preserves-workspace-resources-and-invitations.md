# Leaving preserves Workspace resources and invitations

Category: enhancement
Status: done

## What to build

Verify and preserve the non-obvious invariants of `Leave Workspace`: leaving is membership-only removal. Workspace documents, templates, pending Workspace invitations, and the Workspace API key should remain intact for remaining members and integrations. Pending Workspace invitations sent by the leaver should remain pending unless separately cancelled or expired.

## Acceptance criteria

- [x] Leaving a Workspace does not delete Workspace documents visible to remaining members.
- [x] Leaving a Workspace does not delete Workspace templates visible to remaining members.
- [x] Pending Workspace invitations sent by the leaver remain pending after the leaver's membership is removed.
- [x] Pending Workspace invitations sent by other members remain pending after the leave.
- [x] The Workspace API key for the left Workspace is not rotated or invalidated by the leave action.
- [x] Remaining members can continue using the Workspace after another member leaves.
- [x] Backend behavior tests cover invitations and Workspace API-key preservation across leave.
- [x] End-to-end or integration-level verification covers at least one remaining-member access scenario after leave.
- [x] Relevant repo checks pass using existing scripts.
