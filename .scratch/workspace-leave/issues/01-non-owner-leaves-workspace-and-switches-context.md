# Non-owner leaves a Workspace and switches context

Category: enhancement
Status: complete

## What to build

Build the main `Leave Workspace` path for signed-in non-owner Workspace members who have another accepted Workspace available. A Workspace admin or member should see `Leave Workspace` instead of `Delete Workspace`, confirm the action, remove only their own Workspace membership, refresh their accepted Workspaces, remove locally stored API-key material for the left Workspace, and land in the most recently created remaining accepted Workspace context.

- [x] Confirming `Leave Workspace` removes only the acting user's Workspace membership and does not delete the Workspace or other memberships.
- [x] After a successful leave with remaining accepted Workspaces, the left Workspace disappears from the user's accepted Workspace list.

- [x] A failed leave keeps the current Workspace context unchanged and shows a clear failure message.
- [x] Workspace policy behavior tests cover admin/member leave with another accepted Workspace.

## Agent Brief

**Category:** enhancement
**Summary:** Add the main self-service `Leave Workspace` path for signed-in non-owner Workspace members who have another accepted Workspace available.

**Current behavior:**
Workspace admins and members currently see the same destructive `Delete Workspace` action as owners, even though only owners can delete a Workspace. There is no self-service leave path that removes only the current user's Workspace membership and then moves the user into another accepted Workspace context.

**Desired behavior:**
Signed-in Workspace admins and members with at least one other accepted Workspace should see `Leave Workspace` instead of `Delete Workspace`. When they confirm the action, the system should remove only their own Workspace membership from the selected Workspace, refresh accepted Workspaces, remove locally stored API-key material for the left Workspace, preserve locally stored API-key material for remaining Workspaces, and select the most recently created remaining accepted Workspace. Cancelling the confirmation or receiving a leave failure should leave Workspace context unchanged.

**Key interfaces:**
- `Workspace policy` leave operation — should accept the acting signed-in user and target Workspace, enforce non-owner membership rules for this slice, remove only the acting user's membership, and return enough information for callers to distinguish success from failure.
- Workspace leave API contract — should expose a session-only self-service leave action for the selected Workspace without overloading owner/admin member-management actions or destructive Workspace deletion.
- Workspace context transition logic — should decide the request shape, refresh requirements, successful post-leave accepted Workspace selection, and failure behavior without owning browser effects.
- App/browser adapter behavior — should own confirmation, network request execution, accepted Workspace refresh, log messaging, and local API-key storage updates.
