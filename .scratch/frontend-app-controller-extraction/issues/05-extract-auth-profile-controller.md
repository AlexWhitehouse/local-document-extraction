## Agent Brief

**Category:** enhancement
**Summary:** Extract the frontend auth/profile controller from App while preserving auth form behavior, Better Auth actions, profile editing, profile menu dismissal, sign-out cleanup, and session refetch behavior.

**Current behavior:**
The root App component remains the public frontend root and still directly owns auth and profile state, actions, effects, and view-model assembly. This includes auth mode, auth form values, password touched/submission state, password complexity feedback, confirm-password mismatch feedback, Better Auth sign-in/sign-up/provider/sign-out handlers, signed-in profile state, profile draft state, profile save loading state, profile menu open state, outside-click and Escape dismissal, profile loading, profile saving, and sign-out cleanup coordination. Auth and profile presentation components already exist, and Document, Template, and Workspace behavior has been extracted behind controllers.

**Desired behavior:**
App should delegate cohesive auth and profile behavior to an auth/profile controller while remaining the public root composer. The controller should return grouped view models and actions for the auth screen and profile menu. User-visible auth, profile, session, sign-out cleanup, backend API, storage, and UI behavior must remain unchanged.

**Key interfaces:**
- The root App component remains the public bootstrap and composition boundary.
- The auth/profile controller public API should expose grouped view models and actions for the auth screen and profile menu rather than requiring App to own or assemble individual auth/profile fields.
- Better Auth session handling should continue to use the existing runtime auth client and preserve session refetch behavior after sign-in, sign-up, profile save, and sign-out.
- Auth form values must remain separate from Stored workspace preference and must not be initialized from persisted Workspace selection data.
- Password complexity feedback, confirm-password mismatch feedback, safe auth error Action toasts, Google sign-in start behavior, and auth mode switching should remain user-visible compatible with the current behavior.
- Profile loading and saving should continue using the existing authenticated request behavior that does not require accepted Workspace API access.
- Sign-out must continue coordinating with the Template, Document, and Workspace controllers so user-specific stored workspace data, Completed document cache, visible Workspace API key material, Workspace lists, invitation selection, Workspace users, and workspace-scoped frontend state are cleared.
- App-level auth/profile behavior tests remain the primary regression safety net; add controller-specific tests only if independently meaningful pure behavior emerges or a bug is found.

**Acceptance criteria:**
- [ ] App no longer directly owns auth mode, auth form values, password touched/submission state, profile state, profile draft state, profile save loading state, or profile menu open state.
- [ ] The controller returns grouped view models and actions for the auth screen and profile menu.
- [ ] Sign-in, sign-up, Google sign-in, password complexity feedback, confirm-password mismatch feedback, auth mode switching, and safe auth error Action toasts are preserved.
- [ ] Auth form values are still not initialized from Stored workspace preference or Workspace selection data.
- [ ] Profile loading, profile editing, dirty-state behavior, outside-click dismissal, Escape dismissal, and save behavior are preserved.
- [ ] Sign-out still clears user-specific stored workspace data, Completed document cache, visible Workspace API key material, Workspace lists, invitation selection, Workspace users, and workspace-scoped frontend state through the relevant controllers.
- [ ] Better Auth session refetch behavior is preserved after sign-in, sign-up, profile save, and sign-out.
- [ ] No user-visible UI changes, backend API changes, storage-key changes, React Context, URL routing, global state library, or CSS architecture changes are introduced.
- [ ] `npm run test --prefix frontend` passes.
- [ ] `npm run build --prefix frontend` passes.

**Out of scope:**
- Changing user-visible auth behavior, profile behavior, visual design, Active page semantics, Workspace selection view semantics, Document behavior, Template behavior, or Workspace behavior.
- Changing Better Auth configuration, backend routes, request/response contracts, Workspace access rules, storage keys, persisted data shapes, Stored workspace preference behavior, or Completed document cache persistence semantics.
- Introducing URL routing, React Context, a global state library, CSS architecture changes, or a broad terminology-only rename.
- Adding controller-specific tests solely to assert internal hook structure.
