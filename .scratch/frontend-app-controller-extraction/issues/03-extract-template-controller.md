# Extract Template Controller

Category: enhancement
Status: completed

## Parent

## What to build

Move **Template** list/edit state, Template create/update/delete behavior, selected upload Template coordination, and Template JSON modal logic out of App into a Template controller that returns grouped view models for the Templates context list, Template page, Template JSON modal, and Template-related toolbar state.

## Acceptance criteria

- [x] App no longer directly owns Template list state, Template editor state, Template search state, draft Template navigation state, save/delete loading state, loaded Template snapshots, or Template JSON modal state.
- [x] Template loading, search, draft creation, selection, create, update, delete, and dirty-state behavior are preserved.
- [x] Template JSON export/import, copy-to-clipboard feedback, JSON validation feedback, and save behavior are preserved.
- [x] **Template field** validation, hydration, serialization, and object schema behavior remain unchanged.
- [x] The selected upload Template behavior remains compatible with Document upload.
- [x] The controller public API uses glossary-aligned names, while internal legacy names may remain if they do not leak into App.
- [x] No user-visible UI changes are introduced.
- [x] `npm run test --prefix frontend` passes.
- [x] `npm run build --prefix frontend` passes.

## Agent Brief

**Category:** enhancement
**Summary:** Extract the frontend Template controller from App while preserving Template list/edit behavior, Template JSON modal behavior, Template field semantics, and Selected upload Template coordination.

**Current behavior:**
The root App component remains the public frontend root and still directly owns Template-oriented state, actions, derived values, and view-model assembly. This includes Template list state, Template search state, Template editor state, loaded Template snapshots, draft Template navigation state, create/update/delete loading state, Selected upload Template state, and Template JSON modal state. Template presentation components and Template field helpers already exist, but App still orchestrates the feature behavior directly.

**Desired behavior:**
App should delegate cohesive Template behavior to a Template controller while remaining the public root composer. The controller should return grouped view models and actions for the Templates context list, Template page, Template JSON modal, and Template-related toolbar state. User-visible behavior, Template field validation and serialization semantics, backend API contracts, storage keys, and UI structure must remain unchanged.

**Key interfaces:**
- The root App component remains the public bootstrap and composition boundary.
- The Template controller public API should expose grouped view models by UI surface rather than requiring App to assemble many individual Template props.
- The controller should use the existing workspace-aware request layer for workspace-scoped Template API requests.
- Template field validation, hydration, serialization, object schema handling, and JSON payload validation should continue to use the existing Template field behavior.
- Selected upload Template state must remain available to Document upload behavior so new Documents continue using the intended Template.
- Template JSON modal behavior should preserve export/import draft generation, copy-to-clipboard feedback, JSON parse errors, validation errors, save behavior, and close behavior while saving.
- App-level integration behavior and existing pure Template field tests remain the primary regression safety net; add controller-specific tests only if independently meaningful pure behavior emerges or a bug is found.

**Acceptance criteria:**
- [x] App no longer directly owns Template list state, Template editor state, Template search state, draft Template navigation state, save/delete loading state, loaded Template snapshots, or Template JSON modal state.
- [x] The controller returns grouped view models and actions for the Templates context list, Template page, Template JSON modal, and Template-related toolbar state.
- [x] Template loading, search, draft creation, selection, create, update, delete, and dirty-state behavior are preserved.
- [x] Template JSON export/import, copy-to-clipboard feedback, JSON validation feedback, and save behavior are preserved.
- [x] Template field validation, hydration, serialization, and object schema behavior remain unchanged.
- [x] Selected upload Template behavior remains compatible with Document upload.
- [x] The controller public API uses glossary-aligned names, while internal legacy names may remain if they do not leak into App.
- [x] No user-visible UI changes, backend API changes, storage-key changes, React Context, URL routing, global state library, or CSS architecture changes are introduced.
- [x] `npm run test --prefix frontend` passes.
- [x] `npm run build --prefix frontend` passes.

**Out of scope:**
- Extracting Workspace, auth, or profile controllers in this slice.
- Changing user-visible behavior, visual design, Active page semantics, Workspace selection view semantics, Document behavior, Workspace behavior, auth behavior, or profile behavior.
- Changing backend routes, request/response contracts, Template JSON payload shape, Template field validation semantics, storage keys, or persisted data shapes.
- Introducing URL routing, React Context, a global state library, CSS architecture changes, or a broad terminology-only rename.
- Adding controller-specific tests solely to assert internal hook structure.
