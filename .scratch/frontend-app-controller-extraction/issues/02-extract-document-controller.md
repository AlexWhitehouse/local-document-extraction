# Extract Document Controller

Category: enhancement
Status: completed

## Parent

.scratch/frontend-app-controller-extraction/PRD.md

## What to build

Move **Document**, **Extraction job**, upload modal, polling, deletion, selected Document, and **Completed document cache** behavior out of App into a Document controller that returns grouped view models for the Documents context list, Documents page, toolbar state, and upload modal.

## Acceptance criteria

- [x] App no longer directly owns Document list state, queued job state, selected Document state, upload modal state, upload drag state, loading-more state, manual lookup state, or live polling effects.
- [x] Document upload still uses the selected Template and submits Source files through the `document` multipart field.
- [x] **Document upload toast** behavior is unchanged for queued and failed Source files.
- [x] Queued-only **Extraction jobs**, backend-listed jobs, search filtering, pagination, selected Document fallback, and sort order are preserved.
- [x] Live polling still refreshes queued and processing **Extraction jobs** without changing interval behavior.
- [x] **Completed document cache** storage, hydration, pruning, 404 removal, Workspace-scoped clearing, and sign-out clearing behavior are preserved.
- [x] Deleting a Document still removes it from visible state, queued state, latest response state, and cache consistently.
- [x] The controller public API uses glossary-aligned names, while internal legacy names may remain if they do not leak into App.
- [x] No user-visible UI changes are introduced.
- [x] `npm run test --prefix frontend` passes.
- [x] `npm run build --prefix frontend` passes.

## Agent Brief

**Category:** enhancement
**Summary:** Extract the frontend Document controller from App while preserving Document, Extraction job, upload modal, polling, deletion, selected Document, and Completed document cache behavior.

**Current behavior:**
The root App component remains the public frontend root and still directly owns Document-oriented state, actions, effects, and view-model assembly. This includes Document list state, queued Extraction job state, selected Document state, upload modal state, upload drag state, loading-more state, manual lookup state, live polling effects, deletion behavior, and Completed document cache integration. Presentation components for Document context lists, upload modal, and Extraction result display already exist, but App still orchestrates the feature behavior directly.

**Desired behavior:**
App should delegate cohesive Document behavior to a Document controller while remaining the public root composer. The controller should return grouped view models and actions for the Documents context list, Documents page, toolbar state, and upload modal, using glossary-aligned public names for Document, Source file, Extraction job, Selected upload Template, Action toast, and Completed document cache concepts. User-visible behavior, backend API contracts, storage keys, and UI structure must remain unchanged.

**Key interfaces:**
- The root App component remains the public bootstrap and composition boundary.
- The Document controller public API should expose grouped view models by UI surface rather than requiring App to assemble many individual Document props.
- The controller should use the existing workspace-aware request layer for workspace-scoped Document and Extraction job API requests.
- Document submission must continue to use the `document` multipart field and the selected Template for each Source file.
- Document upload toast behavior should continue to report queued and failed Source files through the existing Action toast system.
- Completed document cache behavior should continue to use the existing cache abstraction and remain scoped by accepted Workspace and Extraction job ID.
- App-level integration behavior remains the primary regression safety net; add controller-specific tests only if independently meaningful pure behavior emerges or a bug is found.

**Acceptance criteria:**
- [ ] App no longer directly owns Document list state, queued Extraction job state, selected Document state, upload modal state, upload drag state, loading-more state, manual lookup state, or live polling effects.
- [ ] The controller returns grouped view models and actions for the Documents context list, Documents page, toolbar state, and upload modal.
- [ ] Document upload still uses the selected Template and submits Source files through the `document` multipart field.
- [ ] Document upload toast behavior is unchanged for queued and failed Source files.
- [ ] Queued-only Extraction jobs, backend-listed jobs, search filtering, pagination, selected Document fallback, and sort order are preserved.
- [ ] Live polling still refreshes queued and processing Extraction jobs without changing interval behavior.
- [ ] Completed document cache storage, hydration, pruning, 404 removal, Workspace-scoped clearing, and sign-out clearing behavior are preserved.
- [ ] Deleting a Document still removes it from visible state, queued state, latest response state, and cache consistently.
- [ ] The controller public API uses glossary-aligned names, while internal legacy names may remain if they do not leak into App.
- [ ] No user-visible UI changes, backend API changes, storage-key changes, React Context, URL routing, global state library, or CSS architecture changes are introduced.
- [ ] `npm run test --prefix frontend` passes.
- [ ] `npm run build --prefix frontend` passes.

**Out of scope:**
- Extracting Template, Workspace, auth, or profile controllers in this slice.
- Changing user-visible behavior, visual design, Active page semantics, Workspace selection view semantics, Template behavior, Workspace behavior, auth behavior, or profile behavior.
- Changing backend routes, request/response contracts, upload multipart field names, storage keys, persisted data shapes, or Completed document cache persistence semantics.
- Introducing URL routing, React Context, a global state library, CSS architecture changes, or a broad terminology-only rename.
- Adding controller-specific tests solely to assert internal hook structure.
