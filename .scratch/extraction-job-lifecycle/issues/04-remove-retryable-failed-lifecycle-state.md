## Agent Brief

**Category:** enhancement
**Summary:** Remove `retryable_failed` as a durable **Extraction job lifecycle** state.

**Current behavior:**
The **Extraction job lifecycle** Module owns queued creation, processing claims, completion, and terminal failure. `retryable_failed` still exists as a durable status in retry failure handling, queue processing, manual retry route behavior, and the **Extraction job** status type.

**Desired behavior:**
Transient retryability should be owned by Cloudflare Workflow retry steps rather than durable **Extraction job lifecycle** status values. No lifecycle path should write `retryable_failed`, and callers should not need to reason about it as a durable **Extraction job** state.

Manual retry behavior should be removed or redesigned so status-based retryability does not re-enter the durable lifecycle. The durable lifecycle should continue moving toward only `queued`, `processing`, `completed`, and `failed`.

**Key interfaces:**
- **Extraction job lifecycle** Module **Interface** — should not expose or write `retryable_failed`.
- **Extraction job** durable status type — should remove `retryable_failed` when no longer used by supported lifecycle paths.
- Cloudflare Workflow retry behavior — should use workflow step retries for transient processing failure rather than durable retry status.
- Manual retry route behavior — should be removed or changed so it does not depend on `retryable_failed`.

**Acceptance criteria:**
- [x] No **Extraction job lifecycle** path writes `retryable_failed` as a durable status.
- [x] Transient AI gateway or processing retry behavior is handled by Cloudflare Workflow retry steps rather than durable status values.
- [x] Manual retry behavior is removed or redesigned so status-based retryability does not re-enter the durable lifecycle.
- [x] The **Extraction job** durable status type no longer includes `retryable_failed` once supported paths stop using it.
- [x] Tests verify transient retry behavior is not represented by `retryable_failed`.
- [x] Backend typecheck succeeds.

**Out of scope:**
- Removing `workflow_started` from the durable lifecycle.
- Redesigning Cloudflare Workflow itself.
- Redesigning AI gateway prompt construction or result normalization.
- Adding new user-facing manual retry semantics.
