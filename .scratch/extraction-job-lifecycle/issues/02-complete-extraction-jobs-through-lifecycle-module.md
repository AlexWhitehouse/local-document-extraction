## Agent Brief

**Category:** enhancement
**Summary:** Route successful **Extraction job** completion through the **Extraction job lifecycle** Module.

**Current behavior:**
The **Extraction job lifecycle** Module currently owns queued creation and processing claims. Successful AI gateway processing is still completed inside the Cloudflare Workflow implementation by directly persisting **Extraction results** and directly marking the **Extraction job** `completed`.

**Desired behavior:**
Successful AI gateway responses should complete through the **Extraction job lifecycle** Module. The Module should own the durable operation that persists **Extraction results** and marks the **Extraction job** `completed`. Cloudflare Workflow should remain the orchestration adapter and should call the lifecycle Module by intent after AI gateway result normalization.

Completion should not be represented before **Extraction results** are durable. The **Extraction job** must remain interpreted against the **Template version** selected at submission time.

**Key interfaces:**
- **Extraction job lifecycle** Module **Interface** — add an intent-shaped completion operation that accepts the **Extraction job** identity, processing attempt, and normalized **Extraction results**.
- **Extraction result** persistence shape — preserve current result fields including field identity, status, answer JSON, normalized value, confidence, and evidence where present.
- Cloudflare Workflow processing flow — should call the completion operation rather than directly owning completion writes.
- **Template version** relationship — completion must continue to persist results for the **Template fields** belonging to the submitted **Template version**.

**Acceptance criteria:**
- [ ] A successful AI gateway response persists one **Extraction result** per extracted **Template field**.
- [ ] The **Extraction job** is marked `completed` only as part of successful **Extraction result** persistence.
- [ ] The **Extraction job** remains interpreted against the **Template version** selected at submission time.
- [ ] Cloudflare Workflow calls the lifecycle Module for completion rather than directly owning durable completion writes.
- [ ] Lifecycle tests cover completion through the Module **Interface** without requiring the full Cloudflare Workflow runtime.
- [ ] Tests avoid asserting private helper names, SQL string shape, Cloudflare Workflow step names, or internal call ordering.
- [ ] Backend typecheck succeeds.

**Out of scope:**
- Terminal failure handling for **Extraction jobs**.
- Removing `retryable_failed` from the durable lifecycle.
- Removing `workflow_started` from the durable lifecycle.
- Redesigning AI gateway prompt construction or result normalization.
- Redesigning **Source file** cleanup.
