## Agent Brief

**Category:** enhancement
**Summary:** Establish the **Extraction job lifecycle** Module for the queued-to-processing path.

**Current behavior:**
Submitting a **Document** currently creates a queued **Extraction job** directly in the extraction route. Queue processing then writes Cloudflare Workflow-oriented lifecycle state before starting the workflow, and the workflow later claims the **Extraction job** for processing. The durable lifecycle rules are spread across callers rather than concentrated behind one **Interface**.

**Desired behavior:**
The first lifecycle slice should introduce a deep **Extraction job lifecycle** Module and route the narrow path from submitted **Document** to queued **Extraction job** to processing claim through it. Existing caller-visible response behavior should be preserved. The Module should own the durable lifecycle decision that submitted **Documents** create `queued` **Extraction jobs** and eligible workflow processing claims move them to `processing`.

Cloudflare Workflow should remain the orchestration adapter. This issue should not remove `retryable_failed` or `workflow_started` globally; later issues cover those lifecycle simplifications.

**Key interfaces:**
- **Extraction job lifecycle** Module **Interface** — should provide intent-shaped operations for creating a queued **Extraction job** and claiming an eligible **Extraction job** for processing.
- **Extraction job** durable status type — should support the queued and processing path used by this slice while staying compatible with later removal of obsolete durable statuses.
- **Document** submission path — should call the lifecycle Module rather than owning lifecycle persistence decisions directly.
- Cloudflare Workflow processing start — should call the lifecycle Module to claim processing rather than owning durable status mutation directly.

**Acceptance criteria:**
- [x] Submitting a **Document** still creates a queued **Extraction job** using the selected **Template version**.
- [x] The submitted **Document** response remains compatible with current caller-visible behavior for this path.
- [x] Cloudflare Workflow processing start uses the **Extraction job lifecycle** Module to move an eligible **Extraction job** to `processing`.
- [x] Lifecycle tests cover queued creation and processing start through the Module **Interface**.
- [x] Tests avoid asserting private helper names, SQL string shape, Cloudflare Workflow step names, or internal call ordering.
- [x] Backend typecheck succeeds.

**Out of scope:**
- Completing **Extraction jobs** with **Extraction results**.
- Failing **Extraction jobs** with terminal error information.
- Removing `retryable_failed` from the durable lifecycle.
- Removing `workflow_started` from the durable lifecycle globally.
- Redesigning AI gateway prompting or result normalization.
- Redesigning **Source file** cleanup.
