**Current behavior:**
The durable **Extraction job** status type has been narrowed to `queued`, `processing`, `completed`, and `failed`. **Extraction job** list and detail reads pass through stored status values, and some frontend expectations may still reflect obsolete lifecycle states from earlier workflow implementation details.

**Desired behavior:**
**Extraction job** list and detail behaviour should expose only the durable **Extraction job lifecycle** states: `queued`, `processing`, `completed`, and `failed`. Frontend behaviour should continue to show clear queued, processing, completed, and failed states without depending on obsolete workflow implementation states.

The work should preserve existing response shape except for ensuring obsolete durable states are not exposed.

**Key interfaces:**
- **Extraction job** list response — should expose only supported durable lifecycle states.
- **Extraction job** detail response — should expose only supported durable lifecycle states and still include **Extraction results** for completed jobs.
- Frontend **Extraction job** status handling — should treat only `queued`, `processing`, `completed`, and `failed` as supported durable lifecycle states.
- **Extraction job** durable status type — should remain aligned with the supported states.
