## Agent Brief

**Category:** enhancement
**Summary:** Route terminal **Extraction job** failure through the **Extraction job lifecycle** Module.

**Current behavior:**
The **Extraction job lifecycle** Module currently owns queued creation and processing claims. Permanent processing failures are still handled inside the Cloudflare Workflow implementation by directly marking the **Extraction job** `failed` with error information. Missing **Source file** and missing **Extraction job** cases are interpreted in workflow code rather than through the lifecycle Module.

**Desired behavior:**
Terminal processing failures should fail through the **Extraction job lifecycle** Module. The Module should own the durable operation that marks an **Extraction job** `failed` with error code, message, updated time, and attempt information. Cloudflare Workflow should remain the orchestration adapter and should call the lifecycle Module by intent for permanent failures.

Missing **Source file** should produce a clear failed lifecycle outcome. Missing **Extraction job** records should stop processing safely without creating inconsistent data.

**Key interfaces:**
- **Extraction job lifecycle** Module **Interface** — add an intent-shaped failure operation for terminal processing failures.
- Failure input shape — should carry **Extraction job** identity, processing attempt, error code, error message, and failure time.
- Cloudflare Workflow processing flow — should call the failure operation for permanent failures rather than directly owning durable failure writes.
- Existing lifecycle status type — should continue to support `failed` and remain compatible with later removal of obsolete durable statuses.

**Acceptance criteria:**
- [x] Permanent processing errors mark the **Extraction job** `failed` with an error code and message.
- [x] Missing **Source file** failures become a clear failed lifecycle outcome.
- [x] Missing **Extraction job** records stop processing safely without creating inconsistent data.
- [x] Cloudflare Workflow calls the lifecycle Module for terminal failure rather than directly owning durable failure writes.
- [x] Lifecycle tests cover terminal failure behaviour through the Module **Interface**.
- [x] Tests avoid asserting private helper names, SQL string shape, Cloudflare Workflow step names, or internal call ordering.
- [x] Backend typecheck succeeds.

**Out of scope:**
- Successful completion with **Extraction results**.
- Removing `retryable_failed` from the durable lifecycle.
- Removing `workflow_started` from the durable lifecycle.
- Redesigning Cloudflare Workflow retry steps.
- Redesigning AI gateway prompt construction or result normalization.
