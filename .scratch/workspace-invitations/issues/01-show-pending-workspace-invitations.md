## Agent Brief

**Category:** enhancement
**Summary:** Show actionable pending workspace invitations to workspace owners and admins, separate from current workspace members.

**Current behavior:**
Workspace owners and admins can invite users, but workspace access management focuses on current members. Pending workspace invitations are not exposed as a first-class management list with inviter identity, expiry, and offered role. Invite creation also needs to reject invitations for email addresses that already belong to current workspace members, so the same person does not appear as both a member and an invitee.

**Desired behavior:**
Owners and admins should be able to list actionable pending invitations for a workspace from access management. Members should not be able to access this list. The list should be separate from current workspace users and should include enough summary data for the frontend to show invited email, offered role, pending status, inviter identity, invited time, expiry, and workspace context. Accepted, cancelled, and expired invitations should not appear in this actionable management list.

**Key interfaces:**
- `Workspace policy` invitation lifecycle behavior should own the authorization and D1 reads for workspace-scoped pending invitation summaries.
- The workspace API should expose a thin workspace-scoped pending invitations endpoint for owners/admins, delegating authorization and filtering to `Workspace policy`.
- Invitation summary responses should include invitation id, workspace id, workspace name, invited email, offered role, status, inviter id, inviter display identity, invited time, expiry, and any stable fields needed by the frontend to render/sort consistently.
- Invite creation should reject a normalized invited email when it already belongs to a current workspace member.
- The workspace access-management UI should render current members and pending invitations as separate sections.

**Acceptance criteria:**
- [ ] Owners and admins can list actionable pending invitations sent from a workspace.
- [ ] Members cannot list pending invitations sent from a workspace.
- [ ] Pending invitations appear in a separate access-management section from current users.
- [ ] Invitation summaries include workspace, invited email, offered role, pending status, inviter identity, invited time, and expiry.
- [ ] Accepted, cancelled, and expired invitations are not shown in the pending invitation management list.
- [ ] Invite creation rejects an email that already belongs to a current workspace member.
- [ ] Backend policy tests cover owner/admin/member authorization and invitation summary behavior.
- [ ] Backend typecheck succeeds using the repo's backend typecheck command.
- [ ] Frontend production build succeeds using the repo's frontend build command.

**Out of scope:**
- Cancelling pending invitations; that is covered by the follow-up cancellation slice.
- Merging invited workspace entries into the invitee's workspace list.
- Accepting or declining invitations from the invitee-facing detail view.
- Sending invitation emails or integrating with an email provider.
- Adding full invitation audit history for accepted, cancelled, declined, or expired invitations.
