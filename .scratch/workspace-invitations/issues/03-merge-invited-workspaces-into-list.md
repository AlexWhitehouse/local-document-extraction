## Agent Brief

**Category:** enhancement
**Summary:** Merge actionable invitee-facing workspace invitations into the visible workspace list without granting access.

**Current behavior:**
The app can list accepted workspaces and has backend foundations for invitee-facing pending invitations, but pending invitations are not yet composed into the visible workspace list as invitation entries. Invitees must not be given active workspace context merely because an invitation exists.

**Desired behavior:**
After sign-in or session load, the frontend should fetch invitee-facing actionable pending invitations alongside accepted workspaces. The visible workspace list should show accepted workspaces first, followed by invited workspace entries ordered by latest update first. Invited entries should be visually distinct with orange styling, should be marked as invited, should show the offered role, and should count toward the visible workspace count. Search should include invitation-specific fields. Selecting an invited entry should not grant workspace API access; detail-view behavior is covered by a follow-up slice.

**Key interfaces:**
- Invitee-facing invitation listing should return only actionable pending invitations for the signed-in user's current normalized email.
- Invitation summary data should include workspace name, workspace id, invited email, offered role, inviter identity, status, invited time, expiry, and update time where needed for sorting.
- Workspace state/list composition should represent accepted workspace entries and invited workspace entries distinctly while preserving a separate active accepted workspace context.
- Workspace search and count behavior should operate over the composed visible list, not only accepted workspaces.

**Acceptance criteria:**
- [ ] Invitee-facing invitations are fetched alongside accepted workspaces after sign-in/session load.
- [ ] The visible workspaces list includes accepted workspaces first, then actionable pending invitation entries.
- [ ] Invited entries are visually distinct with orange styling and an invited status.
- [ ] Invited entries show the offered role.
- [ ] The workspace count includes invited entries.
- [ ] Workspace search matches invited entries by workspace name, workspace id, inviter name, inviter email, invited email, and offered role.
- [ ] Expired, cancelled, accepted, and workspace-deleted invitations do not appear as invited workspace entries.
- [ ] Backend policy tests cover actionable invitee-facing listing and expiry filtering behavior.
- [ ] Backend typecheck succeeds using the repo's backend typecheck command.
- [ ] Frontend production build succeeds using the repo's frontend build command.

**Out of scope:**
- Rendering the locked invitation detail view after selection.
- Accepting or declining invitations.
- Adding direct accept/decline controls to the workspace list item.
- Sending invitation emails or building a notification center.
- Granting templates, documents, jobs, API key, workspace rename, delete, upload, or user management access before invitation acceptance.
