## Agent Brief

**Category:** enhancement
**Summary:** Let invitees decline their own pending workspace invitations from the locked invitation detail view.

**Current behavior:**
Invitees can see pending workspace invitations in the workspaces flow and the invitation detail view now has a Decline Invitation action placeholder, but invitee decline is not wired through that view. Workspace owners/admins can cancel pending invitations, but invitee decline needs a distinct authorization path even though it uses the same terminal `cancelled` status.

**Desired behavior:**
An invitee should be able to decline their own pending workspace invitation from the locked invitation detail view without a confirmation prompt. Decline should authorize by the signed-in user's current normalized account email, set the invitation status to `cancelled`, return a minimal success response with invitation id and `cancelled` status, refresh workspace and invitation state, and remove the declined invitation from visible invited workspace entries and detail state.

**Key interfaces:**
- Workspace invitation decline policy should own invitee authorization by current account email and the transition from pending invitation to `cancelled`.
- Invitee decline API should be separate from owner/admin workspace invitation cancellation because those actions have different authorization rules.
- Decline response shape should remain minimal and action-oriented: success, invitation id, and `cancelled` status.
- Workspace selection state should clear selected invitation state after successful decline and fall back to an accepted workspace when available.
- Invitee-facing invitation state should refresh after decline so declined invitations disappear from visible workspace entries.
- Invitation detail UI should enable the Decline Invitation action only when a pending invitation is selected and should not show a confirmation prompt for invitee decline.
