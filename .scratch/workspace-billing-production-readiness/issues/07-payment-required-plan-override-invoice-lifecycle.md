# Payment-Required Plan Override Invoice Lifecycle

Category: enhancement
Status: completed

## What to build

Complete the invoice lifecycle for Application admin payment-required Plan overrides. Paid invoices should activate the override and grant Included Credits exactly once, while customer-action, finalization-failure, payment-failed, voided, and uncollectible states should remain payment-gated and visible to owners/admins.

## Acceptance criteria

- [x] Payment-required Plan override invoices persist customer-action, finalization-failed, payment-failed, voided, and marked-uncollectible states without activating the Plan override.
- [x] Hosted invoice/payment URLs are retained when Stripe provides them.
- [x] Paid override invoices activate the Plan override, grant Included Credits exactly once, and record an Application admin audit entry.
- [x] Duplicate, delayed, and out-of-order events do not duplicate audit entries or Included Credits.
- [x] Owner Billing page and Application admin billing view show actionable state for pending, failed, terminal, and paid override invoices.
- [x] Billing reconciliation repairs clearly paid missed override invoices and records drift for ambiguous states.
- [x] Backend, frontend Billing page, and Application admin tests cover the full payment-required override invoice lifecycle.

## Agent Brief

**Category:** enhancement
**Summary:** Complete payment-required Plan override invoice lifecycle handling for customer-action, finalization-failure, terminal unpaid, paid, and reconciled invoice states.

**Current behavior:**
Workspace billing already has payment-required Application admin Plan overrides, owner-visible Stripe invoices, Application admin billing audit entries, owner Billing page visibility, and explicit Stripe billing webhook outcome/routing support.

Paid payment-required Plan override invoice events can activate the Plan override and grant Included Credits, and payment-failed invoice events can persist failed invoice state without activating entitlement. Duplicate paid invoice delivery is already intended to be idempotent. Billing reconciliation also has an existing path for clearly paid missed payment-required Plan override invoices and drift records for invoice-status mismatches.

The remaining gap is that all supported negative and terminal invoice lifecycle events are not yet first-class for payment-required Plan override invoices. Customer-action-required, invoice-finalization-failed, voided, and marked-uncollectible payment-required override invoice events should not fall through subscription-only invoice handling or become failed Stripe billing events just because they are not self-service subscription invoices.

**Desired behavior:**
Payment-required Plan override invoices should have a complete non-granting lifecycle. When Stripe sends customer-action-required, finalization-failed, payment-failed, voided, or marked-uncollectible events for a payment-required Plan override invoice, Workspace billing should persist the relevant invoice status and hosted invoice/payment URL when Stripe provides one. These states must keep the Plan override payment-gated: no Active entitlement change, no Included Credit grant, and no paid/API access unlocked.

Paid payment-required override invoices should continue to activate the Plan override, grant Included Credits exactly once for the relevant Billing period, preserve hosted invoice/payment URLs, and record an Application admin billing audit entry. Duplicate deliveries, delayed events, out-of-order events, and manual replays should not duplicate Included Credits or duplicate audit entries that imply a second state transition.

Owner and Application admin surfaces should show actionable pending, failed, terminal, and paid override invoice state without exposing raw Stripe identifiers, raw payloads, payment method details, or admin-only notes to owners. Billing reconciliation should repair clearly paid missed payment-required override invoices through the same idempotent activation/grant path, and should record manual-review drift for ambiguous or terminal unpaid states it cannot safely repair.

**Key interfaces:**
- Stripe billing webhook event router — should route supported invoice lifecycle events to payment-required Plan override invoice handling before falling back to subscription-only invoice handling where appropriate.
- Payment-required Plan override control data — should persist invoice status, hosted invoice/payment URL, paid timestamp, and activation state without granting entitlement for non-paid states.
- Active entitlement and Included Credit grant behavior — paid override activation should remain idempotent for the same Workspace, invoice, target Plan, and Billing period.
- Owner Billing page summary/activity contract — should expose payment-required override invoice status and hosted payment action in owner-safe language.
- Application admin billing state and audit log — should expose payment-required override invoice status transitions and audit history needed for commercial support.
- Billing reconciliation — should safely repair clearly paid missed override invoices and record drift for ambiguous or terminal states.

**Acceptance criteria:**
- [x] Payment-required Plan override invoices persist `payment_action_required`, `finalization_failed`, `payment_failed`, `void`/`voided`, and `uncollectible`/`marked_uncollectible` states without activating the Plan override.
- [x] Hosted invoice/payment URLs are retained or updated when Stripe provides them for any payment-required override invoice lifecycle event.
- [x] Paid payment-required override invoices activate the Plan override, grant Included Credits exactly once, preserve prior Purchased Credits, and record one meaningful Application admin billing audit transition.
- [x] Duplicate, delayed, out-of-order, and replayed payment-required override invoice events do not duplicate Included Credits or duplicate audit entries for the same state transition.
- [x] Owner Billing page shows actionable pending, customer-action, finalization-failed, payment-failed, terminal, and paid payment-required override invoice states with owner-safe payment actions.
- [x] Application admin billing view shows payment-required override invoice lifecycle state and audit history needed for review without leaking raw Stripe payloads or secrets.
- [x] Billing reconciliation repairs clearly paid missed payment-required override invoices through the idempotent paid activation path and records drift for ambiguous or terminal unpaid invoice states.
- [x] Backend webhook/reconciliation tests, frontend owner Billing page tests, and Application admin billing tests cover the full payment-required override invoice lifecycle.
- [x] `npm run test --prefix backend`, `npm run typecheck --prefix backend`, and `npm run build --prefix frontend` pass, or any unavailable verification is documented with the exact blocker.

**Out of scope:**
