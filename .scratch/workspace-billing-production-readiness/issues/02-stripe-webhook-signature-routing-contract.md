## Agent Brief

**Category:** enhancement
**Summary:** Harden the Stripe billing webhook signature and event-routing contract before live Workspace billing launch.

**Current behavior:**
Workspace billing already receives Stripe billing events through the `/v1/billing/stripe/webhook` endpoint. The webhook entry path reads the raw request body before parsing, requires a `Stripe-Signature` header, verifies `v1` HMAC signatures against the configured webhook secret, and records unsupported signed Stripe billing events as ignored diagnostics without mutating Workspace billing state.

The remaining production-readiness gaps are around replay protection, operator clarity, and making the supported-event routing contract explicit. Signature verification does not yet enforce a production timestamp tolerance, signing-secret rotation behavior is not fully documented for Stripe's temporary two-secret rotation window, and the supported event list is not documented as the exact live webhook allowlist. Existing backend coverage includes missing-signature and ignored-event behavior, but should be extended for malformed signatures, invalid signatures, unsupported signature schemes, old timestamps, supported routing, and ignored routing.

**Desired behavior:**
Every Stripe billing webhook request should be verified from the exact raw request body before any business logic runs. Requests without `Stripe-Signature`, with malformed signature headers, with no valid `v1` signature candidate, with invalid HMACs, or with timestamps outside the production tolerance should be rejected before Workspace billing state can be mutated.

Signature verification should ignore non-`v1` signature schemes, compare candidate signatures in constant time, and protect against replay attacks using a documented timestamp tolerance. Signing-secret rotation behavior should be implemented or documented clearly enough that operators know how to handle Stripe's temporary two-secret rotation window for the live endpoint without accepting unsigned or stale events.

The webhook router should make supported Stripe billing event types explicit. Supported events should route to named Workspace billing handlers. Unsupported, future, or irrelevant signed Stripe billing events should return a successful webhook response, should not mutate Workspace billing state, and should be recorded as ignored diagnostics when the event is persisted.

Operational documentation should name the live Stripe webhook allowlist for the current Workspace billing production-readiness scope, including `checkout.session.completed`, delayed Checkout success/failure events, invoice paid/failed/action/finalization/terminal events, and customer subscription lifecycle events.

**Key interfaces:**
- `/v1/billing/stripe/webhook` — must remain a public Stripe webhook endpoint that does not require a user session or Workspace API key.
- `Stripe-Signature` verification — should use the raw request payload, the configured webhook signing secret or documented rotation path, `v1` signatures, constant-time comparison, and a production timestamp tolerance.
- Stripe billing event router — should expose a single explicit source of truth for supported billing event types and send unsupported signed events through the ignored outcome path.
- Stripe billing event diagnostics — ignored and failed outcomes must continue to avoid raw payloads, API keys, webhook secrets, payment method details, and unnecessary customer PII.
- Operator documentation — should state the live endpoint destination, the exact subscribed event allowlist, timestamp/replay behavior, and signing-secret rotation steps.

**Acceptance criteria:**
- [ ] Webhook signature verification reads and verifies the raw request body before parsing or business logic.
- [ ] Requests missing `Stripe-Signature`, using malformed headers, using only non-`v1` schemes, carrying invalid signatures, or carrying stale timestamps are rejected without mutating Workspace billing state.
- [ ] Valid `v1` signatures within the timestamp tolerance are accepted, including headers with multiple signature candidates.
- [ ] Signature comparison remains constant-time for valid-length hex candidates.
- [ ] Signing-secret rotation behavior is either implemented or documented for Stripe's temporary two-secret rotation window.
- [ ] The webhook router explicitly names all currently supported Workspace billing Stripe event types and maps unsupported signed events to the ignored outcome without Workspace billing mutations.
- [ ] Documentation lists the live webhook event allowlist for Checkout completion, delayed Checkout success/failure, invoice paid/failed/action/finalization/terminal events, and customer subscription lifecycle events.
- [ ] Backend tests cover valid signatures, invalid signatures, malformed headers, stale timestamps, unsupported signature schemes, supported event routing, and ignored event routing.

**Out of scope:**
- Adding new Workspace billing product semantics, plan prices, Credit pack sizes, Enterprise terms, refunds, disputes, coupons, or Stripe Customer Portal behavior.
- Implementing the later production-readiness event lifecycle issues such as Plan downgrade invoice activation, delayed Credit pack outcomes, subscription lifecycle drift handling, negative invoice states, or Billing reconciliation production coverage.
- Changing the Billing ledger authority model or Workspace product data storage.
- Entering, printing, committing, or documenting production Stripe API keys, webhook secrets, or raw Stripe webhook payloads.
