# Worker Production Deploy and Secret Preflight

Category: enhancement
Status: completed

## What to build

Make production Worker deploys repeatable and safe for live billing. The deploy scripts, Worker configuration, generated types, docs, required secret declarations, live Price ID handling, remote binding checks, and preflight process should agree on one production path and fail before traffic when required production prerequisites are missing.

## Acceptance criteria

- [x] Package scripts and documentation agree on the production secret-loading path, including whether `wrangler deploy --secrets-file ../.vars`, Cloudflare Worker secrets, or both are used.
- [x] The production secrets file path, format, required keys, and gitignore expectation are documented without secret values.
- [x] `wrangler.jsonc` declares required Worker secrets where practical using the current `secrets.required` configuration.
- [x] Worker types are regenerated or verified after required secret/binding changes.
- [x] Worker configuration review covers launch-date compatibility-date review, `nodejs_compat`, observability, `workers_dev = false`, custom domain route, assets, D1, Durable Objects, R2, Queue, Workflow, Analytics Engine, and Email bindings.
- [x] Live Stripe Price ID separation is documented so test-mode IDs cannot be mistaken for production catalog IDs.
- [x] A deploy preflight or configuration test validates remote migrations, required secrets, live Price IDs, webhook setup, Cron Trigger setup, custom domain health, and frontend build without printing secrets.

## Agent Brief

**Category:** enhancement
**Summary:** Make production Worker deploys fail before traffic when live billing secrets, bindings, Stripe Price IDs, and operator prerequisites are not production-ready.

**Current behavior:**
Workspace billing production-readiness work has completed the Stripe restricted API key contract, so this issue is no longer blocked by the Stripe API safety audit. The Worker deploy path already has a production-oriented deploy command, production bindings, a custom-domain route, Cron Trigger configuration, observability settings, and existing Worker configuration tests.

The remaining risk is that those pieces are not yet enforced as one repeatable production deploy contract. Required Worker secrets are not declared as the source of truth for deploy validation and generated Worker types. Production secret-loading documentation is split between Wrangler secret uploads and the operator-managed secrets file path. Recurring Pro and Max Stripe Price IDs are environment configuration, but the live production path does not yet prove that configured Price IDs are live-mode Stripe Prices rather than earlier test-mode catalog IDs. There is not yet a single preflight or configuration test that checks remote production prerequisites without printing secret values.

**Desired behavior:**
Production deploys should use one documented secret-loading path that package scripts, Worker configuration, generated Worker types, and operator documentation all agree on. Required production secret names should be declared through the current Worker secrets configuration mechanism where practical, and Worker types should be regenerated or verified after any secret or binding changes.

The production deploy documentation should describe the secrets file path, dotenv or JSON format, required key names, gitignore expectation, and relationship to Cloudflare-stored Worker secrets without showing secret values. Local development should remain clearly separate from production secrets and Stripe test mode.

Live Stripe Price ID separation should be enforced by behavior, not naming conventions. The runtime should continue using the environment's configured Pro and Max monthly Price IDs, while the production preflight verifies with Stripe that those IDs are active live-mode monthly GBP Prices and match the code-owned Pro/Max catalog expectations. The preflight must not print Price IDs, API keys, webhook secrets, or other secret values.

The production preflight or configuration checks should fail before traffic when required prerequisites are missing or ambiguous: remote D1 migrations, required secrets, live Stripe Price IDs, live webhook setup, Cron Trigger setup, custom-domain health, relevant Cloudflare bindings, and frontend production build.

**Key interfaces:**
- Worker secrets configuration - should declare required secret names such as authentication, AI Gateway, Stripe API key, Stripe webhook signing secret, and optional Google OAuth secret when Google sign-in is enabled.
- Generated Worker environment types - should stay aligned with declared required secrets and configured bindings.
- Production deploy command - should build frontend assets and deploy the Worker using the documented production secret-loading path.
- Production secrets file contract - should document required keys and accepted format without committing or printing values.
- Stripe Price ID preflight - should retrieve configured recurring Pro and Max Prices using a server-side Stripe key and assert `livemode`, `active`, currency, recurring interval, amount, and plan mapping.
- Worker configuration checks - should cover compatibility date review, `nodejs_compat`, observability, `workers_dev = false`, custom domain route, assets, D1, Durable Objects, R2, Queue, Workflow, Analytics Engine, Email, and Cron Trigger configuration.
- Operator runbook or preflight output - should report pass/fail statuses and missing prerequisite names without exposing secrets or raw Stripe credentials.

**Acceptance criteria:**
- [x] The package scripts and production deploy documentation agree on a single production secret-loading path.
- [x] The production secrets file path, accepted format, required key names, and gitignore expectation are documented without secret values.
- [x] The Worker configuration declares required secrets using the current `secrets.required` shape where practical.
- [x] Generated Worker environment types are regenerated or verified after required secret or binding changes.
- [x] Worker configuration checks cover compatibility date review, `nodejs_compat`, observability, `workers_dev = false`, custom-domain route, assets, D1, Durable Objects, R2, Queue, Workflow, Analytics Engine, Email, and Cron Trigger configuration.
- [x] Production Stripe Pro and Max monthly Price IDs are not treated as trustworthy merely because they are configured.
- [x] A preflight validates the configured Pro and Max monthly Price IDs against Stripe and fails unless each Price is live-mode, active, GBP, monthly recurring, mapped to the expected plan, and consistent with the code-owned catalog.
- [x] The preflight or equivalent configuration test validates remote D1 migrations, required secrets, live webhook setup, Cron Trigger setup, custom-domain health, and frontend build before production traffic.
- [x] Preflight, tests, docs, and logs do not print API keys, webhook signing secrets, secret file contents, raw Stripe credentials, or full sensitive environment dumps.
- [x] Backend typecheck and the relevant Worker configuration tests pass.
- [x] Frontend production build passes when the production deploy path depends on built frontend assets.

**Out of scope:**
- Creating, copying, or committing live Stripe API keys, webhook signing secrets, or secret file contents.
- Creating or editing live Stripe Products, Prices, webhook endpoints, or Dashboard settings except through documented operator verification steps.
- Changing Workspace billing product semantics, plan prices, Credit pack sizes, Enterprise pricing rules, Billing ledger authority, or owner/Application admin roles.
- Reworking Stripe webhook lifecycle behavior, Billing reconciliation semantics, or owner-facing billing UI states covered by other production-readiness issues.
- Launching live billing or running real-money smoke tests.
