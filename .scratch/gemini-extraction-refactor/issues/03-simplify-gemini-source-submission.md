## Agent Brief

**Category:** enhancement
**Summary:** Simplify Gemini source submission so supported PDFs and images are sent directly to the Extraction model as inline source content.

**Current behavior:**
The extraction adapter has a Gemini-compatible inline source path, but it also retains an inactive PDF-to-markdown conversion path for non-Gemini request construction. This makes PDF extraction harder to reason about because a **Source file** can appear to have two model input paths even though the intended runtime is Gemini-only.

**Desired behavior:**
Supported PDF and image **Source files** should be submitted to the Gemini Extraction model as inline source content through the public extraction adapter boundary. PDF extraction should no longer depend on markdown conversion in the runtime extraction path. Existing **Document** submission API behaviour, supported source formats, retry semantics, and completed **Extraction job** response shape should remain unchanged.

**Key interfaces:**
- `runExtraction()` — should accept requested **Template fields**, source bytes, and source MIME type, then invoke the configured Gemini Extraction model with inline source content.
- Workers AI Gemini input shape — should include text instructions plus inline source data for both PDF and image MIME types.
- PDF markdown conversion support — should not remain part of runtime extraction once Gemini inline source submission is the only supported path.

**Acceptance criteria:**
- [ ] PDF **Source files** are submitted to Gemini as inline source content.
- [ ] Image **Source files** are submitted to Gemini as inline source content.
- [ ] The inactive markdown conversion path is removed from extraction runtime.
- [ ] Tests cover PDF inline source submission through the public extraction adapter boundary.
- [ ] Tests cover image inline source submission through the public extraction adapter boundary.
- [ ] Existing **Document** submission API behaviour remains unchanged.
- [ ] Backend test suite and typecheck pass.

**Out of scope:**
- Supporting OpenAI, Anthropic, or any other non-Gemini provider.
- Reintroducing PDF markdown conversion as a fallback path.
- Changing **Document** submission API fields or accepted formats.
- Changing **Extraction job lifecycle** states, retry semantics, or completed response shape.
