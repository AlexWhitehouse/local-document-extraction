## Agent Brief

**Category:** enhancement
**Summary:** Make Gemini model and Workers AI Gateway configuration explicit and consistent.

**Current behavior:**
The backend extraction path is configured around Gemini, but model selection is not consistently driven by application configuration. Gateway execution and persisted processing metadata can refer to separate configuration concepts, which makes it harder to audit which gateway path actually handled an **Extraction job**.

**Desired behavior:**
The extraction adapter should use the configured Extraction model when present and fall back to the agreed Gemini model when absent. Gateway execution should use the configured gateway identifier with a safe fallback. Persisted processing metadata should use the same actual gateway identifier rather than a separate route configuration value.

**Key interfaces:**
- `AI_MODEL` configuration — optional model selection for the Gemini extraction adapter, with a fallback to the agreed Gemini model.
- `AI_GATEWAY_ID` configuration — gateway identifier used for Workers AI Gateway execution and persisted processing metadata.
- `runExtraction()` — should call the configured/fallback model through the configured/fallback gateway and return raw model field results.
- **Extraction job lifecycle** completion metadata — should persist gateway metadata that reflects the actual gateway identifier used by extraction.

**Acceptance criteria:**
- [ ] The extraction adapter uses configured model selection when present.
- [ ] The extraction adapter falls back to the agreed Gemini model when model configuration is absent.
- [ ] Gateway execution uses the configured gateway identifier with a safe fallback.
- [ ] Persisted processing metadata uses the actual gateway identifier rather than separate route configuration.
- [ ] Tests cover configured model selection and fallback model selection.
- [ ] Workflow tests are updated only where necessary for gateway metadata expectations.
- [ ] Backend test suite and typecheck pass.

**Out of scope:**
- Supporting non-Gemini model providers.
- Removing inactive non-Gemini request or response paths; those are covered by later issues.
- Pruning unsupported provider environment fields; that is covered by a later issue.
- Changing **Extraction job lifecycle** states or retry semantics.
