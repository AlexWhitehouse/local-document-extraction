## Agent Brief

**Category:** enhancement
**Summary:** Route Workspace member actions through Workspace context transitions.

**Current behavior:**
Workspace context display, pending Workspace invitation locked context, invitee accept/decline transitions, and Workspace user-management visibility are owned by the Workspace context Module. Workspace member actions are still coordinated inline by the App. The App owns missing Workspace and target-user guards, role-change/removal/owner-transfer request construction, refresh ordering, and failure-safe behavior.

**Desired behavior:**
Workspace member actions should be modeled as pure Workspace context transitions. The Workspace context Module should decide whether a member action is allowed to proceed from the current Workspace context, what request effect is required for role change, removal, or owner transfer, and which refresh effects are required after success. The App should remain the adapter for network requests, React state application, and logging. Backend Workspace policy remains the durable authority for actual authorization and mutation outcomes.

**Key interfaces:**
- Workspace context Module transition interface — accepts current Workspace context state and a Workspace member action event/result; returns guard outcomes, request effects, refresh effects, and failure-safe outcomes.
- Member action guard outcome — represents missing accepted Workspace context or missing target Workspace user without requiring a network request.
- Member action success outcome — represents successful role change, removal, or owner transfer and requests refresh of Workspace users, Workspaces, and relevant Workspace context.

**Acceptance criteria:**
- [x] Member actions without an accepted Workspace context return a guard outcome without performing a request.
- [x] Member actions without a target Workspace user return a guard outcome without performing a request.
- [x] Role change actions return the request and refresh effects needed for the selected Workspace context.
- [x] Removal actions return the request and refresh effects needed for the selected Workspace context.
- [x] Owner-transfer actions return the request and refresh effects needed for the selected Workspace context.
- [x] Successful member actions refresh Workspace users, Workspaces, and relevant Workspace context.
- [x] Failed member actions leave Workspace context unchanged unless refreshed data says otherwise.
- [x] Pure frontend tests cover member action guards, role change, removal, owner transfer, refresh effects, and failure-safe behavior.
- [x] Frontend tests and frontend production build pass.

**Out of scope:**
- Changing backend Workspace policy behavior.
- Changing backend route contracts.
- Moving network requests into the Workspace context Module.
- Moving localStorage persistence into the Workspace context Module.
- Moving logging or browser confirmation prompts into the Workspace context Module.
- Implementing Workspace invitation invite or cancel transitions in this slice.
- Changing backend owner/admin/member authorization rules.
