## Agent Brief

**Category:** enhancement
**Summary:** Move Workspace invitation decline transitions into the Workspace context Module.

**Current behavior:**
Pending Workspace invitation locked context is owned by the Workspace context Module, but declining a Workspace invitation is still coordinated inline by the App. The App owns decline guards, request gating, pending Workspace invitation clearing, refresh ordering, and failure-safe behavior.

**Desired behavior:**
Workspace invitation decline should be modeled as a pure Workspace context transition. The Workspace context Module should decide whether decline is allowed, that invitee decline does not require confirmation, what request effect is required, how successful decline clears pending Workspace invitation context, and which refresh effects are required. The App should remain the adapter for network requests, React state application, and logging.

**Key interfaces:**
- Workspace context Module transition interface — accepts current Workspace context state and a decline Workspace invitation event or result; returns guard outcomes, request effects, next Workspace context state, and refresh effects.
- Decline guard outcome — represents missing selected pending Workspace invitation or non-pending Workspace invitation without requiring a network request.
- Decline success outcome — clears pending Workspace invitation context, does not create Workspace access, and requests accepted Workspace plus pending Workspace invitation refresh.

**Acceptance criteria:**
- [x] Declining without a selected pending Workspace invitation returns a guard outcome without performing a request.
- [x] Declining a non-pending Workspace invitation returns a guard outcome without performing a request.
- [x] Declining an invitee's own Workspace invitation does not require confirmation.
- [x] Successful decline clears pending Workspace invitation context.
- [x] Successful decline keeps the user out of that Workspace.
- [x] Decline returns the refresh effects required for accepted Workspaces and pending Workspace invitations.
- [x] Failed decline leaves Workspace context unchanged unless refreshed data says otherwise.
- [x] Pure frontend tests cover decline guards, no-confirmation behavior, pending context clearing, refresh effects, and failure-safe behavior.
- [x] Frontend tests and frontend production build pass.

**Out of scope:**
- Changing backend Workspace policy behavior.
- Changing backend route contracts.
- Moving network requests into the Workspace context Module.
- Moving localStorage persistence into the Workspace context Module.
- Moving logging or confirmation prompts into the Workspace context Module.
- Implementing Workspace invitation accept transitions in this slice.
- Implementing owner/admin Workspace invitation cancellation in this slice.
- Implementing Workspace user-management permission or action transitions in this slice.
