## Agent Brief

**Category:** enhancement
**Summary:** Consolidate App integration around the Workspace context Module.

**Current behavior:**
The Workspace context Module owns Workspace context display, accepted Workspace selection, pending Workspace invitation locked context, invitee accept/decline transitions, owner/admin Workspace invitation management transitions, Workspace member action transitions, and Workspace user-management visibility. The App applies transition outputs, performs network requests, persists browser state, shows confirmation prompts, logs outcomes, and renders. Some App call sites may still duplicate Workspace context rules or apply transition outcomes inconsistently.

**Desired behavior:**
The App should consistently reach Workspace context behavior through the Workspace context Module. Workspace context selection, locked pending Workspace invitation state, permission visibility, and action transition rules should not be reimplemented inline. Browser persistence, network requests, confirmation prompts, logging, React state application, and rendering should remain App adapter responsibilities.

This slice should preserve existing Workspace context behavior while improving locality and making the Workspace context Module the primary behavior surface for tests.

**Key interfaces:**
- Workspace context Module display interface — source of Workspace context display, selected context view, and user-management visibility.
- Workspace context Module transition interfaces — source of accepted Workspace selection, Workspace invitation accept/decline, owner/admin Workspace invitation management, and Workspace member action outcomes.
- App adapter responsibilities — performs effects requested by transition outcomes and applies returned state without owning Workspace context rules.

**Acceptance criteria:**
- [x] App no longer reimplements Workspace context selection, locked invitation state, permission, or action transition rules inline.
- [x] Browser persistence remains outside the Workspace context Module.
- [x] Network requests remain outside the Workspace context Module.
- [x] Confirmation prompts remain outside the Workspace context Module.
- [x] Logging remains outside the Workspace context Module.
- [x] React rendering remains outside the Workspace context Module.
- [x] Existing Workspace context behavior remains stable for accepted Workspace selection, pending Workspace invitation selection, accept, decline, invite, cancel, and member actions.
- [x] Tests cover the Workspace context Module as the primary behavior surface rather than App internals.
- [x] Frontend tests and frontend production build pass.

**Out of scope:**
- Changing backend Workspace policy behavior.
- Changing backend route contracts.
- Moving network requests into the Workspace context Module.
