**Summary:** Move pending Workspace invitation locked context into the Workspace context Module.

Accepted Workspace context display and accepted Workspace selection are now routed through the Workspace context Module. **Desired behavior:**
Pending Workspace invitation context should be owned by the Workspace context Module. Selecting a pending Workspace invitation should produce a locked Workspace context that shows invitation details but does not grant Workspace API access. Stale pending Workspace invitation selection should fall back safely to accepted Workspace context when possible. If the user has no accepted Workspaces and only pending Workspace invitations, the latest pending Workspace invitation should become the selected Workspace context.

Accepted Workspace behavior from the previous slice should remain stable.

**Key interfaces:**
- Workspace context Module interface — accepts accepted Workspaces, pending Workspace invitations, selected Workspace id, selected pending Workspace invitation id, and access inputs; returns the normalized Workspace context display and selected Workspace context view.
- Pending Workspace invitation display model — exposes Workspace invitation id, Workspace id, Workspace name, invited email, offered role, pending status, inviter display, invited time, and expiry.
- Locked Workspace context view — identifies pending Workspace invitation context and reports no Workspace API access or Workspace management access.
