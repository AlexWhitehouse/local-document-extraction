## Agent Brief

**Category:** enhancement
**Summary:** Route owner/admin Workspace invitation management actions through Workspace context transitions.

**Current behavior:**
Workspace context display, pending Workspace invitation locked context, invitee accept/decline transitions, and Workspace user-management visibility are owned by the Workspace context Module. Owner/admin Workspace invitation management actions are still coordinated inline by the App. The App owns invite guards, invite validation, cancel guards, confirmation-required behavior, request construction, refresh ordering, and failure-safe behavior.

**Desired behavior:**
Owner/admin Workspace invitation management should be modeled as pure Workspace context transitions. The Workspace context Module should decide whether invite and cancel actions are allowed, whether invite input is valid, whether cancelling a pending Workspace invitation requires confirmation, what request effect is required, and which refresh effects are required after success. The App should remain the adapter for browser confirmation prompts, network requests, React state application, and logging.

**Key interfaces:**
- Workspace context Module transition interface — accepts current Workspace context state and an invite or cancel event/result; returns guard outcomes, validation outcomes, confirmation-required outcomes, request effects, refresh effects, and failure-safe outcomes.
- Invite transition outcome — represents missing accepted Workspace context, invalid email input, request effect, success refresh, or failure without local Workspace context mutation.
- Cancel transition outcome — represents missing accepted Workspace context, missing selected pending Workspace invitation, confirmation-required state, request effect, success refresh, or failure without local Workspace context mutation.

**Acceptance criteria:**
- [x] Invite actions without an accepted Workspace context return a guard outcome without performing a request.
- [x] Invite actions with invalid email input return a validation outcome without performing a request.
- [x] Successful invite returns refresh effects for pending Workspace invitations in the selected Workspace.
- [x] Cancel actions without an accepted Workspace context or selected pending Workspace invitation return guard outcomes without performing a request.
- [x] Cancelling someone else's pending Workspace invitation returns a confirmation-required outcome before the request effect.
- [x] Successful cancel returns refresh effects for pending Workspace invitations in the selected Workspace.
- [x] Failed invite and cancel actions leave Workspace context unchanged unless refreshed data says otherwise.
- [x] Pure frontend tests cover invite guards, invite validation, cancel guards, confirmation-required behavior, refresh effects, and failure-safe behavior.
- [x] Frontend tests and frontend production build pass.

**Out of scope:**
- Changing backend Workspace policy behavior.
- Changing backend route contracts.
- Moving network requests into the Workspace context Module.
- Moving localStorage persistence into the Workspace context Module.
- Moving logging or browser confirmation prompts into the Workspace context Module.
- Implementing invitee Workspace invitation accept or decline transitions in this slice.
- Implementing Workspace member role change, removal, or owner-transfer transitions in this slice.
