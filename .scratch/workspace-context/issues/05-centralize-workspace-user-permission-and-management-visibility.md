## Agent Brief

**Category:** enhancement
**Summary:** Centralize Workspace user permission and management visibility in the Workspace context Module.

**Current behavior:**
Workspace context display and pending Workspace invitation locked context are routed through the Workspace context Module, but owner/admin/member display permissions and Workspace user-management visibility are still derived inline by the App. Pending Workspace invitation context must not expose Workspace user-management actions, and accepted Workspace context should derive visibility from the selected Workspace role.

**Desired behavior:**
Workspace user-management visibility should be derived from the Workspace context Module. The Module should report whether the selected accepted Workspace context can list Workspace users, manage Workspace invitations, and expose owner/admin/member management controls. Pending Workspace invitation context should report no Workspace user-management access. Backend Workspace policy remains the durable authority for actual authorization and mutation outcomes.

**Key interfaces:**
- Workspace context Module display interface — returns Workspace user-management visibility for the selected Workspace context.
- Workspace user-management visibility model — reports whether Workspace users can be listed, whether pending Workspace invitations can be managed, and whether owner/admin/member actions should be presented.
- Selected Workspace role input — the accepted Workspace role used by the frontend to derive display and action availability, without replacing backend Workspace policy.

**Acceptance criteria:**
- [x] Workspace user listing availability is derived from Workspace context Module output.
- [x] Workspace invitation management availability is derived from Workspace context Module output.
- [x] Owner, admin, and member display permissions are derived from the selected accepted Workspace context.
- [x] Pending Workspace invitation context does not expose Workspace user-management actions.
- [x] App rendering uses Workspace context Module output for user-management visibility decisions.
- [x] Pure frontend tests cover owner, admin, member, missing Workspace, and pending Workspace invitation contexts.
- [x] Frontend tests and frontend production build pass.

**Out of scope:**
- Changing backend Workspace policy behavior.
- Changing backend route contracts.
- Moving network requests into the Workspace context Module.
- Moving localStorage persistence into the Workspace context Module.
- Moving logging or confirmation prompts into the Workspace context Module.
- Implementing Workspace invitation invite or cancel transitions in this slice.
- Implementing Workspace member role change, removal, or owner-transfer transitions in this slice.
