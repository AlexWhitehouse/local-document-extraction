## Agent Brief

**Category:** enhancement
**Summary:** Move Workspace invitation accept transitions into the Workspace context Module.

**Current behavior:**
Pending Workspace invitation locked context is owned by the Workspace context Module, but accepting a Workspace invitation is still coordinated inline by the App. The App owns accept guards, request gating, post-accept selected Workspace decisions, Workspace API key restoration, pending Workspace invitation clearing, and refresh ordering.

**Desired behavior:**
Workspace invitation acceptance should be modeled as a pure Workspace context transition. The Workspace context Module should decide whether acceptance is allowed, what request effect is required, how successful acceptance updates selected Workspace context, how saved Workspace API keys are restored, and which refresh effects are required. The App should remain the adapter for network requests, React state application, and logging.

**Key interfaces:**
- Workspace context Module transition interface — accepts current Workspace context state and an accept Workspace invitation event or result; returns guard outcomes, request effects, next Workspace context state, and refresh effects.
- Accept guard outcome — represents missing selected pending Workspace invitation or non-pending Workspace invitation without requiring a network request.
- Accept success outcome — clears pending Workspace invitation context, selects the accepted Workspace when resolvable, restores the saved Workspace API key when available, and requests accepted Workspace plus pending Workspace invitation refresh.

**Acceptance criteria:**
- [x] Accepting without a selected pending Workspace invitation returns a guard outcome without performing a request.
- [x] Accepting a non-pending Workspace invitation returns a guard outcome without performing a request.
- [x] Successful acceptance clears pending Workspace invitation context.
- [x] Successful acceptance selects the accepted Workspace when it can be resolved after refresh.
- [x] Successful acceptance restores the saved Workspace API key for the accepted Workspace when one exists.
- [x] Acceptance returns the refresh effects required for accepted Workspaces and pending Workspace invitations.
- [x] Failed acceptance leaves Workspace context unchanged unless refreshed data says otherwise.
- [x] Pure frontend tests cover accept guards, post-accept selection, API key restoration, refresh effects, and failure-safe behavior.
- [x] Frontend tests and frontend production build pass.

**Out of scope:**
- Changing backend Workspace policy behavior.
- Changing backend route contracts.
- Moving network requests into the Workspace context Module.
- Moving localStorage persistence into the Workspace context Module.
- Moving logging or confirmation prompts into the Workspace context Module.
- Implementing Workspace invitation decline transitions in this slice.
- Implementing Workspace user-management permission or action transitions in this slice.
