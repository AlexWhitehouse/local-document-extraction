# 09 — Publish agent-readable backend test evidence

**What to build:** Provide concise local commands and persistent CI evidence so an agent can identify every backend failure, slow test, and coverage gap without parsing thousands of passing-test lines or relying on a GUI.

**Blocked by:** 08 — Run Bun-native backend tests isolated and capped-parallel.

**Category:** enhancement

**Status:** completed

- [x] An agent-oriented command suppresses passing-test detail, accepts forwarded file/name filters, and preserves complete failure diagnostics and the final summary.
- [x] The deterministic merge lane uses fixed ordering, isolation, zero retries, and no early bail; a separate targeted command may bail after the first failure.
- [x] A scheduled or manual flake lane randomizes order, repeats tests, records its seed, and documents exact seed reproduction.
- [x] CI emits and uploads merged JUnit, LCOV, and per-file timing artifacts even when tests fail.
- [x] Coverage reports production backend modules absent from LCOV as well as percentages for loaded modules, then establishes a measured baseline that can only ratchet upward deliberately.
- [x] The aggregate agent check continues independent typecheck, lint, and test work after one constituent failure while returning a failing overall status if any check fails.
- [x] Profile, coverage, and test artifacts contain synthetic data and do not expose environment secrets, Document contents, or Model gateway credentials.
