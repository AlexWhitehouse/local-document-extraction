# 15 — Stream built SPA assets through Bun

**What to build:** Serve built frontend assets through Bun's lazy file response machinery so concurrent browser requests avoid full JavaScript-buffer allocations while retaining the established API precedence and SPA experience.

**Blocked by:** 02 — Pin and qualify Bun 1.4.0.

**Category:** enhancement

**Status:** completed

- [x] Auth and workspace-scoped product routes always take precedence over static assets and SPA fallback.
- [x] A real asset is returned lazily with the correct media type, ETag, Last-Modified metadata, and no full application-level file read.
- [x] Conditional requests return 304, valid byte ranges return 206, and HEAD returns the same headers without a body.
- [x] A normal client-side route falls back to the SPA index, while a missing frontend build retains the established unavailable response.
- [x] Normalized and encoded traversal attempts cannot escape the configured frontend root or expose local runtime state.
- [x] Focused concurrency measurements compare response latency and peak RSS before and after the change.
- [x] Built-runtime and Playwright smoke behaviour remain green.

> ## Agent Brief
>
> **Category:** enhancement  
> **Summary:** Replace per-request `readFile()` buffering with contained lazy `Bun.file()` responses, and prove Bun 1.4's real server boundary supplies cache validators, ranges, and HEAD semantics without changing API precedence or SPA fallback.
>
> **Current behavior:** `localRuntime.ts` stats then fully reads every direct asset or `index.html` fallback into a JavaScript buffer. It supplies only a manually selected content type: no ETag, Last-Modified, conditional response, byte-range response, or content length is exercised, and concurrent large assets multiply application-level allocations.
>
> **Desired behavior:** `/v1*` and `/api/auth*` remain unconditional API routes. GET/HEAD asset candidates are decoded and resolved inside a canonical frontend root, reject traversal and symlink escape, receive a metadata-only file check, and become a `Response` whose body is the lazy `BunFile`. Missing direct assets fall back to the same contained `index.html`; a missing build stays 503. Real `Bun.serve` tests own the HTTP features that are not observable from a plain handler invocation.
>
> **Key interfaces:** `createLocalRuntimeFetchHandler`; `Bun.file()`/`BunFile`; `realpath`/`stat`; `Response`; `Bun.serve`; `If-None-Match`; `If-Modified-Since`; `Range`; GET/HEAD; built-runtime smoke and Playwright journey.
>

Implemented and verified on Bun 1.4.0. Static delivery now uses canonical-root-contained `Bun.file()` responses with explicit validators, conditional requests, single ranges, bodyless HEAD responses, and an opaque lazy fallback when a stale `If-Range` must ignore Bun's automatic range handling. The focused 8 MiB/12-concurrent/2-round local comparison recorded 180.45 MiB versus 20.03 MiB peak server RSS and 45.74 ms versus 16.93 ms P95 for buffered versus lazy delivery; see `../evidence/15-static-asset-concurrency.md`. Root CI passed with 185 backend tests (including smoke), 250 frontend tests, coverage, and the production build; the real Chromium extraction journey also passed.
