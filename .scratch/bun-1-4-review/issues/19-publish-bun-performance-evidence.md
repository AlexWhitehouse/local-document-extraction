> ## Agent Brief
>
> **Category:** enhancement  
> **Summary:** Turn the existing bounded full-application extraction prototype into a deterministic Bun 1.3.14-versus-1.4.0 capacity comparison with machine-readable repetitions, explicit regression gates, and sanitized Bun Markdown profiles.
>
> **Current behavior:** The bounded prototype already exercises real multipart admission, authentication, Workspace SQLite stores, queue/runner execution, conditional polling, PDF fixtures, and a fake concurrency-limited Model gateway. It reports useful server and client measurements to a human-oriented console table, but generates fresh random fixture bytes per invocation, applies random retry/poll jitter, has no lifecycle latency or SQLite contention counters, cannot emit one stable result record, does not repeat/warm up runtime comparisons, and has no safe CPU/heap artifact pipeline.
>
> **Desired behavior:** A documented Bun command creates one synthetic fixture set, resets isolated state for every repetition, runs one warm-up plus identical steady bounded repetitions under exact Bun 1.3.14 and 1.4.0 executables, and publishes a Markdown comparison with per-run values, aggregate variance, environment/runtime identity, workload controls, and pass/fail thresholds. The prototype emits a credential-free structured result, including lifecycle latency and observed SQLite busy/retry outcomes. A separate Bun 1.4 profiling repetition produces native Markdown CPU and heap profiles into ignored raw scratch state, scrubs paths and credential-shaped values into shareable evidence, and links concise hot-function, retained-object, and retainer-chain findings from the comparison.
>
> **Key interfaces:** the bounded extraction prototype's coordinator/server result boundary; a single `PROTOTYPE_RESULT` JSON record; fixed synthetic fixture files and hashes; exact-runtime child commands; comparison aggregation and regression evaluation; Bun `--cpu-prof-md` / `--heap-prof-md`; raw-to-shareable artifact sanitizer; backend benchmark command surface.
>
> **Acceptance criteria:**
>
> - [ ] One generated synthetic fixture set and one fixed configuration are reused by both runtimes; every repetition gets fresh state, the same gateway behavior, deterministic polling, one warm-up, and at least three steady repetitions.
> - [ ] Structured results include completion/failure counts, jobs per second, p50/p95 lifecycle latency, peak/baseline RSS, normalized CPU, maximum event-loop lag, observed SQLite busy/retry counts, admission rejections/retries, and peak runner/queue/gateway concurrency.
> - [ ] Evidence records Bun version and revision, OS/architecture, CPU model/count, total memory, repository revision/dirty state, workload/permit settings, fixture sizes and SHA-256 identities, repetition count, each repetition, aggregate mean/range/coefficient of variation, and the exact reproducible command.
> - [ ] The comparison fails on incomplete work or material local regressions using documented thresholds: throughput no worse than 10%, lifecycle p95 no worse than 15%, and resource/lag regressions no worse than 15% with practical noise floors.
> - [ ] A Bun 1.4 bounded profiling repetition writes native Markdown CPU and heap profiles to ignored raw state; sanitized evidence replaces absolute paths and credential-shaped values and exposes hot functions, largest retained objects, and retainer chains without fixture content or user/auth/gateway data.
> - [ ] Tests pin aggregation, threshold semantics, stable Markdown structure, structured-result parsing, and sanitizer behavior before the benchmark implementation is accepted.
> - [ ] The backend README and package command reproduce the comparison without configuration edits, and Bun 1.4 focused tests plus the root CI command remain green.
>
> **Out of scope:** Treating the result as production capacity, reproducing Bun's published microbenchmarks, benchmarking a real Model gateway, uploading artifacts externally, storing raw profile data in tracked paths, optimizing application code in response to this first baseline, or changing extraction/admission behavior solely to improve the score.

Implemented and verified on Bun 1.4.0. The existing full-application prototype now accepts one coordinator-owned synthetic fixture set, disables jitter for comparison runs, resets state per invocation, emits exactly one credential-free structured record, records lifecycle and SQLite contention outcomes, and profiles its bounded server child. The documented command launches exact Bun 1.3.14 and 1.4.0 runtimes with a minimal environment, one discarded warm-up, three steady runs each, fixture version/hash assertions, and explicit regression gates. Native raw profiles are explicitly ignored; the shareable CPU/heap excerpts are path/credential scrubbed and bounded to decision-rich tables and retainer chains. TDD captured the missing module and missing raw-ignore rule as red failures before the implementation made seven focused tests green.

The final Apple M3 Pro run passed: Bun 1.3.14 averaged 3.01 jobs/s, 12,943.16 ms lifecycle p95, 393.95 MiB peak RSS, and 0.80% normalized machine CPU; Bun 1.4.0 averaged 2.79 jobs/s, 13,626.06 ms p95, 366.41 MiB RSS, and 0.73% CPU. Both completed 120/120 steady jobs with zero failures and zero SQLite busy/retry outcomes; Bun 1.4 remained within every 10%/15%-plus-noise-floor gate. See `../evidence/19-bun-runtime-comparison.md` and `../evidence/19-bun-runtime-profiles/`. Root CI passed with 209 parallel backend tests plus one real-process smoke test, 250 frontend tests, coverage, and build; the Chromium journey also passed, and the frozen Bun install reported no changes.
