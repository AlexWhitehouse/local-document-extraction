## Agent Brief

**Category:** enhancement
**Summary:** Establish Bun 1.4.0 as the single reproducible Local Bun Runtime and prove the current product surface remains compatible.

**Current behavior:**
CI installs Bun 1.3.14 from a workflow-local value, local tooling has no authoritative version declaration, the Bun type wrapper resolves 1.3.14, Node types target 25, and health diagnostics do not expose the active runtime revision. The lockfile remains readable by 1.3 and uses the pre-1.4 format.

**Desired behavior:**
The root project declaration should be the source of truth for Bun 1.4.0 and CI should consume it. Bun/Node types should describe the runtime actually in use, frozen installs should be deterministic, health diagnostics should identify the exact runtime, and compatibility should be proven across the complete Local Bun Runtime including native canvas and PDF handling. Reverting one isolated upgrade change should restore the prior runtime/type/lock set.

**Key interfaces:**
- The root package-manager declaration is the authoritative Bun version consumed by setup tooling.
- Local runtime health diagnostics expose Bun version and revision without exposing environment data.
- Bun and Node ambient type packages describe the supported runtime APIs.
- The lockfile and frozen-install command form one reproducible dependency contract.

**Acceptance criteria:**
- [x] Local and CI version checks report exactly Bun 1.4.0 from one repository declaration.
- [x] Frozen installation, migration, typecheck, lint, all tests, build, and built-runtime smoke succeed with no lockfile drift.
- [x] Runtime health reports Bun version/revision, and shutdown uses the promise-aware server contract.
- [x] Native canvas plus valid and malformed PDF coverage passes on supported macOS and Linux targets.
- [x] A durable migration note records the isolated lock/type change and one-change rollback procedure.

**Out of scope:**
- Repairing application dependency advisories; tickets 03–05 own those changes.
- Enabling parallel tests, performance tuning, static-file migration, or package-hygiene gates.
- Adopting a newer Bun patch until 1.4.0 qualification is complete.
