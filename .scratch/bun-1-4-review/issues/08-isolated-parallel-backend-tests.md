# 08 — Run Bun-native backend tests isolated and capped-parallel

**What to build:** Give developers and agents a fast Bun-native backend lane that isolates every test file, uses an evidence-based worker cap, and keeps the real-process runtime smoke path safely separated.

**Blocked by:** 02 — Pin and qualify Bun 1.4.0; 07 — Make the Local Bun Runtime smoke harness race-free.

**Category:** enhancement

**Status:** completed

- [x] The routine Bun-native backend lane uses per-file isolation and an explicit worker count rather than the host CPU-count default.
- [x] Two-worker and four-worker measurements record wall time and peak RSS on local and CI hardware; the selected cap has a documented memory budget.
- [x] The real-process smoke test runs in a separate serial step until its 100-run concurrent acceptance gate is satisfied.
- [x] At least twenty complete randomized repetitions pass with no ordering-dependent failure.
- [x] The lane uses zero retries as a correctness gate and reports the seed for any randomized failure.
- [x] Serial and parallel execution produce the same test count and assertions, and leave no processes, listeners, temporary directories, or SQLite handles behind.
