## Agent Brief

**Category:** enhancement
**Summary:** Coordinate Local Bun Runtime shutdown so new work stops before active requests drain and durable resources close exactly once.

**Current behavior:**
Signal handlers synchronously stop periodic work, request a server stop without awaiting completion, and immediately close Workspace product data stores. Document admission, queued Extraction job dispatch, auth closure, analytics flush, active requests, and timeout escalation are not coordinated by one lifecycle contract.

**Desired behavior:**
The first shutdown request should atomically stop new admission and new Extraction job claims, cancel recurring runtime work, and begin graceful server/request drainage. Once active work reaches its defined boundary, the runtime should flush analytics and close auth and Workspace stores exactly once. A deadline or repeated shutdown request should force network shutdown without duplicating durable cleanup.

**Key interfaces:**
- The runtime shutdown entrypoint should return one shared completion promise for every caller.
- Document admission needs an observable closed state that rejects and drains new requests while allowing already-admitted handlers to settle.
- The Local extraction queue needs a shutdown boundary that prevents new dispatch while allowing active handlers to settle without waiting for durable pending metadata.
- Bun server shutdown must be treated as promise-like across the transition from Bun 1.3 to 1.4.

**Acceptance criteria:**
- [x] New Document submissions and Extraction job claims stop before graceful server drainage begins.
- [x] In-flight work settles before analytics, auth, and Workspace stores close.
- [x] Repeated requests and the force deadline do not run durable cleanup more than once.
- [x] Lifecycle tests cover graceful completion, escalation, cleanup failures, and signal-safe invocation.
- [x] The full backend test surface remains green without leaked processes, listeners, temporary state, or database handles.

**Out of scope:**
- Pinning or migrating to Bun 1.4; that is ticket 02.
- OS memory-pressure handling, request-size policy, or Workspace live-update backpressure changes.
- Waiting indefinitely for queued-but-not-active Extraction jobs; durable queue state remains the restart recovery authority.
