# Stripe Billing Event Invalidation

Category: enhancement
Status: completed

## Parent

.scratch/workspace-context-live-invalidation/PRD.md

## What to build

Emit billing Workspace context invalidation after processed Stripe billing events that mutate Workspace billing state, remaining Credits, Plan limits, or submission-blocking state. Ignored irrelevant Stripe events should not emit invalidation. Failed Stripe event processing should emit invalidation only when it performed a durable mutation that affects Workspace context.

Connected frontends should refresh selected Workspace context through the existing throttled invalidation path and should not receive Stripe payload details or owner-only billing state over Workspace live updates.

## Acceptance criteria

- [x] Processed Stripe billing events that change Workspace billing state emit billing invalidation after durable mutation.
- [x] Processed Stripe billing events that grant or revoke Credits emit billing-usage invalidation after durable mutation.
- [x] Processed Stripe billing events that change entitlement, payment state, or Plan limits emit billing-entitlement invalidation after durable mutation.
- [x] Ignored irrelevant Stripe events do not emit invalidation.
- [x] Failed Stripe event processing emits invalidation only if durable Workspace billing state changed before failure.
- [x] Live update payloads do not include Stripe payload data, invoice data, payment details, customer details, or owner-only billing state.
- [x] Connected frontends refresh selected Workspace context and update operational badges from backend recomputation.
- [x] Focused backend Stripe billing coverage verifies mutation-triggered invalidation, ignored-event quiet behavior, failure behavior, and payload boundaries.

## Agent Brief

**Category:** enhancement
**Summary:** Emit Workspace context invalidation after Stripe billing events that durably change Workspace billing state.

**Current behavior:**
The Workspace live update protocol can carry Workspace context invalidation events, and the frontend can refresh the selected accepted Workspace context through the throttled invalidation path. Non-Stripe billing mutations already use this path in several places. Stripe billing webhook processing is centralized and records processed, ignored, and failed events, but Stripe-originated mutations do not yet consistently publish Workspace context invalidation after they change Workspace billing control state, remaining Credits, Plan limits, payment state, or submission-blocking state.

**Desired behavior:**
Processed Stripe billing events that durably change Workspace billing state should emit Workspace context invalidation after the mutation commits. Events that change Credits or remaining billing usage capacity should emit `billing_usage`. Events that change entitlement, payment state, Plan limits, scheduled entitlement state, or submission-blocking state should emit `billing_entitlement`. Ignored irrelevant Stripe events should remain quiet. Failed Stripe event processing should emit invalidation only when the handler already performed a durable mutation that affects Workspace context before failing.

Live update payloads must remain invalidation hints only. They must not include raw Stripe event payloads, invoice data, payment details, customer details, computed Billing operational status, owner-only billing state, account identity, or Workspace API key material.

**Key interfaces:**
- `StripeBillingEventProcessingResult` or equivalent webhook outcome contract — should distinguish no-op/ignored events from durable billing mutations and carry any invalidation reason the dispatcher needs.
- Stripe billing event handlers — should report when they grant Purchased Credits, record Credit pack payment failure activity, activate or suspend self-service subscriptions, update payment-required Plan overrides, update Enterprise invoice/payment states, grant Included Credits, clear scheduled entitlement, or otherwise change Workspace context inputs.
- Workspace context invalidation broadcaster — should continue to publish only versioned `workspace_context_invalidated` events with a reason and occurrence timestamp.
- Billing ledger and Workspace billing control mutation helpers — should be treated as the durable mutation boundary; invalidation should happen only after these calls succeed.
- Stripe event processing record — should continue recording processed, ignored, and failed outcomes without relying on websocket delivery as durable history.

**Acceptance criteria:**
- [ ] Processed Stripe billing events that change Workspace billing state emit Workspace context invalidation after the durable mutation succeeds.
- [ ] Processed Stripe billing events that grant or revoke Credits, or otherwise change remaining Credit/page capacity, emit `billing_usage` invalidation after the durable mutation succeeds.
- [ ] Processed Stripe billing events that change entitlement, payment state, Plan limits, scheduled entitlement state, or submission-blocking state emit `billing_entitlement` invalidation after the durable mutation succeeds.
- [ ] Ignored irrelevant Stripe events and supported Stripe events that do not match Workspace billing metadata do not emit invalidation.
- [ ] Failed Stripe event processing emits invalidation only if durable Workspace billing state changed before the failure.
- [ ] Live update payloads include only the invalidation reason and occurrence timestamp, with no Stripe payload data, invoice data, payment details, customer details, account identity, Workspace API key material, computed Billing operational status, or owner-only billing state.
- [ ] Connected frontends refresh selected Workspace context through the existing throttled invalidation path and update operational badges from backend recomputation.
- [ ] Focused backend Stripe billing coverage verifies mutation-triggered invalidation, ignored-event quiet behavior, failure behavior, and payload boundaries.

**Out of scope:**
- Changing Stripe webhook authentication, signature verification, supported event type selection, or event idempotency semantics.
- Changing Workspace billing product rules, Plan limits, Credit pricing, Credit pack sizes, or Enterprise commercial terms.
- Pushing computed Billing operational status, Credit balances, invoice state, payment state, or owner-only billing information over Workspace live updates.
- Replacing HTTP Workspace context refresh with websocket-sourced billing state.
- Changing frontend throttling or selected Workspace context refresh behavior beyond what is needed to verify Stripe-triggered invalidation.
