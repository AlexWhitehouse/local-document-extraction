# Selected Workspace Context Refresh

Category: enhancement
Status: completed

## Parent

.scratch/workspace-context-live-invalidation/PRD.md

## What to build

Add a narrow accepted Workspace context refresh path that refreshes only the current accepted **Workspace context** instead of fetching all Workspaces and pending Workspace invitations. The refreshed Workspace entry should include the frontend data needed to update header badges, submission-blocking state, Workspace role/access flags, Plan limits, remaining Credits, remaining Plan page capacity, and Workspace API key existence metadata.

The frontend should be able to merge this selected Workspace context refresh into the existing Workspace context state. It should fall back to the existing full Workspace-list/access-recovery path when the selected refresh reports forbidden, not found, or otherwise indicates the accepted Workspace context can no longer be trusted.

## Acceptance criteria

- [ ] A selected accepted Workspace context refresh path is available to signed-in session users with access to the Workspace.
- [ ] The selected refresh returns the current Workspace entry data needed by the frontend without fetching pending Workspace invitations or unrelated Workspaces.
- [ ] The selected refresh uses the same backend **Billing operational status** semantics as the existing Workspace listing path.
- [ ] The frontend can merge a selected refresh result into the current accepted Workspace context without clearing unrelated Workspace-scoped UI state.
- [ ] Forbidden or not-found selected refresh responses fall back to the existing full Workspace-list/access-recovery behavior.
- [ ] Focused backend coverage verifies selected refresh output and parity with Workspace listing **Billing operational status**.
- [ ] Focused frontend coverage verifies selected refresh merge and full-list fallback behavior.

## Agent Brief

**Category:** enhancement
**Summary:** Add a selected accepted Workspace context refresh path for live invalidation.

**Current behavior:**
The frontend refreshes Workspace context through the full Workspace-list flow. That flow fetches accepted Workspaces and pending Workspace invitations, then recomputes Workspace context data for every listed Workspace. Document live update handling can also use this broad refresh path when Workspace capacity may have changed.

**Desired behavior:**
Signed-in session users should be able to refresh only the currently selected accepted **Workspace context**. The selected refresh should return the same Workspace entry data the frontend needs for header badges, submission-blocking state, Workspace role/access flags, Plan limits, remaining Credits, remaining Plan page capacity, and Workspace API key existence metadata. The frontend should merge a successful selected refresh into the current accepted Workspace context without clearing unrelated workspace-scoped UI state. If the selected refresh reports forbidden, not found, or otherwise means the selected Workspace can no longer be trusted, the frontend should fall back to the existing full Workspace-list/access-recovery behavior.

**Key interfaces:**
- Accepted Workspace context refresh HTTP contract — add or extend a session-only route that accepts a Workspace ID and returns one current accepted Workspace entry, not pending invitations or unrelated Workspaces.
- Workspace entry response shape — preserve the fields used by the existing Workspace listing response, including `has_api_key`, role/access flags, `billing_plan_limits`, `billing_usage_summary`, and `billing_operational_status`.
- Billing operational status computation — selected refresh and Workspace listing must share the same backend semantics so blocker badges cannot drift between refresh paths.
- Frontend Workspace context refresh API — expose a selected-refresh path that can update the selected accepted Workspace entry in-place and separately invoke full-list access recovery when selected refresh is no longer authorized.

**Acceptance criteria:**
- [ ] A selected accepted Workspace context refresh path is available to signed-in session users with access to the Workspace.
- [ ] The selected refresh returns the current Workspace entry data needed by the frontend without fetching pending Workspace invitations or unrelated Workspaces.
- [ ] The selected refresh uses the same backend **Billing operational status** semantics as the existing Workspace listing path.
- [ ] The frontend can merge a selected refresh result into the current accepted Workspace context without clearing unrelated Workspace-scoped UI state.
- [ ] Forbidden or not-found selected refresh responses fall back to the existing full Workspace-list/access-recovery behavior.
- [ ] Focused backend coverage verifies selected refresh output and parity with Workspace listing **Billing operational status**.
- [ ] Focused frontend coverage verifies selected refresh merge and full-list fallback behavior.

**Out of scope:**
- Emitting or parsing Workspace context invalidation websocket events.
- Throttling live invalidation refresh bursts.
- Changing Template, Document, billing, Stripe, or membership mutation paths to emit invalidation events.
- Changing final backend enforcement for Document submission, Template Plan limits, member Plan limits, Credits, or Plan page capacity.
- Sending computed billing badge strings, Credit balances, invoice details, payment details, or owner-only billing details over Workspace live updates.
