# Workspace Live Update Invalidation Protocol

Category: enhancement
Status: completed

## Parent

.scratch/workspace-context-live-invalidation/PRD.md

## What to build

Extend the **Workspace live update** protocol with a `workspace_context_invalidated` event that carries a reason code and occurrence timestamp without computed billing values. Update the frontend live update parser so **Extraction job** lifecycle events update Documents UI state, while Workspace context invalidation events schedule throttled selected Workspace context refreshes.

Replace the current behavior where any live **Extraction job** lifecycle event triggers Workspace capacity refresh. Live invalidation refreshes should coalesce bursts, enforce a minimum interval, and run a trailing refresh when invalidations arrive during the throttle window.

## Acceptance criteria

- [ ] Workspace live update envelopes support `workspace_context_invalidated` events with reason and occurrence timestamp.
- [ ] Invalidation events do not include computed **Billing operational status**, remaining Credits, remaining Plan page capacity, invoice data, payment data, API keys, or account identity.
- [ ] The frontend parser separates **Extraction job** lifecycle events from Workspace context invalidation events.
- [ ] Unknown or malformed live update payloads are ignored safely.
- [ ] Live **Extraction job** lifecycle events update Documents UI state without directly refreshing Workspace context.
- [ ] Workspace context invalidation events schedule selected Workspace context refresh through a throttled refresh scheduler.
- [ ] Burst invalidations coalesce into bounded selected Workspace context refreshes and include a trailing refresh.
- [ ] Stale websocket events are ignored after accepted Workspace context changes or socket replacement.
- [ ] Focused frontend coverage verifies parser behavior, throttling, trailing refresh, stale socket guards, and the removal of job-event-driven context refresh.
- [ ] Focused backend coverage verifies the invalidation envelope shape and payload boundaries.

## Agent Brief

**Category:** enhancement
**Summary:** Extend Workspace live updates with explicit Workspace context invalidation events and throttled selected-context refresh handling.

**Current behavior:**
Workspace live updates currently carry **Extraction job** lifecycle events for an accepted **Workspace context**. The frontend uses those lifecycle events to update Documents UI state, but it also treats any received live job event as a signal to refresh Workspace capacity. That couples document-status freshness to Workspace context freshness, so high-volume ingestion can make connected browsers repeatedly refetch Workspace context even when the websocket event only describes job state.

**Desired behavior:**
Workspace live updates should support a separate `workspace_context_invalidated` event. The event should carry only a reason code and occurrence timestamp. It must not carry computed **Billing operational status**, remaining Credits, remaining Plan page capacity, invoice data, payment data, API keys, account identity, or owner-only billing details.

The frontend should parse live update envelopes into separate groups: **Extraction job** lifecycle events update Documents UI state, while Workspace context invalidation events schedule selected **Workspace context** refreshes. Extraction job lifecycle events should no longer directly trigger Workspace context refresh. Invalidation-triggered refreshes should be coalesced and throttled, with a trailing refresh when additional invalidations arrive during the throttle window. Events from stale sockets should be ignored after the accepted **Workspace context** changes or a replacement socket is installed.

**Key interfaces:**
- Workspace live update envelope — versioned batch messages should accept both `extraction_job_lifecycle` and `workspace_context_invalidated` event types.
- `workspace_context_invalidated` event shape — should include a reason code such as `billing_usage`, `billing_entitlement`, `template_limits`, `member_limits`, or `workspace_access`, plus an occurrence timestamp.
- Frontend live update parser — should ignore unknown, unsupported, or malformed payloads safely and return recognized job lifecycle events separately from Workspace context invalidation events.
- Live invalidation refresh scheduler — should call the selected accepted Workspace context refresh path, enforce a minimum interval, coalesce bursts, and run a trailing refresh when needed.
- Workspace live update broadcaster/helper — should expose a narrow way for backend mutation paths to publish Workspace context invalidation hints without embedding billing or identity data in websocket payloads.

**Acceptance criteria:**
- [ ] Workspace live update envelopes support `workspace_context_invalidated` events with reason and occurrence timestamp.
- [ ] Invalidation events do not include computed **Billing operational status**, remaining Credits, remaining Plan page capacity, invoice data, payment data, API keys, account identity, or owner-only billing details.
- [ ] The frontend parser separates **Extraction job** lifecycle events from Workspace context invalidation events.
- [ ] Unknown, unsupported, and malformed live update payloads are ignored safely.
- [ ] Live **Extraction job** lifecycle events continue to update Documents UI state without directly refreshing Workspace context.
- [ ] Workspace context invalidation events schedule selected Workspace context refresh through a throttled refresh scheduler.
- [ ] Burst invalidations coalesce into bounded selected Workspace context refreshes and include a trailing refresh.
- [ ] Stale websocket events are ignored after accepted Workspace context changes or socket replacement.
- [ ] Focused frontend coverage verifies parser behavior, throttling, trailing refresh, stale socket guards, and removal of job-event-driven context refresh.
- [ ] Focused backend coverage verifies the invalidation envelope shape and payload boundaries.

**Out of scope:**
- Emitting invalidation events from every Template, Document, billing, Stripe, or membership mutation path; those are covered by follow-on issues.
- Changing the selected accepted Workspace context refresh contract beyond what this protocol needs.
- Computing billing badges, Credit balances, Plan page capacity, invoice state, payment state, or owner-only billing details from websocket payloads.
- Making Workspace live updates durable history or a replacement for HTTP Workspace context revalidation.
- Allowing Workspace API keys to open Workspace live update sockets.
