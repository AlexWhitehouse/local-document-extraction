## Agent Brief

**Category:** enhancement
**Summary:** Extract unauthenticated auth presentation and signed-in profile menu presentation into feature-owned components while preserving existing auth and profile behavior.

**Current behavior:**
The root App component still owns unauthenticated sign-in/sign-up presentation and signed-in profile menu presentation alongside session state, auth client calls, profile request orchestration, profile draft state, sign-out cleanup, and feedback logging/toasts. Existing behavior includes email/password sign-in, Google sign-in start, sign-up password policy feedback, confirm-password mismatch feedback, profile name editing, and sign-out cleanup.

**Desired behavior:**
Unauthenticated auth presentation should live behind an auth feature component interface, and signed-in profile menu presentation should live behind a profile feature component interface. App should continue to own session state, auth client calls, profile API orchestration, profile draft state, sign-out cleanup, workspace/document cleanup on sign-out, and feedback behavior for this slice. User-visible fields, labels, validation feedback, provider sign-in behavior, profile editing behavior, and sign-out behavior should remain unchanged.

**Key interfaces:**
- An auth feature presentation component that receives explicit props for auth mode, form values, password-policy state, busy state, submit handling, provider sign-in handling, mode switching, and field updates.
- A profile feature presentation component that receives explicit props for displayed profile identity, menu open state, profile draft value, dirty/saving/busy state, panel ref or equivalent outside-click integration, and callbacks for toggling, editing, saving, and signing out.
- Existing App-owned auth and profile orchestration for session refetching, Better Auth email/social calls, profile loading/saving, sign-out cleanup, and user-facing feedback.
- Existing App-level behavior tests covering auth feedback, password policy feedback, provider sign-in failure feedback, profile editing, and sign-out behavior.

**Acceptance criteria:**
- [ ] Sign-in and sign-up UI render the same fields, actions, password policy feedback, and auth feedback as before.
- [ ] Provider sign-in behavior and feedback remain unchanged.
- [ ] Profile menu display, profile editing, and sign-out behavior remain unchanged.
- [ ] Auth and profile orchestration remains App-owned for this slice; the extracted components are presentation-focused and use explicit props.
- [ ] Existing frontend tests pass with `npm run test --prefix frontend`.
- [ ] The frontend production build succeeds with `npm run build --prefix frontend`.

**Out of scope:**
- Moving session state, auth client calls, profile API request orchestration, sign-out cleanup, workspace/document cleanup, or feedback logging/toasts out of App.
- Introducing React Context, stateful feature hooks, URL routing, API client extraction, or CSS modularisation.
- Changing Better Auth configuration, backend API contracts, user-visible auth/profile behavior, labels, validation semantics, password policy rules, provider sign-in semantics, or Stored workspace preference behavior.
