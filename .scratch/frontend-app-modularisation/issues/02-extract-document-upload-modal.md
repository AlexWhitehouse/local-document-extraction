## Agent Brief

**Category:** enhancement
**Summary:** Extract the Document upload modal presentation into the Documents feature while preserving existing upload behavior and App-level orchestration.

**Current behavior:**
The root App component still owns the Document upload modal markup alongside the state and orchestration used to open and close the modal, select the upload Template, collect Source files, show drag-and-drop state, queue Documents, update per-file queue status, and show the aggregate Document upload toast.

**Desired behavior:**
The upload modal presentation should live in the Documents feature behind a focused component interface. App should continue to own upload state, request orchestration, selected upload Template state, queueing behavior, and Document upload toast behavior for this slice. User-visible behavior, labels, supported Source file formats, queue status display, and upload outcomes should remain unchanged.

**Key interfaces:**
- A Documents feature upload modal component that receives explicit props for modal visibility, Template options, selected upload Template, selected Source files, drag-active state, upload-in-progress state, API-access availability, and callbacks for close, Template selection, Source file selection, drag/drop handling, file removal, and upload submission.
- Existing App upload orchestration functions and state for queueing Documents, preserving selected upload Template behavior, and emitting Document upload toasts.
- Existing App-level behavior tests covering single Document upload, Source file language, multipart field names, per-file queue status display, and mixed multi-file upload toast aggregation.

**Acceptance criteria:**
- [ ] The upload modal opens and closes exactly as before, including refusing to close while Documents are uploading.
- [ ] The selected upload Template behavior is unchanged when opening the modal and changing the Template select value.
- [ ] Source file selection, drag-and-drop, duplicate prevention, removal, queue status display, and queue error display behave the same as before.
- [ ] Supported Source file formats remain PNG, JPEG, WebP, and PDF, and Document submission still uses the existing `document` multipart field.
- [ ] Upload actions still queue Documents through App-owned orchestration and preserve aggregate Document upload toast feedback.
- [ ] Existing frontend tests pass with `npm run test --prefix frontend`.
- [ ] The frontend production build succeeds with `npm run build --prefix frontend`.

**Out of scope:**
- Moving upload state, API request helpers, queue orchestration, or Document upload toast orchestration out of App.
- Introducing React Context, stateful feature hooks, URL routing, API client extraction, or CSS modularisation.
- Changing user-visible upload behavior, labels, validation semantics, supported file formats, backend API contracts, or Document/Source file terminology.
