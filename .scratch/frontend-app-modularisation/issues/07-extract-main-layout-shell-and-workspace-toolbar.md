## Agent Brief

**Category:** enhancement
**Summary:** Extract the main application layout shell, Workspace toolbar, and operational metrics while preserving the current single-page frontend behavior.

**Current behavior:**
The root App component remains the public orchestration component and already delegates several feature-specific presentation areas to frontend modules. App still renders the main signed-in app frame inline, including the left sidebar shell, main navigation, profile placement, global upload action, Workspace toolbar, page-specific primary/destructive toolbar actions, and operational metrics. App also owns session state, Workspace context, shared feature state, request orchestration, cross-feature callbacks, and user-facing feedback.

**Desired behavior:**
The signed-in layout shell, Workspace toolbar, and operational metrics presentation should be extracted behind layout-oriented component interfaces. User-visible behavior must remain unchanged: Active page switching, sidebar counts, upload action availability, Workspace context display, API access state, page-specific toolbar actions, and Template/Document/completion/failure metrics should render and behave exactly as they do today. App should remain the public root component and continue to own cross-feature orchestration, state, side effects, request helpers, Workspace context transitions, and callbacks during this slice.

**Key interfaces:**
- The root App component remains the public orchestration boundary and passes explicit props into extracted layout presentation components.
- The main layout shell should render the signed-in app frame, left sidebar navigation, global upload action, profile placement, context sidebar slot, main content slot, and modal/content slots without taking ownership of feature state or side effects.
- Sidebar navigation should preserve Active page labels, selected styling, counts for Workspaces/Templates/Documents, and navigation callback behavior.
- Workspace toolbar presentation should preserve Workspace context display, Loading workspace context and Workspace resolution error text, pending-invitation API-locked state, accepted Workspace API readiness state, Jobs count, page-specific primary action, and page-specific destructive action behavior.
- Operational metrics presentation should preserve Template count, Document count, completion percentage/progress accessibility label, and failed Extraction job count.
- Existing App-level behavior tests remain the primary regression safety net for this slice.

**Acceptance criteria:**
- [x] Sidebar navigation preserves Active page switching, selected styling, counts, upload action availability, and labels.
- [x] Profile placement in the left sidebar remains unchanged and continues to use the existing profile menu behavior.
- [x] Workspace toolbar preserves Workspace context display, API access state, pending invitation status, page-specific primary action behavior, and page-specific destructive action behavior.
- [x] Operational metrics preserve Template, Document, completion, and failure displays, including the completion progress accessibility label.
- [x] App remains the public root component and continues to orchestrate session, Workspace context, shared state, request helpers, side effects, and cross-feature handlers.
- [x] Existing frontend tests pass with `npm run test --prefix frontend`.
- [x] The frontend production build succeeds with `npm run build --prefix frontend`.

**Out of scope:**
- Changing user-visible behavior, labels, Active page semantics, Workspace context semantics, Workspace API key display semantics, Template behavior, Document behavior, or Action toast behavior.
- Moving state, request helpers, effects, Workspace context transitions, API access decisions, or cross-feature orchestration out of App.
- Introducing URL routing, React Context, stateful feature hooks, API client extraction, CSS modularisation, backend API changes, storage key changes, or UI redesign.
