## Agent Brief

**Category:** enhancement
**Summary:** Extract Template field editing and Template JSON modal presentation into the Templates feature while preserving existing Template authoring behavior.

**Current behavior:**
The root App component still owns Template field editing UI, object schema editing UI, Template JSON modal presentation, and the pure helpers that normalize, hydrate, validate, serialize, and parse Template field data. App also owns Template authoring state, Template JSON modal state, save/update orchestration, API calls, and Action toast feedback.

**Desired behavior:**
Template field editing and Template JSON modal presentation should live in the Templates feature behind focused component interfaces. Pure Template field/schema helpers that are tightly owned by those extracted components should move with the Templates feature. App should continue to own Template authoring state, API request orchestration, workspace access checks, save/update calls, and Action toast feedback for this slice. User-visible Template authoring behavior, validation semantics, JSON payload shape, copy-to-clipboard feedback, save/cancel behavior, and object schema editing behavior must remain unchanged.

**Key interfaces:**
- A Templates feature component for Template field editing that receives explicit props for the current Template fields and a change callback, and preserves field creation, duplication, removal, reordering, required flags, data type changes, generated field IDs, and object schema editing.
- A Templates feature modal component for Template JSON export/import that receives explicit props for visibility, JSON draft value, validation/copy state, save state, API-access availability, and callbacks for draft changes, save, cancel, close, and copy-to-clipboard.
- Template field/schema helper functions that normalize field names, field IDs, data types, object schemas, object metadata, hydrated Template fields, and Template JSON payloads without changing current validation errors or serialized payload shape.
- Existing App-owned Template orchestration for creating, updating, loading, saving Template JSON, workspace-scoped API access, and Action toast feedback.

**Acceptance criteria:**
- [ ] Template field editing preserves field creation, duplication, removal, reordering, required flags, data type changes, generated field IDs, and object schema editing behavior.
- [ ] Object-like Template fields preserve table column creation, removal, reordering, heading sanitization, generated column IDs, column type changes, and column descriptions.
- [ ] Template JSON export/import preserves validation, save, cancel, and copy-to-clipboard behavior, including existing user-visible validation errors and copied feedback.
- [ ] Pure Template field/schema helpers owned by extracted Template components move with the Templates feature without changing Template JSON payload shape or Template field hydration semantics.
- [ ] Focused frontend tests cover complex Template field or object schema behavior after extraction.
- [ ] Existing frontend tests pass with `npm run test --prefix frontend`.
- [ ] The frontend production build succeeds with `npm run build --prefix frontend`.

**Out of scope:**
- Moving Template authoring state, API request helpers, workspace access checks, save/update orchestration, or Action toast orchestration out of App.
- Introducing React Context, stateful feature hooks, URL routing, API client extraction, or CSS modularisation.
- Changing user-visible Template authoring behavior, Template validation semantics, Template JSON payload shape, backend API contracts, Workspace behavior, or Document upload behavior.
