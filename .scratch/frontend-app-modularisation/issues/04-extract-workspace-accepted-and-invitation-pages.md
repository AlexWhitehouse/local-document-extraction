## Agent Brief

**Category:** enhancement
**Summary:** Extract accepted Workspace and Workspace invitation page presentation while preserving current Workspace behavior.

**Current behavior:**
The root App component still renders the accepted Workspace page and the **Workspace invitation** / **Locked invitation state** inline. App also owns Workspace context transitions, API requests, confirmation prompts, and side effects. Existing behavior already distinguishes accepted **Workspace selection view** entries from **Invited workspace entry** selection and locks workspace-scoped actions until an invitation is accepted.

**Desired behavior:**
Workspace page presentation should be split into separate feature-owned views for accepted Workspace access and **Workspace invitation** access. The accepted Workspace view should render the same Workspace name editing, **Workspace API key display**, invite user controls, Workspace users, and pending invitation management. The **Workspace invitation** view should render the same **Locked invitation state**, invitation details, accept action, and decline action. App should continue to own Workspace context transitions, requests, confirmation prompts, and side effects during this phase.

**Key interfaces:**
- The root App component should remain the public orchestration boundary and pass explicit props into extracted presentation components.
- Workspace context display data should continue to distinguish accepted Workspace access from selected pending Workspace invitations.
- Workspace invitation accept/decline callbacks, Workspace user-management callbacks, Workspace API key callbacks, and Workspace mutation callbacks should keep their existing externally visible behavior.
- Existing App-level Workspace behavior tests should remain the primary regression safety net for this slice.

**Acceptance criteria:**
- [ ] Accepted Workspace UI preserves Workspace name editing, **Workspace API key display**, invite user controls, Workspace users, and pending invitation management.
- [ ] **Workspace invitation** UI preserves **Locked invitation state**, invitation details, accept action, and decline action.
- [ ] Workspace-scoped actions remain disabled or unavailable in invitation state exactly as before.
- [ ] Existing App-level Workspace behavior tests continue to pass.
- [ ] The frontend production build succeeds.

**Out of scope:**
- Changing user-visible Workspace, Workspace invitation, Workspace API key, or Workspace user-management behavior.
- Moving Workspace state, request helpers, confirmation prompts, or side effects out of App.
- Introducing React Context, route changes, API client extraction, CSS modularisation, backend API changes, or storage key changes.
