## Agent Brief

**Category:** enhancement
**Summary:** Extract the context sidebar shell and page-specific context lists while preserving existing Workspaces, Templates, and Documents navigation behavior.

**Current behavior:**
The root App component still renders the context sidebar shell inline. It owns the page-specific list presentation for Documents, Templates, and Workspaces, including search inputs, selected item highlighting, empty or loading states, load-more controls, invited Workspace entries, and footer status chips. App also owns the state, request orchestration, Workspace context transitions, and selected item callbacks that drive those lists.

**Desired behavior:**
The shared context sidebar layout should be extracted into a reusable layout component, and each feature should own its own context list presentation. The Documents list should preserve Document search, selected Document highlighting, empty state text, and load-more behavior. The Templates list should preserve Template search, draft entry behavior, selected Template highlighting, and loading/editing affordances. The Workspaces list should preserve search, accepted Workspace entries, Invited workspace entries, Loading workspace context, Workspace resolution error display, and retry behavior. App should continue to own cross-feature state, request orchestration, Workspace transitions, selected IDs, and callbacks during this slice.

**Key interfaces:**
- A shared context sidebar layout component that renders the current Active page heading, a feature-owned list body, and footer status chips without owning feature-specific branching behavior.
- A Documents feature context list component that receives explicit props for search text, Document items, selected Document, pagination/loading state, empty-state conditions, and callbacks for search changes, Document selection, and loading more Documents.
- A Templates feature context list component that receives explicit props for search text, Template items, draft Template entry state, current editing/selection state, and callbacks for search changes, draft selection, and Template selection.
- A Workspaces feature context list component that receives explicit props for search text, accepted Workspace entries, Invited workspace entries, selected Workspace selection view, Loading workspace context state, Workspace resolution error state, and callbacks for search changes, accepted Workspace selection, invited Workspace selection, and retrying Workspace resolution.
- Existing App-owned orchestration for state, effects, API requests, Workspace context transitions, and Action toast feedback should remain the source of truth for this phase.

**Acceptance criteria:**
- [x] Document context list preserves search, selected **Document**, empty state, and load-more behavior.
- [x] Template context list preserves search, draft entry, selected Template, and template-loading behavior.
- [x] Workspace context list preserves search, accepted Workspace entries, **Invited workspace entries**, loading state, resolution error state, and retry action.
- [x] Context sidebar footer status chips preserve existing counts and labels for each **Active page**.
- [x] App remains the public orchestration component and continues passing explicit props rather than introducing React Context or stateful feature hooks.
- [x] Existing frontend tests pass with `npm run test --prefix frontend`.
- [x] The frontend production build succeeds with `npm run build --prefix frontend`.

**Out of scope:**
- Moving Workspace, Template, or Document state, effects, request helpers, or cross-feature orchestration out of App.
- Introducing URL routing, React Context, stateful feature hooks, API client extraction, CSS modularisation, or backend API changes.
- Changing user-visible behavior, labels, status chip wording, search semantics, selection behavior, Workspace invitation semantics, or Document pagination behavior.
