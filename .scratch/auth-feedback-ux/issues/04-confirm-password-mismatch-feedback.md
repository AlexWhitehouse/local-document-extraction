# Add Confirm-Password Mismatch Feedback

Category: enhancement
Status: completed

## What to build

Add Confirm Password to sign-up as a frontend-only guard against typos. Confirm-password mismatch should provide immediate inline feedback, red outlines on both password text boxes while values differ, and a Sonner error toast when mismatch blocks account creation.

## Agent Brief

**Category:** enhancement
**Summary:** Add frontend-only confirm-password validation and mismatch feedback to sign-up.

**Current behavior:**
The sign-up flow validates required name, email, password, and the **Account password policy**, then sends only the actual password to the auth backend. Users currently have no Confirm Password field, so password typos are not caught before account creation.

**Desired behavior:**
Sign-up should include a required Confirm Password field that exists only in frontend form state and is never sent to the auth backend. Once Confirm Password has input, Password and Confirm Password should both show mismatch styling while their values differ, including when Confirm Password has text and Password is empty. The mismatch styling and inline message should disappear immediately once the two values match. Submitting with a mismatch should be blocked before any auth backend call and should show the Sonner error toast “Passwords do not match.” Switching between Sign In and Sign Up should clear password, confirm password, and password-validation state while preserving email and name. The auth form should continue to submit the active mode with Enter.

**Key interfaces:**
- The auth form state should include Confirm Password as sign-up-only frontend state.
- The sign-up submit path should treat Confirm Password as a required field for frontend validation but omit it from the auth client sign-up payload.
- The auth form UI should expose accessible Password and Confirm Password fields, inline mismatch text, and visually clear mismatch styling on both password fields.
- The existing Sonner auth error feedback should be used for blocked mismatch submissions.

**Acceptance criteria:**
- [x] Sign-up includes a Confirm Password field.

- [x] Confirm Password is frontend-only and is not sent to the auth backend.

- [x] If Confirm Password has text and Password is empty, both fields are outlined in red.

**Out of scope:**
- Sending Confirm Password to the backend.
- Changing the backend **Account password policy** or auth endpoint behavior.
- Password reset or email verification flows.
- Success toasts for auth events.
- A full inline required-field error system for name, email, or missing password fields.
