## Agent Brief

**Category:** enhancement
**Summary:** Add visible Sonner failure feedback for sign-in paths while preserving existing auth logging.

**Current behavior:**
Email sign-in and Google sign-in failures are written to the existing activity log, but unauthenticated users do not see that log on the auth screen. The sign-in controls are button-driven rather than relying on normal form submission, so pressing Enter is not guaranteed to submit the active sign-in flow.

**Desired behavior:**
Email sign-in validation failures, email sign-in auth failures, and Google sign-in startup failures should show visible Sonner error toasts. Sign-in auth failures and Google sign-in failures should use generic safe user-facing messages rather than raw provider/auth details. Successful auth events should not show success toasts. Existing activity-log behavior should remain intact. Pressing Enter in sign-in mode should submit sign-in.

**Key interfaces:**
- The frontend auth screen's sign-in submit behavior should support normal form submission for the active auth mode.
- The auth notification behavior should use a single global Sonner toaster with rich error styling.
- The auth failure handling path should separate user-facing safe messages from raw diagnostic messages kept in the existing log.

**Acceptance criteria:**
- [ ] Email sign-in validation failures show a Sonner error toast that reports all missing required fields at once.
- [ ] Email sign-in server/auth failures show a generic safe toast that does not reveal whether an email address exists.
- [ ] Google sign-in startup failures show a generic safe toast rather than raw OAuth details.
- [ ] Successful auth events do not show success toasts.
- [ ] Existing activity-log messages for sign-in and Google sign-in outcomes are preserved.
- [ ] The auth screen has one global Sonner toaster using error styling with rich colors.
- [ ] Pressing Enter in sign-in mode submits sign-in.
- [ ] Focused verification covers the observable sign-in failure behavior.
- [ ] Frontend production build passes.

**Out of scope:**
- Sign-up password-policy feedback.
- Confirm Password behavior.
- Backend Account password policy enforcement.
- Success toasts for auth events.
- Toasts for non-auth app operations.
