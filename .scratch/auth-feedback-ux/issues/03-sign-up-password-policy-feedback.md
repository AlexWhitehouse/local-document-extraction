# Add Sign-Up Password-Policy Feedback

Category: enhancement
Status: completed

## Parent

.scratch/auth-feedback-ux/PRD.md

## What to build

Add visible sign-up feedback for account creation failures and live inline guidance for the **Account password policy**. Users should see requirement messages while composing a password, blocked submits should show Sonner feedback, and common sign-up failures should be translated into actionable user-facing toasts.

## Acceptance criteria

- [x] Password-policy requirement messages appear only in sign-up mode.
- [x] Requirement messages appear after password typing begins or after an invalid sign-up submit attempt.
- [x] Requirement copy is “At least 8 characters”, “One uppercase letter”, “One number”, and “One special character”.
- [x] Each requirement message disappears as soon as the entered password satisfies that requirement.
- [x] Unmet password-policy requirements do not create red password field outlines.
- [x] Create Account remains clickable unless a request is busy.
- [x] Submitting with an unmet Account password policy is blocked and shows “Password must meet all complexity requirements.” as a Sonner error toast.
- [x] Missing sign-up fields are reported in one toast.
- [x] Email already in use and invalid email sign-up failures map to friendly actionable toasts.
- [x] Unknown sign-up failures use a generic safe toast.
- [x] Existing activity-log messages for sign-up outcomes are preserved.
- [x] Focused verification covers live requirement visibility, blocked submit feedback, and sign-up error mapping.
- [x] Frontend production build passes.

## Agent Brief

**Category:** enhancement
**Summary:** Add live sign-up Account password policy feedback and actionable sign-up failure toasts.

**Current behavior:**
The sign-up flow calls the auth client and writes failures to the existing activity log, but unauthenticated users do not get visible feedback on the auth screen. The sign-up password field does not show live **Account password policy** guidance while the user types, and blocked submissions do not currently surface the agreed password-policy toast behavior.

**Desired behavior:**
Sign-up should show live inline **Account password policy** requirement messages after password typing begins or after an invalid submit attempt. Each requirement should disappear as soon as the entered password satisfies it. Submitting while the password does not meet the policy should be blocked and show the Sonner error toast “Password must meet all complexity requirements.” Missing sign-up fields, email already in use, invalid email, and unknown sign-up failures should show the agreed user-facing toast behavior while preserving existing activity-log messages.

**Key interfaces:**
- The frontend sign-up validation path should consume the app-owned Account password policy semantics established by the completed backend/policy issue.
- The sign-up failure mapping should translate known client-side and auth/server failures into safe user-facing messages.
- The auth notification behavior should use the existing global Sonner toaster rather than adding a separate notification abstraction.
