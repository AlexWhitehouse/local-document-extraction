## What to build

Replace broad legacy browser persistence with a clean Stored workspace preference contract. The frontend writes a new Document Extraction storage key containing only accepted Workspace ID and display name, does not read the legacy Image Extraction key, and stops persisting user/session-specific or workspace-scoped backend data through the workspace preference blob.

## Agent Brief

**Category:** enhancement
**Summary:** Replace broad legacy browser persistence with a narrow Stored workspace preference contract.

**Current behavior:**
The frontend still has local browser persistence shaped like a broad workspace/session blob. It can initialize auth form values, API key material, per-Workspace API key maps, Templates, selected upload Template, selected Document, and job history from persisted data. That broad persistence mixes user/session-specific fields, workspace-scoped backend data, and secret material with Workspace preference, and legacy synthetic Workspace IDs can re-enter local state.

**Desired behavior:**
Browser persistence for Workspace selection should be a clean **Stored workspace preference** only. The SPA should write a new Document Extraction storage key containing only accepted Workspace ID and display name. It should not read or migrate the legacy Image Extraction key, should treat legacy `workspace_local_default` values as no accepted Workspace preference, and should not persist auth form values, Workspace API key material, Templates, selected upload Template, selected Document, job history, or Active page through the Workspace preference blob. Sign-out should clear Stored workspace preference and user-specific stored workspace data.

**Key interfaces:**
- Stored workspace preference shape - should contain only accepted Workspace ID and display name, with no API key, API base, auth form, Template, Document, job history, invitation, or page state.
- Local storage adapter - should read and write the new Document Extraction storage key and intentionally ignore the legacy Image Extraction storage key.
- Workspace resolution logic - should use Stored workspace preference only as a hint that must still match a backend-confirmed accepted Workspace.
- Sign-out cleanup - should clear Stored workspace preference and any user-specific browser data that could expose previous Workspace context.

**Acceptance criteria:**
- [x] The frontend writes Stored workspace preference under a new Document Extraction local storage key.
- [x] The frontend does not read or migrate the legacy `imageextraction.workspace.v1` key.
- [x] Stored workspace preference contains only accepted Workspace ID and display name.
- [x] Auth form values are not initialized from or written to Stored workspace preference.
- [x] Workspace API key material and per-Workspace API key maps are not initialized from or written to Stored workspace preference.
- [x] Templates, job history, selected Document, selected upload Template, and Active page are not initialized from or written to Stored workspace preference.
- [x] Legacy `workspace_local_default` values do not enter accepted Workspace context.
- [x] Sign-out clears Stored workspace preference and user-specific stored workspace data.
- [x] Relevant frontend checks cover storage shape, legacy-key ignore behavior, stale/synthetic preference handling, and sign-out cleanup.
- [x] Verification includes the frontend production build.

**Out of scope:**
- Migrating data from the legacy Image Extraction local storage key.
- Persisting Active page or adding URL routing for page restoration.
- Completed Document cache retention behavior, except where sign-out or accepted Workspace context changes require clearing user-specific data.
- Workspace API key display and one-time key visibility rules.
