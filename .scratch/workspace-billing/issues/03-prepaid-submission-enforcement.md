# Prepaid Submission Enforcement

Category: enhancement
Type: AFK
Status: completed

## Parent

.scratch/workspace-billing/PRD.md

## What to build

Enforce prepaid Credit and Plan page capacity on Document submission for non-enterprise Workspaces. The backend should generate the Extraction job ID, determine exact Billable Document page count, reserve Credits and page usage in the Billing ledger, then store the Source file and create/queue the Extraction job. If the Workspace lacks Credits or monthly page capacity, reject before Source file storage. If billing succeeds but later acceptance work fails, record a compensating refund.

This slice should be demoable by manually granting Credits, submitting images and PDFs successfully, exhausting Credits or Free monthly capacity, and seeing blocked submissions without orphaned Source files.

## Agent Brief

**Category:** enhancement
**Summary:** Enforce prepaid Credit and Plan page capacity before accepting non-enterprise Document submissions.

**Current behavior:**
Workspace billing has a Free Active entitlement by default, an owner-only Billing page, a per-Workspace Billing ledger Durable Object, manual Goodwill Credit grants/revocations, Owner billing activity, and Application admin billing audit entries. Document submission already validates the selected Template, generates an Extraction job ID, detects PDF Source file page count, stores the Source file, creates a queued Extraction job, sends queue work, and emits product analytics. It does not yet reserve Credits or record Plan page limit usage before accepting a submission. The existing Billing ledger only covers Goodwill Credit grant/revoke activity, so successful Document submissions do not spend Credits and monthly page capacity is always reported as unused.

**Desired behavior:**
For non-enterprise Workspaces, a Document submission should be accepted only after Workspace billing has enough prepaid Credits and remaining monthly Plan page capacity for the exact Billable Document page count. Image Documents count as one Billable Document page. PDF Documents count by detected Source file page count. Billing validation and reservation must happen after exact page count is known and before Source file storage, queued Extraction job creation, queue send, or analytics emission.

When the reservation succeeds, the Billing ledger records a Credit reservation and current Billing period page usage using an internally generated idempotency key derived from the generated Extraction job ID. Credit reservation entries should capture Workspace ID, Extraction job ID, Template ID/version, Billable Document page count, submission time, actor or auth mode when available, and the idempotency key. Reservations should spend Included Credits before other eligible prepaid Credit buckets.

If the Workspace lacks Credits or remaining monthly page capacity, the submission should return a billing/entitlement error and leave no Source file, Extraction job, queue message, or analytics event behind. If billing reservation succeeds but Source file storage, queued Extraction job creation, or queue send fails before the submission is accepted, the Billing ledger should record a Credit refund or equivalent compensating entry that restores Credits and Plan page limit capacity. Deleting an Extraction job must not refund Credits or reduce historical page usage.

The frontend should treat billing summaries as advisory: when the Workspace is already blocked, Document upload controls should be disabled before file selection and show limited Billing operational status without owner-only invoice/payment details. Backend enforcement remains authoritative because exact PDF page count is known only during submission.

**Key interfaces:**
- Billing ledger Durable Object RPC surface — add reservation, refund/compensation, page-usage accounting, rebuildable Credit/page summaries, and idempotency behavior for submission reservations.
- Billing ledger entry model — add append-only entries for Credit reservations and Credit refunds/corrections while preserving Goodwill grant/revocation history.
- Billing entitlement summary contract — expose available Credits, current-period page usage/capacity, and advisory blocking reasons in a way that owner and non-owner product surfaces can safely consume.
- Document submission acceptance contract — generate the Extraction job ID before reservation, compute Billable Document page count, reserve billing before product side effects, compensate on later acceptance failure, and keep analytics after successful acceptance.
- Workspace product data interaction — create queued Extraction jobs only after billing has accepted the submission.
- Frontend Document upload controls — consume advisory Billing operational status to disable upload when already blocked, while still handling final backend billing rejection after exact page count is known.
