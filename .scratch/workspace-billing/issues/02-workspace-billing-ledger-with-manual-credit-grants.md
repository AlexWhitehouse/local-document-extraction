# Workspace Billing Ledger With Manual Credit Grants

Category: enhancement
Type: AFK
Status: completed

## Parent

.scratch/workspace-billing/PRD.md

## What to build

Add the per-Workspace billing Durable Object from ADR 0003 and prove the ledger with manual, no-Stripe Credit grants. An Application admin should be able to grant Goodwill Credits to a Workspace, revoke unspent manual grants, and write an Application admin billing audit entry. A Workspace owner should see the resulting Credit balance and Owner billing activity on the Billing page.

This slice establishes the append-only Billing ledger, rebuildable balance/activity summaries, D1 billing control records needed to route to the ledger, and the minimal owner/admin UI/API path for manual Credit grants.

## Agent Brief

**Category:** enhancement
**Summary:** Add the Workspace billing Durable Object ledger and manual Goodwill Credit grant/revoke flow without Stripe.

**Current behavior:**
The first Workspace billing slice is complete. Workspaces resolve to the Free Active entitlement by default, Workspace owners can read a session-only billing summary, and the frontend has an owner-only Billing page showing zero Credits, current-period page capacity, plan limits, and no payment controls. There is not yet a separate per-Workspace Billing ledger, no ledger-backed Credit balance or Owner billing activity projection, no D1 billing control/audit records for manual commercial actions, and no Application admin billing flow for granting or revoking Goodwill Credits.

**Desired behavior:**
Workspace billing should have its own per-Workspace Durable Object, following ADR 0003, as the authoritative append-only Billing ledger. The ledger should support manual Goodwill Credit grants and revocations, rebuild Credit balances and Owner billing activity from ledger entries, and expose summaries through the existing owner-facing Billing page path. Application admins should be able to grant Goodwill Credits to a Workspace with a reason and revoke only unspent manual grants. Each manual grant or revocation should write an Application admin billing audit log entry with actor, timestamp, reason, before/after values, and affected Workspace. Workspace owners should see updated available Credits and customer-facing Owner billing activity; non-owners should not see owner billing activity or grant controls.

**Key interfaces:**
- Workspace billing Durable Object binding and class — a separate per-Workspace authority with lazy SQLite schema initialization for the Billing ledger.
- Billing ledger entry model — append-only entries for Goodwill Credit grants, Goodwill Credit revocations, and any rebuildable summary/activity data needed for this slice.
- Ledger RPC surface — operations for granting Goodwill Credits, revoking unspent Goodwill Credit grants idempotently, summarizing Credit balances, and listing Owner billing activity.
- Billing control store over D1 — records needed to route Workspace billing requests to the ledger plus Application admin billing audit log entries.
- Owner-facing billing summary contract — include ledger-derived available Credits and Owner billing activity while preserving the existing session-only Workspace billing authority rules.
- Application admin billing API/UI surface — allow Application admins to find a Workspace billing record, grant Goodwill Credits with a reason, and revoke only eligible unspent Goodwill Credit grants.
