# Enterprise Ramp-Up Billing

Category: enhancement
Type: AFK
Status: completed

## Parent

.scratch/workspace-billing/PRD.md

## What to build

Add Application-admin-assigned Enterprise ramp-up billing. Enterprise ramp-up should use the Enterprise limit profile, not prepaid Credits, and record Enterprise usage charges for accepted submissions. Application admins set ramp-up duration in months, defaulting to 3, and an Enterprise billing cycle start date. At each invoice period close, the app generates a ramp-up usage invoice from Billing ledger usage using tiered usage slices.

## Acceptance criteria

- [ ] Application admins can assign Enterprise ramp-up deal terms with duration in months, default 3, billing cycle start date, collection method, and reason.
- [ ] Enterprise ramp-up uses Enterprise limit profile and does not use prepaid Credits.
- [ ] Enterprise ramp-up has no standard hard monthly Plan page limit.
- [ ] Accepted Enterprise ramp-up submissions record Enterprise usage charge entries before Source file storage and job creation.
- [ ] Enterprise usage charge entries include the same submission metadata as Credit reservations.
- [ ] Enterprise ramp-up usage bands are tiered by slice: 0-10,000 at £0.14, 10,001-20,000 at £0.13, 20,001-40,000 at £0.12, 40,001-60,000 at £0.11, 60,001+ at £0.10.
- [ ] Ramp-up invoice periods align to the Enterprise billing cycle start date.
- [ ] Ramp-up invoices are generated automatically after each monthly invoice period closes from Billing ledger usage.
- [ ] Ramp-up invoices use explicit Stripe invoice items derived from usage and tiered pricing.
- [ ] Ramp-up invoices finalize automatically unless Enterprise invoice review mode is enabled.
- [ ] Ramp-up invoices are visible and payable by the Workspace owner.
- [ ] Overdue ramp-up invoices suspend Enterprise entitlement until paid.
- [ ] Suspended or expired ramp-up falls back to active self-service subscription entitlement if one exists, otherwise Free.
- [ ] Tests cover ramp-up assignment, entitlement precedence, usage entries, tiered pricing, invoice generation, review mode, overdue suspension, fallback, and owner/admin UI.
- [ ] `npm run typecheck --prefix backend` and `npm run build --prefix frontend` pass.

## Agent Brief

**Category:** enhancement
**Summary:** Add Application-admin-assigned Enterprise ramp-up billing with usage-based monthly invoicing.

**Current behavior:**
Workspace billing supports the code-owned Free, Pro, and Max plan catalog, owner-only Billing page summaries, prepaid Credit reservations, Plan page limit enforcement, Stripe-backed Credit packs and subscriptions, subscription changes/cancellation, unpaid state handling, Application admin Plan overrides, payment-required override invoices, No-billing mode, and Application admin billing audit logging.

No-billing mode already provides the Enterprise limit profile without Credits, invoices, or usage charges, and Document submission can record a non-credit ledger entry before Source file storage and Extraction job creation. There is not yet an Enterprise ramp-up deal model, Enterprise entitlement state, Enterprise usage charge ledger entry, ramp-up usage-band pricing, automatic ramp-up invoice generation, Enterprise invoice review mode, or overdue Enterprise invoice suspension.

**Desired behavior:**
Application admins should be able to assign Enterprise ramp-up deal terms to a Workspace. The terms must include ramp-up duration in months with a default of 3, Enterprise billing cycle start date, invoice collection method, optional invoice review mode, and a required reason. Active Enterprise ramp-up should use the Enterprise limit profile, not prepaid Credits, and should have no standard hard monthly Plan page limit.

When a Document submission is accepted under active Enterprise ramp-up, the Billing ledger must record an Enterprise usage charge entry before Source file storage and Extraction job creation. The entry should include the same submission metadata as Credit reservations: Workspace, Extraction job, Template, Template version, Billable Document page count, submission time, auth mode, actor when available, and an internal idempotency key. Enterprise usage and invoice ledger entries should record rates and monetary amounts needed to reproduce invoice generation.

Ramp-up invoice periods should align to the configured Enterprise billing cycle start date. After each monthly invoice period closes, the system should generate an owner-visible Stripe invoice using explicit invoice items derived from Billing ledger Enterprise usage and tiered ramp-up usage bands. Pricing is slice-based per monthly period: pages 0-10,000 at GBP 0.14, 10,001-20,000 at GBP 0.13, 20,001-40,000 at GBP 0.12, 40,001-60,000 at GBP 0.11, and 60,001+ at GBP 0.10. Invoices should finalize automatically unless Enterprise invoice review mode is enabled.

Overdue ramp-up invoices should suspend Enterprise entitlement until paid. A suspended or expired ramp-up should fall back to active self-service subscription entitlement if one exists, otherwise Free. Active Enterprise ramp-up should supersede self-service subscription entitlement without spending Credits or double-billing.

**Key interfaces:**
- Active entitlement resolver - should support active Enterprise ramp-up between active Plan override and active self-service subscription according to existing precedence, while preserving No-billing mode above all billed entitlements.
- Workspace billing control data - should store Enterprise ramp-up deal terms, billing cycle start date, duration, collection mode, invoice review mode, status, suspension/expiry state, Stripe invoice references, Application admin actor, reason, timestamps, and audit-relevant before/after snapshots.
- Billing period logic - should compute Enterprise ramp-up invoice periods from the Enterprise billing cycle start date and determine when a monthly invoice period has closed.
- Billing ledger RPC surface - should support idempotent Enterprise usage charge entries with Document submission metadata and invoice-related ledger entries that preserve usage bands, rates, and amounts.
- Document submission billing authority - should choose Enterprise usage charge recording when Enterprise ramp-up is the Active entitlement, and it must do so before durable product side effects.
- Stripe billing gateway - should create explicit invoice items and invoices for ramp-up usage, support automatic or manual collection, expose hosted invoice payment URLs when needed, and use idempotency keys for Stripe writes.
- Stripe billing webhook processing - should update Enterprise ramp-up invoice status, activate or restore entitlement after payment when applicable, suspend entitlement on overdue/failed invoices, and handle duplicate events idempotently.
- Application admin billing API/UI - should let Application admins assign ramp-up terms, inspect current Enterprise status, review invoice status, and see audit history without mixing this with owner-only billing controls.
- Owner Billing page contract - should show Enterprise ramp-up entitlement, usage/invoice status, hosted payment action when applicable, and customer-facing Owner billing activity without exposing raw Stripe IDs or admin-only notes.
