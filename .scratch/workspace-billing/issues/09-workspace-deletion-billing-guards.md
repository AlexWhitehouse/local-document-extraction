## Agent Brief

**Category:** enhancement
**Summary:** Add billing-aware Workspace deletion guards so deletion stops future self-service billing, preserves required billing records, and never becomes a refund path.

**Current behavior:**
Workspace deletion is owner-only and already protects the "user must keep at least one accepted Workspace" invariant. Once policy approval passes, deletion cleans residual Source files, hard-erases Workspace product data, and removes Workspace control data.

Workspace billing now has Free/Pro/Max entitlements, Stripe Customer and subscription references, paid subscription activation, scheduled self-service cancellation/downgrade behavior, and Unpaid billing state from failed subscription invoices. However, the Workspace deletion path does not yet consult billing state, stop an active self-service subscription, deactivate billing entitlements before deletion, block deletion while unpaid billing debt exists, or retain a minimal non-cascading billing record after Workspace control data is removed. Existing billing control/audit rows are tied to the Workspace lifecycle, so they are not enough by themselves for post-deletion financial/audit/legal retention.

**Desired behavior:**
Deleting a Workspace should become a billing-aware operation. After normal Workspace deletion policy approval, the system should check Workspace billing state before product/control data erasure. If the Workspace has any unresolved unpaid billing invoice/deletion-blocking unpaid state, deletion should fail with a clear billing/payment-required error and leave product data, control data, billing state, Credits, and subscriptions unchanged.

If deletion is allowed and the Workspace has an active or scheduled self-service subscription, the backend should stop future self-service billing through Stripe before product/control data deletion completes. The Stripe operation must be configured so deletion does not refund unused paid time, unused Included Credits, Purchased Credits, Enterprise invoices, or other charges, and does not create proration/refund side effects. If Stripe cancellation/deactivation cannot be completed, deletion should fail before product/control data is erased.

Allowed deletion should deactivate local billing entitlements before Workspace control/product data deletion proceeds, so a deleted Workspace cannot keep active billing authority, API entitlement, scheduled plan changes, or owner billing controls. This should not mutate the append-only Billing ledger in a refund-like way: no Credit refund entries, no usage removal, and no reduction of historical Plan page usage should be recorded for Workspace deletion.

Before deleting Workspace control data, the backend should retain minimal billing records needed for financial, audit, and legal purposes in a non-cascading retention store. Retained records may reference the deleted Workspace ID, actor user ID, Stripe Customer/subscription/invoice/event identifiers, Billing ledger object name, final billing/deletion state, timestamps, and compact JSON snapshots needed to explain the deletion outcome. Retained records should avoid account emails, account names, Workspace names, or other identity/profile data beyond what Stripe or invoices already retain.

If active Enterprise deal metadata exists for the Workspace, deletion should not proceed as a normal owner self-service deletion. It should be blocked or routed to Application admin handling with a clear error. Do not build Enterprise assignment, ramp-up, annual commitment, or invoicing in this slice; implement the deletion guard against the current or newly introduced Enterprise control metadata shape and leave the broader Enterprise flows to the later Enterprise issues.

**Key interfaces:**
- Workspace deletion policy and route contract — remains session-only and owner-only, but gains billing preflight/deactivation before the existing cascade.
- Workspace billing control store — should expose deletion-safe reads of subscription, unpaid/deletion-blocking invoice state, scheduled entitlement state, Stripe Customer/subscription references, Enterprise-deal presence, and any retained billing record write path.
- Stripe billing gateway — should provide a deletion-specific way to stop future self-service subscription billing without refunds or proration side effects.
- Billing ledger authority — should remain append-only; Workspace deletion must not call refund/correction operations or remove historical Credit reservation / Plan page usage entries.
- Retained billing records — a D1-backed retention model without a cascading Workspace foreign key, storing only minimal references and snapshots needed after the Workspace row is deleted.
- Workspace deletion cascade — should still hard-erase Workspace product data and Source files before final control-data removal once billing preflight/deactivation/retention has succeeded.

**Acceptance criteria:**
- [x] Workspace deletion by an owner is blocked while the Workspace has unresolved unpaid billing invoices or an equivalent deletion-blocking Unpaid billing state.
- [x] A blocked billing deletion returns a clear error and does not erase product data, delete Source files, delete Workspace control data, cancel subscriptions, deactivate entitlements, or write retained deletion records as though deletion completed.
- [x] Allowed deletion for an active self-service subscription stops future Stripe subscription billing before Workspace product/control data deletion completes.
- [x] Allowed deletion deactivates local self-service billing entitlement, scheduled entitlement changes, owner billing controls, and API entitlement before Workspace control data is removed.
- [x] If Stripe subscription cancellation/deactivation fails, Workspace deletion fails before Workspace product/control data is erased.
- [x] Workspace deletion does not refund Credits, subscription payments, Enterprise invoices, or other billing charges.
- [x] Workspace deletion does not create Billing ledger Credit refund/correction entries and does not reduce historical Plan page usage.
- [x] Minimal retained billing records survive Workspace control-data deletion and can reference the deleted Workspace ID, actor user ID, Stripe IDs, Billing ledger object name, final billing/deletion state, and timestamps.
- [x] Retained billing records do not store account emails, account names, Workspace names, or other avoidable identity/profile fields beyond Stripe/invoice references.
- [x] Workspaces with active Enterprise deal metadata are blocked from normal owner self-service deletion or clearly routed to Application admin handling.
- [x] Tests cover deletion with unpaid invoices/state, deletion with an active subscription and no unpaid invoices, Stripe failure before data erasure, no-refund/no-ledger-refund behavior, retained record shape, and Enterprise handling.
- [x] `npm run typecheck --prefix backend` passes.

**Out of scope:**
- Building Application admin Enterprise assignment, Enterprise ramp-up, Enterprise annual commitment, or Enterprise invoice generation.
- Refunding unused subscription time, Included Credits, Purchased Credits, Goodwill Credits, Enterprise invoices, or any other charge.
- Deleting or mutating historical Billing ledger entries.
- Reworking the existing Workspace deletion confirmation UX beyond handling the new backend error states.
- Replacing the existing Workspace product data and Source file deletion cascade except where necessary to sequence billing deactivation and retention safely.

## Implementation notes

- Added immediate Stripe subscription cancellation for deletion using no final invoice and no proration.
- Added local billing entitlement deactivation before deletion cascade.
- Added non-cascading retained billing records that keep minimal Workspace/actor/Stripe references and avoid account or Workspace identity fields.
- Preserved the append-only Billing ledger by avoiding refund or usage-correction calls during Workspace deletion.
