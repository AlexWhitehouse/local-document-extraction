## Agent Brief

**Category:** enhancement
**Summary:** Add app-owned non-enterprise subscription changes, scheduled cancellation/downgrade behavior, Unpaid billing state, and API access suspension.

**Current behavior:**
Workspace billing already has a Free entitlement foundation, a Billing ledger for Credits and Plan page usage, owner-only Billing page access, Credit pack Checkout, signed/idempotent Stripe billing event processing, and first-time Pro/Max subscription starts through Stripe Checkout. A paid first subscription invoice can activate Pro or Max entitlement and grant the plan's Included Credits for the paid Billing period.

The remaining gap is ongoing subscription lifecycle management after a Workspace is already on a paid self-service plan. The application does not yet own Pro -> Max upgrades, Max -> Pro or paid -> Free downgrades, subscription cancellation, failed renewal payment handling, or the resulting API access behavior.

**Desired behavior:**
Self-service plan changes must be initiated through the application so product rules, proration intent, payment gates, scheduled entitlement changes, and owner-facing Billing page state remain application-owned. Stripe Customer Portal may still be used for payment method updates or other supported hosted flows, but it must not expose unrestricted plan switching that bypasses the application.

A Pro Workspace owner can start a Pro -> Max Plan upgrade. The upgrade creates a prorated invoice or equivalent Stripe-hosted payment path for the remaining Billing period. Max entitlement, Max Plan page limit, Max API access, and additional Included Credits activate only after successful payment. The Included Credit grant should only top the current Billing period up to the Max allowance, not grant a second full plan allowance. Existing current-period Billable Document page usage carries forward and is evaluated against the Max Plan page limit after payment, so a Pro Workspace blocked at its current Plan page limit can upgrade and continue after the upgrade is paid.

Max -> Pro and paid -> Free Plan downgrades should be scheduled for the next Billing period rather than applied immediately. Subscription cancellation should schedule a downgrade to Free at the next Billing period, preserve already-paid access until that point, preserve Purchased Credits, and not refund unused paid time or unused Included Credits. After a paid subscription ends, future Free Billing periods should keep the latest Stripe Billing period anchor so period boundaries do not jump unexpectedly.

Failed renewal payment events should create or preserve Unpaid billing state. While Unpaid, the Workspace receives no new Included Credits, operates under Free plan limits for new actions, and has inactive API access entitlement. Existing Workspace product data, memberships, and Workspace API keys are preserved. Workspace API key product requests should be rejected with entitlement errors, not invalid-credential errors, until entitlement returns. Buying Credit packs while Unpaid is allowed, but Purchased Credits do not restore paid subscription entitlement or API access.

When a later successful payment resolves the Unpaid state, the Workspace should restore the paid self-service entitlement for the paid Billing period and grant Included Credits idempotently for that period according to the active paid plan and any already-granted allowance.

**Key interfaces:**
- Non-enterprise plan catalog and entitlement resolver — should represent active paid entitlement, scheduled next entitlement, Unpaid billing state, Free fallback limits, API access entitlement, and Billing period anchors.
- Workspace billing control data — should persist Stripe subscription references, subscription status, paid Billing period dates, scheduled Plan downgrade/cancellation state, Unpaid state, and the latest Stripe Billing period anchor needed for later Free periods.
- Stripe billing gateway and webhook processor — should support app-owned subscription updates, prorated upgrade payment paths, subscription update/deletion events, invoice payment failure, invoice payment recovery, idempotent event processing, and Stripe write idempotency keys.
- Billing ledger — should grant Included Credits idempotently for paid periods, grant only additional Included Credits needed during Pro -> Max upgrades, preserve Purchased Credits across downgrades/cancellation/Unpaid state, and keep current-period page usage intact.
- Product access enforcement — should apply Free limits while Unpaid, enforce Plan limit overage consistently for session and Workspace API key requests, and reject Workspace API key product requests with entitlement errors when API access is inactive.
- Owner Billing page/controller — should show active subscription state, Unpaid state, scheduled downgrade/cancellation, available Credits, current-period page capacity, subscription change/cancellation actions, and post-Checkout/payment refresh behavior without exposing unrestricted Customer Portal plan switching.
