# Show and stop impersonation mode

Category: enhancement
Status: completed

## Parent

## What to build

Show a persistent main-layout impersonation indicator whenever Better Auth's session response indicates impersonation. The indicator should name the current impersonated user, avoid showing Better Auth user IDs, and provide an immediate Stop impersonating action that restores the Application admin session safely.

- [x] Impersonation state is read from Better Auth's session response rather than a custom product session endpoint.
- [x] During impersonation, the main layout shows a persistent indicator naming the current impersonated user.

- [x] Stop impersonating is immediate and does not require confirmation.
- [x] Stopping impersonation calls Better Auth's stop-impersonating utility, clears session-scoped Workspace, Template, and Document UI state, refetches the session, and returns the restored Application admin to the Admin page.
- [x] Stop impersonating uses loading/disabled state while in flight and Action toasts for success/failure.
- [x] Focused frontend coverage verifies indicator visibility/content, no user ID display, immediate stop behavior, state clearing, session refetch, and return-to-Admin navigation.

## Agent Brief

**Category:** enhancement
**Summary:** Show persistent impersonation mode in the main layout and let an Application admin stop impersonating safely.

**Current behavior:**
Application admins can start impersonating eligible regular users from the Application admin page. Starting impersonation uses Better Auth admin client utilities, clears session-scoped Workspace, Template, and Document UI state, refetches the authenticated session, and moves the SPA to the Workspace page.

The SPA does not yet show a persistent main-layout impersonation indicator after Better Auth reports that the current session is impersonating another user. There is also no visible Stop impersonating action that restores the original Application admin session from the main layout.

**Desired behavior:**
When Better Auth's session response indicates impersonation, the authenticated main layout should show a persistent impersonation indicator. The indicator should name the current impersonated user using user-facing account information, such as email or display name, and must not show the original admin's Better Auth user ID.

The indicator should include an immediate Stop impersonating action. The action should not require confirmation. While the stop request is in flight, the control should use loading or disabled state so it cannot be submitted repeatedly.

After stopping impersonation succeeds, the frontend should clear session-scoped Workspace, Template, and Document UI state, refetch the authenticated session, and return the restored Application admin to the Application admin page. Success and failure should use existing Action toast behavior. Failure should be recoverable and should not leave the UI pretending impersonation has stopped if the Better Auth request failed.

**Key interfaces:**
- Better Auth session response — impersonation state must be read from the existing session data returned by Better Auth, not from a custom product session endpoint.
- Existing runtime auth client — use Better Auth's admin client stop-impersonating utility through the existing configured auth client; do not add custom product `/v1/admin/*` routes.
- Main authenticated layout — provide a persistent, visible impersonation indicator outside the Application admin page itself so it remains visible while the impersonated user is on Workspace, Template, or Document pages.
- Session-scoped UI clearing — stopping impersonation should clear Workspace, Template, and Document browser state before restoring the Application admin page experience.
- Auth session refresh — refetch the Better Auth session after stopping impersonation so the SPA uses the restored admin session consistently.
- Action toast system — report stop-impersonating success and failure using the existing Action toast pattern.

**Acceptance criteria:**
- [ ] Impersonation state is read from Better Auth's session response rather than a custom product session endpoint.
- [ ] During impersonation, the main layout shows a persistent indicator naming the current impersonated user.
- [ ] The impersonation indicator does not show the original admin's Better Auth user ID.
- [ ] Stop impersonating is immediate and does not require confirmation.
- [ ] Stopping impersonation calls Better Auth's stop-impersonating utility.
- [ ] Successful stop clears session-scoped Workspace, Template, and Document UI state.
- [ ] Successful stop refetches the authenticated session.
- [ ] Successful stop returns the restored Application admin to the Application admin page.
- [ ] Stop impersonating uses loading or disabled state while in flight.
- [ ] Stop impersonating success and failure use Action toasts.
- [ ] Failed stop is recoverable and does not incorrectly navigate away or clear the visible impersonation state as if it succeeded.
- [ ] Focused frontend coverage verifies indicator visibility/content, no original admin user ID display, immediate stop behavior, state clearing, session refetch, success navigation to the Application admin page, and failure feedback.

**Out of scope:**
- Changing who can start impersonation.
- Adding admin-to-admin impersonation.
- Adding custom product `/v1/admin/*` routes.
- Adding custom admin audit logging.
- Showing Workspace membership summaries or Workspace data management on the Application admin page.
- Deleting users, creating users, setting passwords, or manually revoking sessions.
