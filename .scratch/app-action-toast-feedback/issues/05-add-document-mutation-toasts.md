# Add Document Mutation Toasts

Category: enhancement
Status: completed

## Parent

.scratch/app-action-toast-feedback/PRD.md

## What to build

Add toast feedback to explicit document mutation actions: upload/queue, retry, and delete. Single-document queue and retry actions should confirm that work was queued, not that extraction completed. Multi-file upload should produce one aggregate toast after the queue batch finishes, while per-file details remain inline and in the activity log.

Polling-based extraction completion and failure should remain toast-free. Document deletion should keep its confirmation behavior, remain silent when cancelled, and treat already-removed cleanup as a success-style outcome.

## Acceptance criteria

- [x] Single-document upload/queue shows success, validation-blocker, and friendly failure toasts.
- [x] Multi-file upload produces one aggregate toast for all-success, mixed-success, and all-failure outcomes.
- [x] Per-file upload status rows and activity-log details remain available.
- [x] Retrying a failed document shows queued, validation-blocker, and friendly failure toasts.
- [x] Deleting a document shows success and failure toasts.
- [x] A delete 404 that removes the document from local state shows a success-style “already removed” toast.
- [x] Cancelling the delete confirmation produces no toast.
- [x] Polling-based extraction completion and failure do not produce toasts.
- [x] Background document refresh/polling remains toast-free.

## Agent Brief

**Category:** enhancement
**Summary:** Add toast feedback for explicit document upload, retry, and deletion mutations.

**Current behavior:**
Document mutation actions primarily update inline rows and the activity log. Single-document upload/queue, multi-file upload batches, retry, and delete do not consistently produce immediate visible toast feedback. Polling and document status UI already provide ongoing extraction state and should remain the source of truth for background completion or failure.

**Desired behavior:**
Explicit document mutations should use centralized Sonner toast feedback. Upload/queue should show validation blockers and friendly failures, and successful queueing should confirm that work was queued rather than completed. Multi-file upload should emit one aggregate toast after the batch finishes for all-success, mixed-success, and all-failure outcomes while preserving per-file inline status rows and activity-log details. Retry should show queued, validation-blocker, and friendly failure toasts. Delete should show success and failure toasts, stay silent when the confirmation is cancelled, and treat a delete 404 that cleans up local state as a success-style already-removed outcome. Polling-based completion/failure and background refresh/polling should stay toast-free.

**Key interfaces:**

- Toast notification module - should supply document mutation notification message/severity and aggregate upload copy.
- Document upload action handlers - should emit one aggregate batch toast after queue attempts finish.
- Document retry action handler - should emit toasts only for explicit retry outcomes.
- Document deletion action handler - should distinguish successful deletion, already-removed cleanup, failure, and cancelled confirmation.
- Document polling/status paths - should remain toast-free.

**Acceptance criteria:**

- [x] Single-document upload/queue shows success, validation-blocker, and friendly failure toasts.
- [x] Multi-file upload produces one aggregate toast for all-success, mixed-success, and all-failure outcomes.
- [x] Per-file upload status rows and activity-log details remain available.
- [x] Retrying a failed document shows queued, validation-blocker, and friendly failure toasts.
- [x] Deleting a document shows success and failure toasts.
- [x] A delete 404 that removes the document from local state shows a success-style “already removed” toast.
- [x] Cancelling the delete confirmation produces no toast.
- [x] Polling-based extraction completion and failure do not produce toasts.

- [x] Focused frontend verification passes for the changed notification behavior.

**Out of scope:**

- Adding polling-based extraction completion or failure toasts.
- Toasting background document refresh, list, or poll failures.
- Changing document API contracts or queue behavior.
- Changing Sonner global configuration, placement, duration, theme, or styling.
