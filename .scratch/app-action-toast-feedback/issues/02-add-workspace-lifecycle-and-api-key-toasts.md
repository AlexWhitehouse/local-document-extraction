# Add Workspace Lifecycle And API Key Toasts

Category: enhancement
Status: completed

## Parent

.scratch/app-action-toast-feedback/PRD.md

## What to build

Add Sonner toast feedback to explicit **Workspace** lifecycle and credential actions: API key rotation, workspace creation, workspace rename, **Leave Workspace**, and workspace deletion. The behavior should confirm terminal success, report validation/guard blockers, and show friendly failure messages while preserving existing activity-log detail.

Silent operations and cancelled browser confirmations should stay quiet. API key toasts must never expose key material. Leave-workspace success should mention replacement personal **Workspace** creation when that edge case occurs.

## Acceptance criteria

- [x] Rotating a workspace API key shows success and failure toasts without exposing any key material.
- [x] Creating a **Workspace** shows success and failure toasts unless the action is explicitly silent.
- [x] Renaming a **Workspace** shows success and failure toasts while preserving the existing disabled save behavior when the name is unchanged.
- [x] **Leave Workspace** shows success and failure toasts, including replacement personal **Workspace** wording when applicable.
- [x] Deleting a **Workspace** shows success and failure toasts.
- [x] Cancelling leave/delete confirmations produces no toast.
- [x] Background workspace listing/refresh remains toast-free.
- [x] Existing activity-log messages remain available for diagnostic detail.

## Agent Brief

**Category:** enhancement
**Summary:** Add Sonner toast feedback for Workspace lifecycle and API key actions.

**Current behavior:**
Signed-in Workspace lifecycle and credential actions primarily write to the activity log. Users do not consistently receive immediate visible feedback after rotating an API key, creating a Workspace, renaming a Workspace, leaving a Workspace, or deleting a Workspace. The shared toast-notification module already exists and should be used rather than scattering ad hoc copy.

**Desired behavior:**
Explicit Workspace lifecycle and credential actions should show centralized Sonner toast feedback for terminal success, validation or guard blockers, and friendly failures. Activity-log messages should remain available for diagnostic detail. Silent operations, background Workspace listing or refresh, and cancelled browser confirmations should not toast. API key toast copy must never include key material. Leave Workspace success should mention replacement personal Workspace creation when the action result indicates that edge case occurred.

**Key interfaces:**

- Toast notification module - should provide the success, validation, and failure message/severity that action handlers pass to Sonner.
- Workspace lifecycle action handlers - should call the notification seam for explicit create, rename, leave, delete, and API key rotate outcomes.
- Workspace context transition helpers - should continue to drive context changes and should not be replaced with toast-specific branching.

**Acceptance criteria:**

- [x] Rotating a Workspace API key shows success and failure toasts without exposing any key material.
- [x] Creating a Workspace shows success and failure toasts unless the action is explicitly silent.
- [x] Renaming a Workspace shows success and failure toasts while preserving disabled save behavior when the name is unchanged.
- [x] Leave Workspace shows success and failure toasts, including replacement personal Workspace wording when applicable.
- [x] Deleting a Workspace shows success and failure toasts.
- [x] Cancelling leave or delete confirmations produces no toast.
- [x] Background Workspace listing and refresh remain toast-free.
- [x] Existing activity-log messages remain available for diagnostic detail.
- [x] Focused frontend verification passes for the changed notification behavior.

**Out of scope:**

- Changing Sonner global configuration, placement, duration, theme, or styling.
- Adding loading toasts.
- Changing backend API contracts or database schema.
- Toasting passive background refresh/list failures.
