## What to build

Build the shared toast-notification seam for app action feedback. The module should provide a small, testable interface for action-specific success, validation, and failure notification copy so signed-in app handlers can use consistent Sonner messages without scattering ad hoc strings.

This slice should prove the notification rules through focused unit tests, including friendly failure copy, target display names, no API key material in notifications, **Workspace invitation** terminology, **Workspace member action** terminology, and aggregate document upload messages.

## Agent Brief

**Category:** enhancement
**Summary:** Establish a shared toast-notification module for signed-in app action feedback.

**Current behavior:**
The app uses Sonner toasts for auth error feedback, but signed-in action feedback does not yet have a shared notification-copy seam. Upcoming workspace, template, **Workspace invitation**, **Workspace member action**, document, and clipboard toast work would otherwise need to scatter user-facing copy and severity decisions across action handlers.

**Desired behavior:**
Create a focused toast-notification module that exposes a small public interface for action-specific notification messages and severity. The module should centralize success, validation, and failure copy for explicit signed-in user actions while preserving the agreed product rules: no API key material in notifications, friendly failure copy instead of raw backend errors, human-readable targets where available, domain-accurate **Workspace invitation** and **Workspace member action** wording, and aggregate upload feedback.

**Key interfaces:**

- Toast notification message interface — should represent the notification severity and message text that app action handlers can pass to Sonner.
- Action-specific notification helpers — should cover workspace, template, **Workspace invitation**, **Workspace member action**, document, and clipboard actions.
- Upload aggregate helper — should produce concise copy for all-success, mixed-success, and all-failure document upload batches.

**Acceptance criteria:**

- [x] A toast-notification module exists with a small public interface for action-specific notification messages and severity.
- [x] The module supports success, validation, and failure messages for workspace, template, **Workspace invitation**, **Workspace member action**, document, and clipboard actions.
- [x] API key notification messages never include API key material.
- [x] Success messages can include human-readable target names or emails when available and fall back safely when unavailable.
- [x] Failure messages are concise and user-friendly, leaving raw backend error detail for the activity log.
- [x] Aggregate document upload messages cover all-success, mixed-success, and all-failure batch outcomes.
- [x] Unit tests cover representative notification rules without coupling to private implementation details.
- [x] Frontend tests pass.

**Out of scope:**

- Wiring the module into signed-in app action handlers.
- Changing Sonner global configuration, placement, duration, or styling.
- Adding loading toasts.
- Toasting background refresh, listing, or polling behavior.
- Changing backend API contracts or database schema.
