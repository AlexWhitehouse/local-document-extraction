# Add Template Action Toasts And Dirty-State Saving

Category: enhancement
Status: completed

## Parent

.scratch/app-action-toast-feedback/PRD.md

## What to build

Add toast feedback across template actions: template create, update, delete, template JSON save/import validation, successful JSON save, and template JSON clipboard copy. Add edited-template dirty-state tracking so saving an existing template is disabled until the loaded template has changed. Add a confirmation prompt before template deletion.

Template field add, delete, duplicate, reorder, and edit operations should remain draft-only and toast-free until the template is persisted. Detailed template JSON validation errors should remain inline while a short toast makes the blocked save visible.

## Acceptance criteria

- [x] Creating a template shows success, validation-blocker, and friendly failure toasts.
- [x] Updating an existing template shows success, validation-blocker, and friendly failure toasts.
- [x] The edited-template save button is disabled until the loaded template has changed.
- [x] Creating a new template remains enabled when API access exists and uses validation toasts for invalid drafts.
- [x] Local template field draft edits do not produce toasts before persistence.
- [x] Deleting a template requires confirmation, shows success/failure toasts, and stays silent when confirmation is cancelled.
- [x] Invalid template JSON save attempts keep detailed inline errors and also show a short error toast.
- [x] Successful template JSON saves show a success toast.
- [x] Copying template JSON to the clipboard shows success and failure toasts.
- [x] Existing activity-log and inline JSON error behavior are preserved.

## Agent Brief

**Category:** enhancement
**Summary:** Add toast feedback for template persistence, JSON, clipboard, and deletion actions, plus edited-template dirty-state saving.

**Current behavior:**
Template actions primarily update inline state and the activity log. Template persistence, template JSON save/import validation, JSON copy, and deletion do not consistently produce visible toast feedback. Existing template deletion does not require confirmation. Editing an existing template can submit a no-op save even when the loaded template has not changed.

**Desired behavior:**
Template create, update, delete, template JSON save/import, and template JSON clipboard copy should use centralized Sonner toast feedback for success, validation blockers, and friendly failures. Detailed template JSON validation errors should remain inline. Template field draft edits should remain toast-free until persisted. Deleting a template should require browser confirmation and should remain silent when cancelled. Existing-template save should be disabled until the loaded template draft differs from the last loaded or saved template state; new-template save should remain enabled when API access exists and rely on validation toasts for invalid drafts.

**Key interfaces:**

- Toast notification module - should supply template and clipboard notification message/severity for handlers.
- Template editor draft state - should track whether the current existing-template draft differs from the loaded or saved template payload.
- Template JSON validation path - should keep inline error detail while also emitting a concise blocked-save toast.
- Template deletion action - should preserve destructive-action safeguards through confirmation before request execution.

**Acceptance criteria:**

- [x] Creating a template shows success, validation-blocker, and friendly failure toasts.
- [x] Updating an existing template shows success, validation-blocker, and friendly failure toasts.
- [x] The edited-template save button is disabled until the loaded template has changed.
- [x] Creating a new template remains enabled when API access exists and uses validation toasts for invalid drafts.
- [x] Local template field draft edits do not produce toasts before persistence.
- [x] Deleting a template requires confirmation, shows success/failure toasts, and stays silent when confirmation is cancelled.
- [x] Invalid template JSON save attempts keep detailed inline errors and also show a short error toast.
- [x] Successful template JSON saves show a success toast.
- [x] Copying template JSON to the clipboard shows success and failure toasts.
- [x] Existing activity-log and inline JSON error behavior are preserved.
- [x] Focused frontend verification passes for the changed notification and dirty-state behavior.

**Out of scope:**

- Replacing browser confirmations with custom modal dialogs.
- Toasting local template field add, remove, duplicate, reorder, or typing edits before persistence.
- Changing template API contracts or database schema.
- Changing Sonner global configuration, placement, duration, theme, or styling.
