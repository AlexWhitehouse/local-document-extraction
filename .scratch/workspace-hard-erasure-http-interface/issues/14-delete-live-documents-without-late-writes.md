# Delete Queued And Processing Documents Without Late Writes

## What to build

Extend Document deletion to queued and processing **Extraction jobs**. The deletion action must coordinate with queue delivery, retry scheduling, and active Model gateway processing so job state, Extraction results, Source files, analytics, or live updates cannot reappear after the Document has been removed.

Use the Workspace operation and cancellation behavior established for Workspace deletion rather than creating a second unrelated concurrency mechanism.

## Acceptance criteria

- [ ] A queued Document can be deleted before claim and cannot be claimed by a later queue delivery.
- [ ] A processing Document can be deleted after active extraction is cancelled or drained.
- [ ] Document deletion does not return success while active processing can still persist lifecycle state.
- [ ] Late completion, failure, retry, queue delivery, or cleanup callbacks cannot recreate the deleted Extraction job or results.
- [ ] The Source file and Source-file metadata are removed after deletion succeeds.
- [ ] No misleading product analytics or Workspace live update is emitted for a lifecycle transition that was suppressed by deletion.
- [ ] Deleting one live Document does not block unrelated Extraction processing in the same or another Workspace beyond required local coordination.
- [ ] The frontend removes the Document and does not reinsert it when a stale live update arrives.
- [ ] Contract-oriented concurrency tests exercise queued and processing deletion through public Document and runner Interfaces.
- [ ] Existing active-job completion and retry behavior remains unchanged when no deletion occurs.
- [ ] Focused lifecycle, queue, Document deletion, live-update, and build checks pass.

## Agent Brief

**Category:** enhancement
**Summary:** Extend Document deletion across queued and processing lifecycle states using job-scoped cancellation built into the existing Workspace operation coordinator.

**Current behavior:**
The terminal-only delete path rejects queued/processing jobs. The extraction runner has only a workspace-wide cancellation signal, so a document-specific deletion could race a late claim, completion, failure, retry, analytics event, or lifecycle update.

**Desired behavior:**
Document deletion closes and aborts only the target job through `LocalWorkspaceProductOperations`, waits for active target processing to drain, then removes product/source data. Late runner deliveries discover the missing job or deletion gate and produce no state, retry, analytics, or live update. Unrelated jobs remain free to run.

**Key interfaces:**
- `LocalWorkspaceProductOperations` — adds job-scoped operation admission, cancellation, and drain behavior alongside existing workspace hard-deletion coordination.
- `LocalExtractionRunner` — acquires a job-scoped operation and treats its abort/missing claim as a silent stop before every durable side effect.
- Document delete handler/product store — begins the target-job deletion gate, waits for processing, hard-removes the job, then completes/fails the gate safely.
- Document controller — records locally removed IDs so stale lifecycle messages cannot reinsert them.

**Acceptance criteria:**
- [ ] Queued and processing Documents delete through the public interface; processing is aborted and drained before success.
- [ ] Late claim/completion/failure/retry/cleanup events create no job, results, analytics, or lifecycle updates after deletion.
- [ ] Source binary/metadata are removed; unrelated jobs can continue; no-delete runner behavior remains unchanged.
- [ ] Stale live events do not restore locally deleted Documents.
- [ ] Contract-oriented concurrency coverage and focused lifecycle/frontend/build checks pass.

**Out of scope:**
- New global queue infrastructure, workspace hard deletion changes, or a user-facing cancellation state.
- Job search/pagination behavior, addressed in later issues.

## Completion

Extended the existing Workspace operation coordinator with job-scoped cancellation/drain gates, then used it for queued and processing Document deletion. The runner now silently stops late target work before durable side effects, while unrelated jobs continue. Added concurrency, stale-live-message, and queue-delivery coverage; full backend/frontend tests, lint, backend typecheck, and frontend production build passed.
