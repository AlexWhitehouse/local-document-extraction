## Agent Brief

**Category:** bug
**Summary:** Remove unsupported profile-route dependencies and use the authenticated Better Auth client/session directly.

**Current behavior:**
The profile controller issues `GET` and `PATCH` requests to `/v1/profile`, but the backend exposes no such route. Tests mock that nonexistent HTTP behavior even though profile identity is already available in the authenticated session.

**Desired behavior:**
Profile name and email are derived from the resolved Better Auth session. Saving a non-empty changed name calls `authClient.updateUser({ name })`, handles the returned error shape, refreshes the session, and preserves current menu/feedback behavior. Email remains read-only and no custom profile route is added.

**Key interfaces:**
- `useAuthProfileController` — consumes session identity and Better Auth client outcomes; it does not construct generic profile-route requests.
- Better Auth client `updateUser()` — performs the authenticated name update; a successful mutation is followed by session refresh.
- Better Auth Fetch handler — remains the real backend seam for profile mutation.

**Acceptance criteria:**
- [ ] No frontend profile code or tests construct or mock `/v1/profile`.
- [ ] Signed-in profile identity comes from the resolved session, and a changed non-empty name uses `authClient.updateUser({ name })`.
- [ ] Success refreshes session and displays updated session identity; failure and empty-name behavior remain recoverable and visible.
- [ ] Account email remains read-only and no custom backend profile route exists.
- [ ] A real Better Auth handler test verifies the profile-name mutation/session path.
- [ ] Focused auth/profile tests and frontend build pass.

**Out of scope:**
- Email-change, password-change, account deletion, or extra profile fields.
- Changes to Workspace access, document behavior, or the generic transport runtime.

## Completion
