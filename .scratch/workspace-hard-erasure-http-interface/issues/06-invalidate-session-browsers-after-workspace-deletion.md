# Invalidate Session Browsers After Workspace Deletion

Status: completed
Category: bug
Type: AFK
User stories covered: 14-16

## Parent

## What to build

Notify every connected session browser when its accepted Workspace is deleted. The backend should emit a Workspace context invalidation for access change after control-data revocation, and the frontend should revalidate through HTTP, clear Workspace-scoped Template and Document state, and select another accepted Workspace where available.

The requesting browser's existing deletion transition and another member's live invalidation path should converge on the same valid Accepted workspace context behavior.

## Acceptance criteria

- [ ] Workspace deletion emits a versioned Workspace context invalidation with the access-change reason after Workspace access is revoked.
- [ ] The invalidation contains no account identity, Workspace API key, Source-file content, Extraction results, or Document content.
- [ ] A connected browser revalidates the selected Accepted workspace context over HTTP when it receives the invalidation.
- [ ] Forbidden revalidation blocks useful live-update effects until access recovery finishes.
- [ ] The browser clears visible Template, Document, completed-cache, and one-time Workspace API key state for the deleted Workspace.
- [ ] The browser selects another accepted Workspace returned by the backend without inventing a fallback Workspace ID.
- [ ] The deleting browser preserves its current success transition and does not perform duplicate user-visible cleanup.
- [ ] Tests cover a second connected session losing access through the live update and arriving at a valid replacement Workspace context.
- [ ] Focused live-update, Workspace controller, app integration, and build checks pass.

## Agent Brief

**Category:** bug
**Summary:** Emit and consume a privacy-safe Workspace-access live invalidation after successful deletion.

**Current behavior:**
The live-update protocol can parse Workspace context invalidations, but the backend does not emit one when deletion revokes access and the App does not connect document live-access revalidation to Workspace context recovery. A second connected browser can remain on stale Workspace state.

**Desired behavior:**
After control access is revoked during deletion, connected session browsers receive a versioned `workspace_context_invalidated` event with the `workspace_access` reason and no private payload. A non-deleting browser immediately revalidates over HTTP, clears Workspace-scoped state through the existing context transition, and selects a backend-provided accepted replacement. The deleting browser retains its established success transition without duplicate recovery feedback.

**Key interfaces:**
- `LocalLiveUpdateHub` — broadcasts a privacy-safe Workspace context invalidation to Workspace subscribers.
- `Workspace deletion` — emits access invalidation only after revocation and before final completion.
- `useDocumentController` and `useWorkspaceController` — connect access invalidation to one context revalidation while suppressing duplicate recovery during a locally initiated deletion.

**Acceptance criteria:**
- [ ] Deletion emits a versioned `workspace_context_invalidated` event with `workspace_access` and no identity, credential, source, result, or document payload.
- [ ] A second connected session revalidates via HTTP, clears Workspace-scoped state, and selects a returned accepted replacement.
- [ ] Live job effects remain suppressed until access revalidation settles.
- [ ] The deleting browser does not duplicate its existing cleanup or success feedback.
- [ ] Focused live-update/controller/app checks and build pass.

**Out of scope:**
- General live-update transport redesign, durable event history, and changes to non-deletion Workspace product invalidations.
- Profile, membership, document deletion, or job-listing feature work.

## Completion

Implemented privacy-safe Workspace access invalidation after revocation, connected it to browser Workspace recovery, and suppressed duplicate recovery during local deletion. Full backend/frontend tests, lint, backend typecheck, and frontend production build passed.
