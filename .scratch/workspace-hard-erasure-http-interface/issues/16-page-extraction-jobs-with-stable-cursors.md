## Agent Brief

**Category:** enhancement
**Summary:** Add opaque, search-bound cursor pages to the authoritative job collection without changing total-count semantics.

**Current behavior:**
The controller and Document adapter carry a cursor parameter, but the backend always returns the full matching collection with no next cursor. The UI's Load More state is therefore non-executable.

**Desired behavior:**
The product store returns bounded descending pages ordered by `(created_at DESC, job_id DESC)`. An opaque cursor captures the final tuple and normalized search criteria; invalid, tampered, or search-mismatched cursors receive a clear 400 outcome. `total` remains the unfiltered durable Workspace total, and append behavior avoids duplicates while retaining the current selection.

**Key interfaces:**
- `LocalWorkspaceProductStore` — receives decoded page boundaries and returns deterministic bounded job slices.
- Job collection handler — owns opaque cursor encode/decode/validation and creates the next cursor from the final row.
- Document request adapter/controller — forward cursor/search as opaque values, append de-duplicated pages, and preserve cache-pruning safeguards for partial lists.

**Acceptance criteria:**
- [ ] First/middle/final pages are bounded, deterministic, repeatable, and gap-free across equal timestamps.
- [ ] Cursor validation binds it to the active search and rejects invalid/tampered/mismatched values clearly.
- [ ] Search, Workspace isolation, and the independent total behave consistently across pages.
- [ ] The controller appends pages without duplicates while preserving selection and conservative cache behavior.
- [ ] Adapter-to-Fetch contracts plus focused product/controller/build checks pass.

**Out of scope:**
- Arbitrary sorting, offset pagination, and answer/evidence full-text search.
- New storage indexes unrelated to job collection traversal.

## Completion

Implemented bounded, creation-time/job-ID ordered job pages with HMAC-signed opaque cursors bound to normalized search criteria. Invalid or mismatched cursors return a domain 400; totals remain unfiltered and stable. Controller coverage verifies de-duplicated appends and selection retention, while Fetch contracts cover page traversal, equal timestamps, search, isolation, and cursor errors. Full backend/frontend tests, lint, backend typecheck, and frontend production build passed.
