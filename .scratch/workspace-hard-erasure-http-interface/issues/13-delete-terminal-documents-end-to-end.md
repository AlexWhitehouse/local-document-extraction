## Agent Brief

**Category:** enhancement
**Summary:** Make deletion of completed and failed Documents a real workspace-product operation, including residual Source-file cleanup and frontend state reconciliation.

**Current behavior:**
The document controller sends a raw `DELETE /jobs/:id` request, but the backend exposes only job reads and the product store has no terminal-delete operation. Browser tests therefore mock a route that does not exist.

**Desired behavior:**
An authorized workspace context can delete only a completed or failed Extraction job. The product store atomically removes the job, results, and source metadata, while the HTTP handler idempotently cleans any residual Source-file binary. Missing jobs remain a 404 so the frontend can show its existing already-removed outcome. Other jobs and Templates stay unchanged.

**Key interfaces:**
- `LocalWorkspaceProductStore.deleteTerminalExtractionJob` — validates terminal lifecycle state and removes authoritative job/result/source metadata as one operation while returning the residual Source-file key.
- Workspace product job handler — authorizes sessions/API keys, owns residual file cleanup, and exposes the defined `DELETE /v1/jobs/:id` result.
- Plain Document request adapter — constructs the delete route outside React and normalizes successful/not-found outcomes for the controller.

**Acceptance criteria:**
- [ ] Completed and failed Documents are removed with results/metadata/residual binary; non-terminal and missing cases have defined outcomes.
- [ ] Other Documents, Templates, and Workspace product data are preserved, with session/API-key authorization matching product routes.
- [ ] The controller uses the adapter and removes/de-selects document state and completed-cache entries for success or already-missing outcomes.
- [ ] Fetch-application contract tests cover terminal, residual, missing, and forbidden paths; focused frontend and build checks pass.

**Out of scope:**
- Cancellation of queued/processing extraction, background-runner protocol changes, and deletion of Templates or Workspaces.
- Generic job pagination/search work, handled by later issues.

## Completion

Contract coverage verifies completed, failed, missing, non-terminal, forbidden, API-key, and preservation behavior; full backend/frontend tests, lint, backend typecheck, and frontend production build passed.
