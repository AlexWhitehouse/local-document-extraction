## Agent Brief

**Category:** enhancement
**Summary:** Expose authorized Workspace membership listing through control data and a plain frontend domain adapter.

**Current behavior:**
The Workspace controller requests a member-list route directly, but the backend has no implementation. Tests satisfy the UI with raw route mocks, so the visible member-management panel does not prove an executable HTTP interface.

**Desired behavior:**
Any accepted signed-in Workspace member may request the current member list. The backend returns stable user ID, display name, email, and role data from Workspace control records; non-members and API-key callers cannot use the session-only route. The React controller calls a plain Workspace adapter that normalizes the list and guards late responses after context switching.

**Key interfaces:**
- `LocalWorkspaceControl` — authorizes an accepted member and returns Workspace member identity/role summaries.
- Workspace HTTP handler — exposes the session-only membership collection route without accepting API keys.
- Frontend Workspace request Adapter — owns membership route construction and response normalization outside React.

**Acceptance criteria:**
- [ ] An accepted member receives stable user identity, name, email, and role summaries for the selected Workspace.
- [ ] Non-members and Workspace API keys cannot list the members.
- [ ] The controller renders adapter-provided member data and ignores a late response for a no-longer-selected Workspace.
- [ ] A contract test runs the frontend Adapter against the real Fetch application for authorized and forbidden outcomes.
- [ ] Focused control/controller tests and build pass.

**Out of scope:**
- Member mutations, ownership transfer, invitation-management listing, and Leave Workspace.
- Changes to generic transport, live updates, or Workspace deletion behavior.

## Completion

Implemented control-data member listing, the session-only HTTP route, frontend request-adapter normalization, and real contract coverage for authorized, forbidden, and API-key cases. Full backend/frontend tests, lint, backend typecheck, and frontend production build passed.
