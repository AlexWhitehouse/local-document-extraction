## Agent Brief

**Category:** enhancement
**Summary:** Let a non-owner member leave a non-final Workspace through control data, the HTTP interface, and a frontend request adapter.

**Current behavior:**
The frontend confirmation and transition logic constructs a leave route, but no control-data operation or backend route exists. The UI uses mocked results, so a member cannot actually remove only their own membership.

**Desired behavior:**
A non-owner member who still has another accepted Workspace may leave. The operation removes only that caller's membership, preserves the Workspace and all its resources/other access, and returns a valid remaining accepted Workspace context with no key material. Owners, non-members, and API keys are rejected.

**Key interfaces:**
- `LocalWorkspaceControl` — atomically validates non-owner departure, removes only the caller's membership, and returns the next accepted Workspace.
- Session-only leave route — delegates to control data and never accepts Workspace API keys.
- Frontend Workspace request Adapter — owns leave route construction and normalizes the returned next context.

**Acceptance criteria:**
- [ ] A non-owner with another accepted Workspace leaves and receives a valid remaining context; the departed Workspace resources and other members remain.
- [ ] Owners, non-members, and API-key callers cannot leave.
- [ ] The controller uses the adapter, confirms, clears departed state, and selects the server-returned/remaining Workspace.
- [ ] Contract coverage crosses the Fetch application for success, rejection, and preserved resources.
- [ ] Focused control/context checks and build pass.

**Out of scope:**
- Creating a replacement for final departure, member management changes, and invitation lifecycle changes.
- Live updates, generic transport redesign, or Workspace deletion changes.
