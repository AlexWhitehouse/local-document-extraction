## Agent Brief

**Category:** enhancement
**Summary:** List actionable sent Workspace invitations for owners/admins through the control-data HTTP seam.

**Current behavior:**
Invitation creation and cancellation exist, but the controller directly requests a missing sent-invitation collection route and tests mock its response. The visible management list is not tied to executable pending invitation state.

**Desired behavior:**
Owners and admins can list only actionable pending invitations sent by their Workspace. Members and API keys are rejected; accepted, cancelled, declined, and expired entries are excluded. The frontend adapter owns the collection route and returns normalized invitation entries for the controller to refresh after create/cancel.

**Key interfaces:**
- `LocalWorkspaceControl` — authorizes owner/admin invitation management and returns current unexpired pending sent invitations.
- Session-only Workspace invitation collection route — lists for `GET` and retains existing creation behavior for `POST`.
- Frontend Workspace request Adapter — owns sent-invitation list route/response normalization.

**Acceptance criteria:**
- [ ] Owners/admins list current actionable pending sent invitations; members/API keys cannot.
- [ ] Non-pending or expired entries are excluded, and create/cancel refresh the same list.
- [ ] The controller consumes adapter output rather than a raw route request.
- [ ] Contract coverage exercises list/create/cancel/filter/forbidden outcomes through the Fetch app.
- [ ] Focused invitation/controller checks and build pass.

**Out of scope:**
- Additional invitation lifecycle states, outbound invitation delivery, and member mutations.
- Leave Workspace, live updates, or generic transport redesign.
