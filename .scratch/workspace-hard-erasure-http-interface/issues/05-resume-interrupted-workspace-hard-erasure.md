# Resume Interrupted Workspace Hard-Erasure

Status: completed
Category: bug
Type: AFK
User stories covered: 13, 18-20

## Parent

## What to build

Make Workspace hard-erasure recoverable across a backend crash or filesystem failure. Persist the minimum deletion intent needed to resume inaccessible cleanup, retry idempotently, and reconcile orphan Workspace product data before the Local extraction runner scans for resumable jobs.

A successful cleanup should remove transient deletion metadata. A failed synchronous request must not leave the Workspace accessible again, and startup must favor erasure over recovery of orphan Extraction jobs.

## Acceptance criteria

- [ ] Workspace control data persists enough deletion intent to resume cleanup after access revocation and before physical erasure completes.
- [ ] Completed hard-erasure removes transient deletion intent so successful deletion retains no unnecessary Workspace control record.
- [ ] Filesystem cleanup failure does not report successful deletion and leaves durable retry information.
- [ ] Startup resumes incomplete deletion before Local extraction runner recovery begins.
- [ ] Orphan Workspace product databases and Source-file directories associated with incomplete deletion are erased rather than recovered.
- [ ] Reconciliation is idempotent when control data, product data, Source files, or deletion metadata are already absent.
- [ ] A simulated crash after access revocation but before erasure completes is recovered automatically on restart.
- [ ] A simulated crash cannot cause queued or stale processing work for the deleted Workspace to run first.
- [ ] Active Workspace product data is never mistaken for an orphan during reconciliation.
- [ ] Focused migration/reconciliation, runner recovery, Workspace deletion, and backend typecheck checks pass.

## Agent Brief

**Category:** bug
**Summary:** Persist inaccessible Workspace deletion intent and reconcile it before runner recovery after interruption.

**Current behavior:**
Workspace control access is removed before physical erasure, but a filesystem failure or process interruption leaves no durable record that the remaining product database and Source files must be erased. Startup recovery can only infer product stores from disk, so it has no first-class cleanup instruction.

**Desired behavior:**
Deletion records a minimal durable Workspace deletion intent before revoking access. It removes that intent only after product and Source-file erasure succeeds. Failed cleanup returns failure while retaining the intent, and startup reconciles every intent idempotently before the extraction runner scans product stores. Active Workspace data is never selected for reconciliation merely because it exists on disk.

**Key interfaces:**
- `LocalWorkspaceControl` — persists, lists, and completes deletion intents independently of Workspace foreign-key cascades.
- `Workspace deletion` — records intent, performs synchronous cleanup, retains intent after cleanup failure, and exposes startup reconciliation.
- Runtime composition — invokes reconciliation before Local extraction-runner recovery and shares the deletion Module with the Fetch application.

**Acceptance criteria:**
- [ ] Access-revoked deletion has durable cleanup intent until product and Source-file erasure finish; successful deletion removes it.
- [ ] A physical cleanup failure reports failure, preserves intent, and leaves the Workspace inaccessible.
- [ ] Reconciliation idempotently erases product/source remnants for every intent and then removes only the completed intent.
- [ ] Reconciliation runs before runner recovery, so queued/stale orphan jobs cannot be scheduled first.
- [ ] Only explicit deletion intents are reconciled; active Workspace product data remains untouched.
- [ ] Focused control/reconciliation/runner tests and backend typecheck pass.

**Out of scope:**
- Browser invalidation, retries of live deletion HTTP requests, and user-facing recovery progress.
- Document deletion, profile, access-management, and job-listing capability work.

## Completion

Implemented durable Workspace deletion intents, failed-cleanup retention, idempotent reconciliation, and runtime startup reconciliation before runner recovery. Full backend/frontend tests, lint, backend typecheck, and frontend production build passed.
