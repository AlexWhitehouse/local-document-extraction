# Preserve non-PDF behavior and internal metadata boundaries

Category: enhancement
Status: completed

## Parent

.scratch/source-file-page-count/PRD.md

## What to build

Harden the feature boundaries around **Source file page count**. PNG, JPEG, and WebP Document submissions should continue through the existing successful submission flow without page counting and should persist `NULL` page count metadata. Existing Source file cleanup and failure-handling behavior should remain intact.

Keep **Source file page count** internal in this slice. It should not appear in public Extraction job list or detail responses, Workspace live update envelopes, Workspace product analytics events, queue messages, or Workflow params. The metadata is durable for future product features, but it should not become a public contract yet.

## Agent Brief

**Category:** enhancement
**Summary:** Preserve non-PDF Document submission behavior while keeping Source file page count internal.

**Current behavior:**
Valid PDF Document submissions already compute and persist Source file page count as nullable internal Source file metadata. Invalid or uncountable PDF Source files are rejected before durable side effects. The submission flow also supports PNG, JPEG, and WebP Source files under the existing MIME and byte-size rules, and the Source file page count path is intended to return `null` for those non-PDF Source files.

Some boundary behavior is already implied by the current interfaces: queued Extraction job creation accepts a nullable Source file page count, public queued responses omit it, queue messages and Workflow params do not carry it, Workspace product analytics events do not define it, and Workspace live update/job summary shapes are not intended to expose it. This issue is about hardening those contracts with focused behavior coverage and fixing any leaks found while doing so.

**Desired behavior:**
Supported non-PDF Document submissions should continue through the successful submission flow without PDF page parsing. They should pass `null` Source file page count metadata into queued Extraction job creation, and authoritative Workspace product data should accept and persist that `NULL` metadata honestly rather than inventing a page count for image Source files.

Source file page count must remain internal in this slice. It should not appear in Extraction job list responses, Extraction job detail responses, Workspace live update envelopes, Workspace product analytics events, queue messages, or Workflow params. Existing cleanup behavior must remain intact when queued Extraction job creation fails after upload and when queue send fails after queued job creation.

**Key interfaces:**
- Document submission route — should accept supported PNG, JPEG, and WebP Source files under the existing validation rules and pass `null` Source file page count into queued Extraction job creation.
- Source file page-counting boundary — should only count PDF Source files; non-PDF Source files should not invoke PDF parsing and should produce nullable page-count metadata.
- Queued Extraction job creation input — should continue to accept `number | null` Source file page count metadata.
- Workspace product store Source file metadata — should persist `NULL` page count values for non-PDF Source files.
- Extraction job list/detail response shapes — should continue to omit Source file page count.
- Workspace live update envelopes — should continue to omit Source file page count from job lifecycle payloads.
- Workspace product analytics events — should continue to omit Source file page count.
- Queue message and Workflow param shapes — should continue to omit Source file page count.
