# v0.1.4 — Evaluations

Compare extraction models and template variants on the same document before choosing what to use in your workflow.

## New: Evaluations

- Upload one PDF or image and compare up to eight candidates side by side.
- Compare model names and capabilities using shared Template fields, or compare independently editable Template variants using one shared model.
- Start from saved Templates or earlier field versions. Select a candidate and use **Add candidate** to copy its current settings without copying its results.
- Edit fields with the familiar Template editor and save useful changes as a new Template without altering the original.
- **Run all** submits candidates together through the existing scheduler, which controls concurrency and Workspace fairness. Results arrive independently and do not appear as completed Documents.
- Add and verify expected answers for field matches, table-cell matches, and coverage. Yes/No fields have typed controls; table answers use a schema-based editor with row selection and explicit row matching.
- Inspect missing or extra table rows, expand structured comparisons, and see queue time, processing time, and token usage when the gateway supplies it.
- Continue editing during a run. Results retain the submitted settings, and edited candidates indicate when they need another run. Failed reruns preserve the previous successful result.

Evaluations are temporary experiments available to signed-in Workspace members. Navigation within the same Workspace preserves them; refreshing, closing the tab, clearing the Evaluation, or switching Workspace discards them. Expected answers and results are not saved as evaluation history. Submitted model requests cannot be cancelled through the UI.

## Other changes since v0.1.3

- Generate a draft Template from a sample document using the configured Workspace model, then review it before saving.
- Refine the Template field and schema editors and the starter invoice Template.
- Enable authentication rate limiting and bound PDF inspection work and memory use.
- Expand the API documentation for automated extraction workflows.

## Compatibility and upgrading

Bun remains pinned to 1.4.2. Release targets remain macOS and glibc Linux on x64 and arm64. Evaluations use the existing Workspace gateway configuration and upload limits; no new credentials or configuration are required. Model requests go to the configured gateway and may incur provider charges.

Stop the application and back up its configuration and state, then run `document-extraction update v0.1.4` or rerun the installer. The installer preserves configuration and runs the normal idempotent migrations. Evaluations in open tabs are not included in backups; finish any experiments before upgrading.

Evaluation correctness and UI flows were tested with synthetic documents and a local fixture gateway. This does not qualify every third-party model or gateway. The release workflow validates the tagged commit before publishing the installer, source archive, and checksum.
