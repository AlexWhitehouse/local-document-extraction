# v0.1.4 — Evaluations

This release adds browser comparisons of extraction models and Template variants on the same document.

## New: Evaluations

- Upload one PDF or image. Compare up to eight candidates side by side.
- Compare model names and capabilities with shared Template fields. Alternatively, compare editable Template variants with one shared model.
- Start with saved Templates or earlier field versions. Select a candidate. Use **Add candidate** to copy its settings without results.
- Edit fields in the Template editor. Save useful changes as a new Template. The original stays unchanged.
- **Run all** starts candidates through the existing scheduler. It controls concurrency and Workspace fairness. Results appear independently and do not become completed Documents.
- Add and verify expected answers for field matches, table-cell matches, and coverage. Yes/No fields use typed controls. Table answers use a schema-based editor with row selection and explicit row matching.
- Inspect missing or extra table rows. Expand structured comparisons. View queue time, processing time, and token usage when available from the gateway.
- Continue editing during a run. Results keep the settings used at submission. Edited candidates indicate that another run is needed. Failed reruns keep the previous successful result.

Signed-in Workspace members can use these temporary Evaluations. Navigation within the Workspace preserves them. Refresh, tab closure, Clear Evaluation, and Workspace changes discard them. Expected answers and results do not become saved evaluation history. The UI cannot cancel submitted model work.

## Other changes since v0.1.3

- Sample documents can generate draft Templates with the Workspace model. Users review each draft before saving.
- Template field and schema editors, and the starter invoice Template, have improvements.
- Authentication rate limits and bounded PDF inspection control work and memory use.
- API documentation includes more information for automated extraction workflows.

## Compatibility and upgrading

Bun remains pinned to 1.4.2. Release targets remain macOS and glibc Linux on x64 and arm64. Evaluations use existing Workspace model settings and upload limits. They require no new credentials or configuration. Runs use the configured gateway and can incur provider charges.

Before an upgrade, finish open Evaluations. Backups do not include them. Stop the application. Back up configuration and state. Run `document-extraction update v0.1.4` or run the installer again. The installer keeps configuration and runs the normal idempotent migrations.

Evaluation behavior and UI workflows passed tests with synthetic documents and a local fixture gateway. These tests do not qualify every third-party model or gateway. The release workflow validates the tagged commit before publishing the installer, source archive, and checksum.
