# v2.4.0 — Connected apps through MCP

This release lets an MCP client, such as an LLM chat app, work in one Workspace on behalf of a signed-in user ([#86](https://github.com/AlexWhitehouse/local-document-extraction/pull/86)). It is off by default. The release also moves action outcomes to toasts, pins Bun 1.4.3 and upgrades React to 19 and Better Auth to 1.7.7 ([#78](https://github.com/AlexWhitehouse/local-document-extraction/pull/78)–[#85](https://github.com/AlexWhitehouse/local-document-extraction/pull/85)).

## Connected apps (MCP)

[Connected apps through MCP](https://github.com/AlexWhitehouse/local-document-extraction/blob/v2.4.0/docs/mcp.md) describes setup, scopes and limits.

- **Opt-in:** set `MCP_ENABLED=true` and a public HTTPS `BETTER_AUTH_URL` behind your own reverse proxy. Hosted clients cannot reach a loopback address. Clients connect to `https://<your origin>/mcp` and register their own callbacks.
- **Delegated, not shared keys:** a connection acts as one user in one Workspace that the user selects on a consent page. It never receives a Workspace API key or Application admin authority. Every call checks the grant, scopes, membership and role against current state.
- **Consent:** sign-in, sign-up, email verification and Google sign-in resume the connection request. The consent page shows the callback destination. Client names and websites are unverified. `workspace:read` is required; other scopes are optional.
- **Lifetime:** access tokens last five minutes. **Stay connected** is off initially. Without it there is no refresh token, and access ends within five minutes or when the browser session ends. With it, refresh tokens rotate within a fixed 30-day grant lifetime.
- **Tools:** read Workspace context, Documents, packets, results, originals, Templates and tags; submit Documents; choose Templates and confirm split plans; create, update, generate and assist Templates; read costs and Model gateway settings for owners and admins.
- **Uploads:** a file attached to a chat is not on the server. The client asks for an upload link, you upload the file in a signed-in browser, and the client submits it. Submission uses the same admission limits, retention and processing as the app.
- **Sensitive actions:** Workspace changes, invitations, member and ownership changes, API-key rotation, Model gateway changes and deletions stay off until `MCP_SENSITIVE_ACTIONS_ENABLED=true`. Each one then needs an approval in the app that shows the exact targets and consequences. Gateway secrets are entered only on that page, and a rotated API key is shown only in the approving browser.
- **Profile settings → Manage connected apps** lists your connections and disconnects each one. Revocation takes effect on the next request. This page works while MCP is disabled.
- **Retries:** a stable `operation_id` recovers a lost response without repeating the action. Interrupted operations are marked as unknown instead of being repeated.

## Interface changes

- Action outcomes appear as toasts instead of inline text. This covers Workspace invitations, starting Evaluations, Template assistant requests, sign-in, sign-up and password reset. Field validation stays inline.
- In Model gateway settings, **Test connection** is now **Test**. A pass briefly shows a tick on the button, and results appear as toasts.
- A packet list that fails to load offers **Try again**. The **Try again** label in the PDF viewer's unavailable-source notice no longer overflows its button.
- The **Choose template version** dialog in Evaluations no longer closes straight away when opened during an editor change.

## Runtime and dependencies

- Bun is pinned to **1.4.3**. The installer and `update` download it automatically.
- React 19, Better Auth 1.7.7, TypeScript 6, Vitest 5, jsdom 30 and other dependencies were upgraded. Type checks use `bun check`.
- The release workflow builds the archive once, tests that archive on every CI platform, and publishes it without rebuilding.

## Upgrading and compatibility

The release workflow checks **Ubuntu 24.04 x64 and arm64, and macOS 15 arm64**. Intel macOS binaries are bundled but not qualified by the CI matrix.

Stop the application. Back up its configuration and state. Then run:

```bash
document-extraction update v2.4.0
```

Migration adds the OAuth, signing-key and connected-app tables to the control database. Each Workspace database adds an operation receipt table the first time it opens. All changes are additive, and existing accounts and data are kept.

`.env.example` adds `MCP_ENABLED=false` and `MCP_SENSITIVE_ACTIONS_ENABLED=false`. Other settings and defaults are unchanged. With MCP disabled, `/mcp` and dynamic client registration are unavailable.

Back up the whole state folder with its machine keys while the server is stopped. Restoring an older backup also restores its grants and signing keys: start with MCP disabled and disconnect restored connections before turning it back on.

## Known limits

- The installation owner reported successful use of **ChatGPT web** on 2026-10-11. No client build or scenario checklist was recorded. **Claude Desktop and other clients are not qualified.** Check your own client before enabling sensitive actions.
- There is no persistent MCP session, resumable stream, task API or subscription. One Bun process serves each state folder.
- Dynamic client registration is open while MCP is on. It is rate-limited and capped at 1,000 clients. Unused clients older than 24 hours are pruned during requests, so a client that waits longer before its first consent may need to register again. Pruning does not stop a sustained registration flood; limit registration at the proxy if needed.
- Repeated migrations can print Better Auth array/TEXT warnings for OAuth fields. They do not mean the migration failed.
- Simulated model tests do not qualify live model routes, Google sign-in or Cloudflare email delivery.
