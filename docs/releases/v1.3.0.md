# v1.3.0 — Evaluation editing and packet progress

This minor release expands Evaluation library editing, shows packet progress on document tabs, and improves single-page PDF processing and Workspace Costs labels.

## Evaluation library and expected answers

- Edit saved library documents without configuring or running a model. Open **Manage library → Edit** to review saved fields and Expected answers.
- Choose a Template and its current or historical field version while editing. **Edit Template → Save Template** saves changes to the selected Workspace Template and uses the new version in the editor. Updating the library's saved answers remains a separate, explicit action.
- **Review template changes** and the **Template changes** filter identify changed field types, names, instructions, new fields, and saved fields no longer requested.
- Review changed tables with their updated columns while retaining compatible values, cell scoring states, and row matching. Reuse previous answers for renamed columns, review supported type conversions, and choose the Expected answer Template when candidates use different schemas.
- Saved answers for removed fields remain available for reuse and appear muted when no longer requested. **Remove expected answer** removes one from the working copy; saving that removal to the library requires **Update saved answers…**.
- Save feedback uses the application's action toasts. Canceling a review leaves existing answers unchanged.

## Document processing and costs

- Packet progress appears directly on the Overview and document tabs. The Overview shows the current packet stage; each document tab shows its pages and status. Animated underlines identify active work, completion, and items needing attention, with reduced-motion preferences respected. The packet summary stays above the tabs when switching documents.
- PDFs uploaded with exactly one page bypass Smart splitting and blank-page exclusion and create one ordinary Extraction job. Automatic Template selection still applies when requested. A multi-page original with only one selected page continues to follow Workspace splitting settings.
- Workspace Costs resolves Template names for split children before their jobs exist and repairs cached **Unassigned** labels when Template metadata is available. Existing resolved historical names are preserved, including accounting records retained after Document deletion.

## Maintenance

The workspace now enforces the vendored anti-slop rules alongside ESLint. Shared JSON validation, typed boundaries, test dependency seams, and formatting were updated to meet those checks.

## Upgrading and compatibility

Bun remains pinned to **1.4.2**. The release workflow checks **Ubuntu 24.04 x64 and arm64, and macOS 15 arm64**. The installer recognizes Intel macOS, but this release's CI does not qualify Intel macOS or older operating systems.

Finish any unsaved Evaluations, then stop the application and back up its configuration and state. Run:

```bash
document-extraction update v1.3.0
```

Workspace product schema migration **14** schedules an incremental, restartable repair of cached cost labels before resuming normal historical backfill. It does not repeat model calls. Existing documents, extraction results, and reported costs remain available. No new required environment variables or provider settings are introduced.

The installer preserves configuration, accounts, documents, and generated secrets. It backs up local state before migration checks. Back up S3 buckets separately. Before a downgrade, restore the backup from before the upgrade.

## Known limits and validation

- Evaluation runs, results, and unsaved answer edits remain temporary. Save library changes explicitly before refreshing or closing the tab.
- A missing Template name can be repaired only while its metadata remains available. The cost repair cannot recover accounting records deleted before accounting retention was introduced.
- Automatic processing can require user review. Model capability, context, and request-size limits still apply.
- S3 buckets must not use object versioning or Object Lock. Local backups exclude S3 originals. Source downloads do not support byte ranges.

The release workflow validates the exact tagged commit before publishing `install.sh`, `document-extraction.tar.gz`, and its SHA256 checksum. Checks include the platform quality and installer suites, Linux Chromium journeys, and the complete-history secret scan. Automated checks do not qualify live Google sign-in, Cloudflare email delivery, or every third-party model route.
