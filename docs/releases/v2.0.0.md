# v2.0.0 — Go document processing

This major release replaces the Bun background processing engine with Go for smart splitting, automatic Template selection, and extraction. Bun continues to serve the public API and frontend, authenticate users, and own Workspace storage and result validation. Existing frontend and public API behavior is preserved.

## Processing changes

- Provider requests have their own concurrency allowance. Waiting for a model response releases local processing capacity so other documents can be prepared and uploaded.
- Model uploads stream from files with bounded buffers. Final extraction releases temporary prepared files after upload, while durable Sources remain available for recovery.
- Smart splitting gives each child document its own model context using logical PDF page views. Local processing avoids creating child PDFs until a download or a PDF-capable provider needs one. Providers without native PDF support continue to receive rendered pages.
- Rendering reuses exact page images across splitting, Template selection, and extraction. Warm workers overlap rendering and lossless PNG encoding while preserving decoded pixels and page dimensions.
- Uploads and result writes can share durable SQLite commits. Accepted work remains durable, and the application recovers outstanding work after a restart.

## Performance evidence

On the development host, the two-page PDF benchmark with smart splitting, automatic Template selection, and an image-only simulated provider reached **27.00 completed Documents/s with a seven-second provider delay**. A separate final runtime check reached **32.66 Documents/s with near-instant simulated responses**. The latter completed all 1,372 accepted logical Documents with verified results and stage counts, zero failed accepted Documents, and 60 rejected upload attempts under saturation.

These are logical child Documents per second, not uploaded PDF packets per second. Each packet in this fixture contains two Documents. Results depend on document size, page content, machine resources, concurrency settings, and provider behavior; they are not a production throughput guarantee. No paid model calls were used. Benchmark summaries remain in `backend-go/`; generated raw results are local, ignored artifacts and are not included in the release.

## Upgrading and runtime requirements

Stop the application and back up its configuration and state, then run:

```bash
document-extraction update v2.0.0
```

Release archives include Go processor binaries for Linux and macOS on x64 and arm64. Installed releases do **not** require a Go compiler. Bun remains pinned to **1.4.2**. Source development requires Go matching `backend-go/go.mod` (**1.27.1** for this release); the normal commands remain:

```bash
bun run build
bun run start
```

Go processing is always enabled. There is no Bun background-processing fallback. The supervisor starts the processor and restarts it after process loss; startup reports a missing processor binary.

Local concurrency now derives from CPU and RAM unless explicitly configured. `GO_MODEL_CONCURRENCY` controls simultaneous provider requests separately; it defaults to an explicitly configured `EXTRACTION_MAX_CONCURRENCY`, otherwise 24. Existing configuration overrides are preserved on upgrade. Review them when tuning throughput. Further controls and resource bounds are documented in the [processor guide](../../backend-go/README.md) and [configuration guide](../configuration.md).

The installer preserves configuration, accounts, documents, extraction results, and generated secrets, and backs up local state before migration checks. No new numbered database migration is introduced by this release, but new processing can persist logical PDF Sources that older releases cannot read. **An in-place downgrade to v1.x is unsupported.** Restore the pre-upgrade application state and configuration to roll back. Back up S3 buckets separately; local backups do not contain S3 originals.

## Qualification and known limits

The release workflow validates the exact tagged commit before publishing the installer, archive, and SHA256 checksum. It checks quality, tests, coverage, native PDF rendering, and installation on **Ubuntu 24.04 x64 and arm64, and macOS 15 arm64**, plus Linux Chromium journeys, Go race checks, and a complete-history secret scan. Intel macOS binaries are bundled but Intel macOS and older operating systems are not qualified by this CI matrix.

- Model context, request-size, and rate limits still apply. Automatic processing can require user review; concurrency does not remove provider limits.
- S3-retained split children still publish separate derived PDFs. S3 buckets must not use object versioning or Object Lock. Source downloads do not support byte ranges.
- Evaluation runs, results, and unsaved answer edits remain temporary. Save library changes before refreshing or closing the tab.
- Simulated model tests do not qualify live model routes, Google sign-in, or Cloudflare email delivery.
