# v2.1.1 — Single PDF engine, evaluation cost and list fixes

This maintenance release completes the move to PDFium, raises the default upload and model-call concurrency, shows model cost in Evaluations, and fixes two document list display bugs.

## Interface changes

- Each Evaluation candidate shows its run cost beside its score, for example `$0.0123`. A trailing `+` marks a partial total when some model calls did not report cost; `Unavailable` means the endpoint reported none. The candidate's run details show the exact amount. Cost covers the successful attempt only, matching the token figures. Evaluation spend stays temporary and is not added to Workspace or Document costs.
- Document list rows keep their normal height once the list holds more than 100 items. Previously, rows grew until the page was reloaded.
- A split upload whose document is waiting for a Template, or has failed, now shows a red edge and **Template needed** in the document list instead of the blue in-progress state.

## Processing changes

- PDFium is the only PDF engine. The Bun API now uses the same `document-extraction-pdf` worker as the Go processor for upload inspection, previews, blank-page checks, page subsets, and its own page rendering. `pdfjs-dist` is removed.
- Page subsets are produced by PDFium. Selecting every page sends the original file.
- Parser budgets are replaced by worker memory ceilings (256 MiB for inspectors, 1 GiB for page workers) and the existing deadlines. Hostile page trees are rejected at the ceiling.
- Workers no longer inherit their parent's peak memory reading, which could otherwise reject every upload once the API process exceeded 256 MiB.
- Fewer runtime round trips per model call, and live-update summaries are built only when someone is subscribed.

PDFium previews, subsets, and blank-page checks are not byte-identical to the previous PDF.js and pdf-lib output. Check extraction accuracy on representative documents if you depend on exact results.

## Changed defaults

| Setting | v2.1.0 | v2.1.1 |
| --- | ---: | ---: |
| `SUBMISSION_MAX_CONCURRENCY` | 8 | 24 |
| `SUBMISSION_MAX_RESERVED_BYTES` | 128 MiB | 288 MiB |
| `GO_MODEL_CONCURRENCY` | 24 | 96 |

Explicit settings in your configuration still take precedence. Lower `GO_MODEL_CONCURRENCY` if your model provider accepts fewer simultaneous requests. Adaptive slowdown remains enabled.

## Upgrading and compatibility

Bun remains pinned to **1.4.2**. The release workflow checks **Ubuntu 24.04 x64 and arm64, and macOS 15 arm64**. Intel macOS binaries are bundled but not qualified by the CI matrix.

Stop the application. Back up its configuration and state. Then run:

```bash
document-extraction update v2.1.1
```

This release adds no database migrations, and state remains compatible with v2.1.0. Evaluation results produced before the upgrade show `Unavailable` cost until they are rerun.

## Known limits

- Model context, request-size, and rate limits still apply. Evaluation cost appears only when the model endpoint reports it.
- Simulated model tests do not qualify live model routes, Google sign-in, or Cloudflare email delivery.
