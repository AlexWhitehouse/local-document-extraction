# v2.5.2 — Template assistant saves applied changes

In this release, applying the Template assistant’s proposed changes saves them to the template ([#98](https://github.com/AlexWhitehouse/local-document-extraction/pull/98)). Before, **Apply** only changed the open draft or the Evaluation candidate, so the saved template stayed the same unless you saved it separately.

## Template assistant

- **Templates:** **Apply and save** updates the draft and saves the template in one step. The panel shows “Applied and saved” and the new version. If the save fails, the changes stay in the draft with a note to save them.
- **Evaluations:** after you apply proposed changes, **Apply and save** saves them to the candidate’s library template and moves the candidate to the saved version. In a model comparison it updates every candidate that shares the template. **Test changes** still runs the changes on a copy without saving them.
- **Versions:** field changes create a new template version. Changes to only the name or description are saved without one.

## Fixes

- **Late saves:** a save that finishes after you open another Evaluation no longer changes the candidates there. A candidate whose template you edited while the save ran keeps your edit.

## Upgrading and compatibility

The release workflow checks **Ubuntu 24.04 x64 and arm64, and macOS 15 arm64**. Intel macOS binaries are bundled but not qualified by the CI matrix.

Stop the application. Back up its configuration and state. Then run:

```bash
document-extraction update v2.5.2
```

- **Databases:** no migrations.
- **Settings:** no settings or defaults change.
- **API:** no changes.

## Known limits

- In an Evaluation, **Apply and save** needs a candidate whose template is in the library.
- Saving doesn’t check for changes made to the same template elsewhere since it was opened. The last save wins.
