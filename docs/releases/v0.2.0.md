# v0.2.0 — Keep original documents

This release can retain each uploaded Document's original file. Users can view it beside extraction results and download it later.

## New: original documents

- Choose no retention, the private data folder, or an S3-compatible bucket such as AWS S3 or a local RustFS server. No retention remains the default. The installer asks on first installation. Existing installations keep their behavior until retention is enabled.
- Open a Document. Select **Results** or **Side by side** in the summary strip. Side by side displays the original and results with an adjustable divider. Narrow screens use Results and Document tabs. The browser remembers each account's choice.
- PDFs use the browser viewer without its thumbnail sidebar. Images support fit, 100%, and 200% display. **Download** in the page heading saves the original with its uploaded name.
- Workspace owners and admins can disable **Retain original documents**. This affects only new uploads. Existing originals remain available.
- Workspace members and Workspace API keys can read originals through `GET /v1/jobs/{jobId}/source`. If an original is unavailable, results remain accessible. The app distinguishes no retention, a missing file, and temporarily unavailable storage.
- Document or Workspace deletion immediately removes access. Background cleanup deletes originals and retries until storage confirms removal.
- `document-extraction storage configure` selects storage and tests S3 settings with a small file. It can also replace credentials or disable retention for new originals.

## Other changes

- Uploads with non-ASCII names, such as `März.pdf`, now save and download correctly.

## Compatibility and upgrading

Bun remains pinned to 1.4.2. Release targets remain macOS and glibc Linux on x64 and arm64.

Stop the application. Back up configuration and state. Run `document-extraction update v0.2.0` or run the installer again.

Updates keep existing settings. To enable retention, run `document-extraction storage configure` or set `SOURCE_STORAGE_PROVIDER`. Migrations add retention columns to Workspace databases and storage tables to the control database. Existing Documents become not retained. Downgrade requires the backup from before the upgrade.

Configuration changes:

- New settings are `SOURCE_STORAGE_PROVIDER` (`none`, `local`, or `s3`), `SOURCE_ORIGINAL_RETENTION_ENABLED`, and `SOURCE_STORAGE_S3_*`. See [Keep original documents](../configuration.md#keep-original-documents).
- `FAILED_SOURCE_RETENTION_MS` and `SOURCE_RETENTION_SWEEP_INTERVAL_MS` keep their existing meaning. They apply only to files without retained originals.

## Known limits

- S3 buckets must not use object versioning or Object Lock. The app does not verify these settings. On such buckets, earlier versions remain after deletion.
- Originals cannot move between storage locations. While originals or unfinished deletions depend on a bucket, its endpoint, bucket, prefix, and addressing style cannot change. A destination change prevents startup. Credentials can still be replaced.
- App backups exclude S3 originals. Back up the bucket with the provider's tools.
- S3 storage passed tests with a self-hosted RustFS server and an in-process test server. AWS S3 is not yet qualified.
- Downloads return complete files. Byte-range requests are not supported.

The release workflow validates the tagged commit before publishing the installer, source archive, and checksum.
