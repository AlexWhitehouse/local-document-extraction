# v0.2.0 — Keep original documents

Keep the original file of each uploaded Document, view it beside its extraction results, and download it again later.

## New: original documents

- Choose where originals are kept: nowhere (the default and previous behaviour), in the private data folder, or in an S3-compatible bucket such as AWS S3 or a RustFS server you run. The installer asks on first install; existing installations keep their current behaviour until you opt in.
- Open a Document and switch between **Results** and **Side by side** in the summary strip. Side by side shows the original next to its results, with a divider you can drag. On narrow screens it becomes Results and Document tabs. Each account's choice is remembered in its browser.
- PDFs open in the browser's viewer without the thumbnail sidebar. Images can be shown to fit, at 100% or at 200%. **Download** in the page heading saves the original under its uploaded name.
- Workspace owners and admins can turn off **Retain original documents** for their Workspace. This affects new uploads only; originals already kept stay available.
- Originals are shown only to Workspace members and Workspace API keys (`GET /v1/jobs/{jobId}/source`). If an original is unavailable, its results are unaffected: the app shows whether it wasn't kept, is missing from storage, or storage can't be reached right now.
- Deleting a Document or Workspace removes access immediately and deletes its originals in the background, retrying until storage confirms removal.
- New launcher command: `document-extraction storage configure`. It chooses the storage, checks S3 settings with a small test file, and can rotate credentials or stop keeping new originals.

## Other changes

- Uploaded file names with non-ASCII characters (for example `März.pdf`) are now saved and downloaded correctly.

## Compatibility and upgrading

Bun remains pinned to 1.4.2. Release targets remain macOS and glibc Linux on x64 and arm64.

Stop the application and back up its configuration and state, then run `document-extraction update v0.2.0` or rerun the installer. Updates keep your settings, so originals are not kept until you run `document-extraction storage configure` or set `SOURCE_STORAGE_PROVIDER`. Migrations add retention columns to each Workspace database and storage tables to the control database. Existing Documents are marked as not retained. Downgrading requires the backup taken before the upgrade.

Configuration changes:

- New `SOURCE_STORAGE_PROVIDER` (`none`, `local` or `s3`), `SOURCE_ORIGINAL_RETENTION_ENABLED`, and `SOURCE_STORAGE_S3_*` settings. See [Keep original documents](../configuration.md#keep-original-documents).
- `FAILED_SOURCE_RETENTION_MS` and `SOURCE_RETENTION_SWEEP_INTERVAL_MS` keep their meaning and apply only to files whose originals aren't kept.

## Known limits

- S3 buckets must not use object versioning or Object Lock. The app does not check this, and on such buckets earlier copies of deleted originals remain.
- Originals can't be moved between storage locations yet. While any originals or deletions depend on an S3 bucket, its endpoint, bucket, prefix and addressing style can't change, and the app refuses to start if they do. Credentials can be rotated.
- S3 originals are not included in app backups; back up the bucket with your provider's tools.
- S3 storage was tested against a self-hosted RustFS server and an in-process test server. It has not yet been qualified against AWS S3.
- Downloads are full-file only; byte-range requests are not supported.

The release workflow validates the tagged commit before publishing the installer, source archive and checksum.
