# v1.0.0 — Automatic template selection and smart splitting

Upload a document with template tags and let the application choose a suitable template. Enable Smart splitting to turn a PDF containing several documents into separate extraction jobs, each with its own results and original page references.

## Automatic document processing

- Create, rename, assign, and delete shared template tags in the frontend. Names are normalized to lowercase, and templates can have multiple tags.
- Supply `template_tags` without `template_id` to choose automatically among templates matching **any** supplied tag. Classification uses candidate names and descriptions; each document in a split PDF is classified independently.
- An explicit `template_id` pins that template version and bypasses automatic template selection. Smart splitting still applies when enabled, and every resulting document uses the pinned template.
- Workspace owners and admins can enable Smart splitting and optional blank-page exclusion under **Document processing**, below the Model gateway. Both settings are off by default. Blank-page removal is part of Smart splitting, and nonblank cover pages are kept.
- Ambiguous decisions receive bounded reassessment before requiring review. Unresolved boundaries and template choices keep their source available for review; restarting the application resumes durable processing without recreating children.
- Multi-document uploads show an overview and separate document tabs. A single-page upload, or an accepted split plan containing one document, opens directly as a normal document. Verified excluded pages remain recorded.
- The upload dialog supports either a specific template or automatic selection by tags. Workspace settings use immediate toggle feedback and save notifications.
- Original-page review previews remain stable during polling and rerenders, avoiding duplicate preview requests.

## API integration

Continue submitting multipart requests to `POST /v1/extract`. Supply either `template_id` or a nonempty `template_tags` JSON array; requests with neither are rejected. Existing explicit-template integrations keep their behavior while Smart splitting is disabled.

With Smart splitting enabled, PDF submissions return a packet representation with `202`, `Location: /v1/packets/{packet_id}`, and `Retry-After: 2`. Poll the packet, then follow each `children[].job_id` using `GET /v1/jobs/{job_id}` to obtain its extraction results. Child `source_pages` refer to the original PDF's physical page numbers. Even a one-child result retains this packet API contract; its simplified frontend presentation does not change the response type.

Handle `awaiting_review` packets and `awaiting_template` jobs explicitly. An all-blank PDF can finish with `outcome: "no_documents"` and no children. See the [API reference and request-chain example](https://github.com/AlexWhitehouse/local-document-extraction/blob/v1.0.0/mkdocs/docs/api/overview.md#follow-the-packet-and-child-request-chain) and the updated [Postman collection](https://github.com/AlexWhitehouse/local-document-extraction/blob/v1.0.0/postman/local-api.postman_collection.json).

## Also included since v0.2.0

- The Template assistant can explain extraction results, diagnose field guidance, and propose edits for review before application.
- The Model gateway supports separate models for document extraction, the Template assistant, and document classification and splitting. Optional roles inherit the extraction model when unset.
- The Evaluation library stores reusable documents and Expected answers. Batch Evaluations compare candidates across documents, with result caching, field mapping, and answer verification.
- Evaluation navigation, day-first date scoring, document preview dividers, and shared interface styling have been improved.

## Upgrading and compatibility

Bun remains pinned to **1.4.2**. Automated release qualification covers **Ubuntu 24.04 x64 and arm64, and macOS 15 arm64**. The installer also recognizes Intel macOS, but this release's CI does not qualify that platform or older operating systems.

Stop the application and back up its configuration and state before running:

```bash
document-extraction update v1.0.0
```

The installer preserves configuration, accounts, documents, and generated secrets, and backs up local state before migration. Back up any S3 bucket separately. Database initialization adds the template-tag, model-role, evaluation-library, and document-processing state needed since v0.2.0. Existing templates and extraction results remain available; Smart splitting and blank-page exclusion remain disabled until enabled in each Workspace. No new environment variables are required for automatic processing. Downgrading requires restoring the pre-upgrade backup.

If you customized upload memory limits, `SUBMISSION_MAX_RESERVED_BYTES` must now accommodate `MAX_SOURCE_FILE_BYTES` plus **40,960 bytes** of multipart overhead (previously 32,768). Default settings already satisfy this requirement.

## Known limits

- Choose a classification/splitting model route with the required document capabilities. Provider image-count, PDF, context, and request-size limits still apply; rendered page images are not automatically batched to work around provider limits. A successful connection test does not test these capabilities.
- Automatic processing can add latency and model usage. Unresolvable decisions or provider failures can require manual review.
- API consumers use polling; a completed parent does not embed child extraction results. A failed parent can still have children worth following.
- Existing source-storage limits remain: S3 buckets must not use object versioning or Object Lock, S3 originals are not included in local backups, and source downloads do not support byte ranges.

The release workflow validates the exact tagged commit before publishing `install.sh`, `document-extraction.tar.gz`, and its SHA256 checksum. Live Google sign-in, Cloudflare email delivery, and every third-party model route are not implied by these automated checks.
