# v2.7.0 — Invite-only sign-up

In this release, `AUTH_SIGNUP_ENABLED=false` makes sign-up invite-only instead of blocking every new account ([#104](https://github.com/AlexWhitehouse/local-document-extraction/pull/104)). Only Application admins and the people they invite can use the installation.

## Invite-only sign-up

- **Turning it on:** set `AUTH_SIGNUP_ENABLED=false`, and list the administrators in `DOCUMENT_EXTRACTION_ADMIN_EMAILS`. You no longer have to create admin accounts before closing sign-up.
- **Who can sign up:** emails in `DOCUMENT_EXTRACTION_ADMIN_EMAILS`, and emails with a pending, unexpired Workspace invitation. Anyone else gets "Sign-up is by invitation only. Ask a workspace admin to invite this email address." Emails match without regard to case.
- **Who can sign in:** Application admins, accounts whose email is listed, accounts with a pending invitation, and members of at least one Workspace.
  - Others get "This account doesn't have access to any workspace. Ask a workspace admin to invite you."
  - Losing access also signs out the account's open sessions.
  - A new invitation restores access.
  - Admin impersonation still works.
- **Invited people:**
  - On first sign-in, their pending invitations are accepted automatically, so they land in the Workspace they were invited to. They get no personal Workspace.
  - Only admins can create Workspaces. **Create workspace** is hidden for everyone else.
  - Invited people can't leave their only Workspace.
  - Workspace members aren't offered the first-use tour, because it creates templates and uploads in the shared Workspace and needs an owner or admin to set up the Model gateway.
- **Google sign-in:** the same rules apply. A refused Google sign-in returns to the sign-in screen with the matching message.
- **Sign-in screen:** in invite-only mode it shows **Have an invitation? Sign up** where it used to say registration is closed. Refusal messages stay until dismissed, and clear when sign-in succeeds.
- **Open sign-up** (`AUTH_SIGNUP_ENABLED=true`, the default) is unchanged.

The decision is recorded in [ADR 0031](https://github.com/AlexWhitehouse/local-document-extraction/blob/v2.7.0/backend/docs/adr/0031-invite-only-sign-up.md).

## API

- **Workspaces:** `GET /v1/workspaces` gains a top-level `can_create_workspaces` boolean.
- **New Workspace errors:**
  - `POST /v1/workspaces` can return `403 workspace_creation_restricted`.
  - `POST /v1/workspaces/{id}/leave` returns `409 last_workspace` when an invited person leaves their only Workspace.
- **New sign-up and sign-in errors:** `/api/auth/*` can return `403` with the code `INVITATION_REQUIRED` or `ACCESS_REQUIRED`. Google redirects carry the same values in `?error=`.

## Upgrading and compatibility

The release workflow checks **Ubuntu 24.04 x64 and arm64, and macOS 15 arm64**. Intel macOS binaries are bundled but not qualified by the CI matrix.

Stop the application. Back up its configuration and state. Then run:

```bash
document-extraction update v2.7.0
```

- **Migrations:** none, in either the control database or Workspace databases.
- **Changed setting:** `AUTH_SIGNUP_ENABLED=false` now means invite-only. If you already run with it, review these two effects before upgrading:
  - People with a pending invitation, and listed admin emails without an account, can now sign up.
  - Existing accounts that aren't admins and belong to no Workspace and have no pending invitation can no longer sign in.
- **Email verification:** without `AUTH_REQUIRE_EMAIL_VERIFICATION=true`, someone who knows an admin or invited email address could register it before its owner. Turn verification on for shared installations.

## Known limits

- The app doesn't email invitations. Tell invited people to sign up with the invited address. Invitations expire after 7 days.
- Adding an email to `DOCUMENT_EXTRACTION_ADMIN_EMAILS` later lets that account sign in and create Workspaces. It doesn't give it the Application admin role, so it can't manage accounts.
- Invitations arriving for someone who already belongs to a Workspace still wait for them to accept.
