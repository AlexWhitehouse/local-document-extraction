# v2.5.0 — Command palette

This release adds a ⌘K / Ctrl+K command palette for finding documents and templates and running actions in plain language ([#95](https://github.com/AlexWhitehouse/local-document-extraction/pull/95), closes [#94](https://github.com/AlexWhitehouse/local-document-extraction/issues/94)). The Costs page gains a chart/table switch and a full-range Excel export ([#92](https://github.com/AlexWhitehouse/local-document-extraction/pull/92), [#93](https://github.com/AlexWhitehouse/local-document-extraction/pull/93)). Account emails are now styled HTML ([#91](https://github.com/AlexWhitehouse/local-document-extraction/pull/91)), and auth screens report problems as toasts ([#89](https://github.com/AlexWhitehouse/local-document-extraction/pull/89)).

## Command palette

- **Opening:** press ⌘K / Ctrl+K anywhere, or choose **Search** at the top of the sidebar. Esc steps back once at a time: an open action, then the pills, then the text, then the palette. It works from the keyboard alone.
- **As you type:** matching actions, templates, documents, pages and workspaces appear straight away.
- **On Enter:** the request becomes typed pills, such as Action, Template, Field, Condition, Date and Status. Each pill shows what it matched.
  - If every phrase is recognised, the search runs with no model call.
  - Otherwise the Workspace's assistant model is asked once. It only fills the gaps, so the parts already recognised keep their meaning between runs.
  - Words that couldn't be used are marked.
- **Searching:** search covers extracted values as well as names, statuses, templates and upload dates. For example, "invoices where the invoice number starts with "inv" uploaded last week" or "receipts with a total over 500".
  - Fields are matched by template, field and type, so a field with the same name on another template never matches.
  - Not found, invalid and empty values stay distinct from zero and false.
  - "Last week" and similar refer to the upload date in UTC days.
  - Tables and nested fields can't be searched yet.
- **Processing cost:** owners and admins can search by cost, for example "documents with a cost over $0.03". It's calculated the same way as on the Costs page.
- **Actions:** each one finishes inside the palette and reports through a toast.
  - Export as CSV, JSON or Excel, for up to 500 documents.
  - Try failed documents again.
  - Delete, after a confirmation inside the palette.
  - Edit a template: the template assistant proposes changes, which you save as a new version or open in the editor.
  - Create a template from a description.
  - Upload, invite a member, switch workspace, set up an evaluation, or go to a page.
- **Open in Documents:** filters the Documents list to the palette's matches. **Clear** returns to the full list.

## Documents, Templates and Workspaces lists

- The search boxes on the three lists are gone; the palette replaces them.
- The date and model filter button on the Documents list is gone too.
- Ticking a document swaps the **Documents** heading for a selection bar with **Select all N** and **Clear**. Select all reaches every document, or every match when a search is applied.
- ⌘A / Ctrl+A ticks all loaded rows, and Esc clears the selection.
- One export holds up to 500 documents. Bulk delete sends at most four requests at once.

## Costs

- The cost-per-document section has a **Chart / Table** switch.
- **Export**, beside the date range, downloads one workbook for the selected range. It has Summary, Daily or Hourly, By template and Documents sheets.
- Search interpretation spend appears on the overview as a separate **Search** line. It isn't included in document totals.

## Other changes

- **Auth screens:** sign-in, sign-up and reset password report problems and sent links as toasts, and outline the field at fault.
- **Empty workspace:** shows an upload prompt, or a prompt to set up a Model gateway.
- **Emails:** verification and password-reset emails are styled HTML with a plain-text part. Links in them are escaped.
- **Template assistant suggestions:** they no longer fail when the model adds extra properties or slightly overlong text.

## API

- **New routes:**
  - `POST /v1/jobs/search` searches jobs by metadata, extracted values and cost, with keyset paging.
  - `GET /v1/search/catalog` lists the searchable templates and fields.
  - `POST /v1/jobs/retry` queues failed jobs again on the template's current version.
  - `POST /v1/search/interpret` turns a request into an action and a filter.
  - `GET /v1/workspaces/{id}/costs/export` returns cost data for a whole range.
- **Changed route:** `POST /v1/jobs/export` accepts `format: "xlsx" | "csv" | "json"`. It defaults to `xlsx`, as before.
- **Errors:** new codes `invalid_search_filter`, `invalid_job_retry`, `invalid_job_export` and `search_interpretation_*`.
- **Cost search:** filtering by cost returns `403 forbidden` for callers who can't read costs.

See the [API overview](https://github.com/AlexWhitehouse/local-document-extraction/blob/v2.5.0/mkdocs/docs/api/overview.md).

## Upgrading and compatibility

The release workflow checks **Ubuntu 24.04 x64 and arm64, and macOS 15 arm64**. Intel macOS binaries are bundled but not qualified by the CI matrix.

Stop the application. Back up its configuration and state. Then run:

```bash
document-extraction update v2.5.0
```

- **Workspace databases:** each one adds an index of extracted values (schema 17) and a table for search interpretation costs (schema 18) the first time it opens.
  - The index is backfilled from existing results at that point. Workspaces with many documents take longer to open the first time.
  - All changes are additive, and existing data is kept.
- **Settings:** no settings or defaults change.
- **Original-file cleanup:** the retention sweep now records a deletion intent before removing a failed document's original, so cleanup interrupted by a stop resumes on the next sweep.

## Known limits

- Search covers scalar fields only: text, number, date and yes/no.
- A template is recognised by its full name or by its name without words like "template" or "form". A short name shared by several templates goes to the model.
- "Or" is only understood between statuses or between templates. Other "or" requests are reported as unsupported rather than guessed.
- Plain-word search ignores case only for unaccented letters in document names, as before. Extracted values ignore case fully.
- Plain-language requests that need the model only work when a Model gateway is configured. The palette explains this when it isn't.
