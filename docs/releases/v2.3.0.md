# v2.3.0 — Template assistant everywhere

This release makes the Template assistant one simple panel that works on Templates, Documents and Evaluations, and connects it to Evaluation results so you can fix failing fields and test the fix. It adds Evaluation shortcuts, lets owners demote admins, and warns before unsaved template edits are lost. It also fixes a denial-of-service issue in template validation and speeds up document listing, search and background work ([#72](https://github.com/AlexWhitehouse/local-document-extraction/pull/72)).

## Security

- Saving or checking a template no longer stalls the server on crafted field descriptions. Table-schema markers were parsed with patterns whose cost grew faster than the description length: 4,000 characters took 12.7 seconds of blocking CPU, and any signed-in user or Workspace API key could send one. Parsing is now linear time.

## Template assistant

- **One request box:** ask a question, describe a change, or leave it empty and select **Review draft** to have the assistant review the draft and its evidence and propose fixes. The **Explain issues** and **Propose edits** tabs are gone. Proposed edits are still reviewed and applied by you.
- **Suggestions:** possible problems come first, then useful additions. With a document attached they start with fields that were not found, invalid, unreadable or below 60% confidence; with Evaluation results attached, with the fields that failed verified expected answers. Selecting a suggestion sends it; its edit icon only fills the request.
- **Docked panel:** on wide windows the assistant runs the full height of the page on both Templates and Evaluations.
- **Improve template** on a completed document opens its template with the assistant, that document and its retained original attached, and a request naming its weak fields.
- **Evaluations:**
  - The magic-wand button beside a candidate's menu, **Improve failing fields**, opens the assistant with the candidate's failing fields and their verified expected answers. For this evidence the model treats verified answers as ground truth. **Ask assistant** in the menu opens it without evidence.
  - After applying edits, **Test changes** runs them on a copy of the candidate and compares overall and per-field accuracy before and after. **Apply to candidate**, or **Apply to template** in a model comparison, applies them directly.

## Evaluations

- **Accept all answers…** sets a candidate's answers as verified expected answers for one document, or for every document. Verified answers that differ are only replaced when you choose to overwrite them, and the toast offers **Undo**.
- **Use for extraction…** sets the best model, or any model candidate, as the Workspace extraction model. It keeps the gateway and stored credential, and only owners and admins can use it.
- Ties for **Best** are broken by table cells, then reported cost, then processing time.

## Workspaces and editing

- Owners can demote an admin with **Make member**. Every member change updates open tabs, so permissions change straight away.
- Leaving a template editor with unsaved changes asks first. This covers the Templates editor and the Evaluation template editor, and sidebar links, template and workspace switches, Back/Forward, sign-out, the editor's close controls, and refresh or close. Saving never asks. The Model gateway form also asks before discarding edits.

## Performance and reliability

- Grouped Document lists load each page in a fixed number of queries, and reading a packet no longer writes to the database. A packet is marked finished when its last document finishes.
- Grouped search uses the search index, including a new index on packet names, and paging stays correct when documents share a timestamp.
- The extraction queue keeps each Workspace's concurrency in memory instead of reading it from the database on every scheduling pass.
- Workspace databases skip schema setup when already current. The background pass visits only Workspaces that may have pending work, with a full sweep at startup and every 15 minutes. Source storage is measured every 15 minutes instead of every minute.
- After a crash or restart, interrupted documents are retried immediately instead of after about five minutes.

## Upgrading and compatibility

Bun remains pinned to **1.4.2**. The release workflow checks **Ubuntu 24.04 x64 and arm64, and macOS 15 arm64**. Intel macOS binaries are bundled but not qualified by the CI matrix.

Stop the application. Back up its configuration and state. Then run:

```bash
document-extraction update v2.3.0
```

Each Workspace database applies two migrations the first time it opens: a search index on packet names, and a one-time pass that marks packets finished when all their documents already are. Configuration settings and defaults are unchanged.

The Template assistant request endpoints are browser-only. Suggestion requests no longer take an `action`, and an assistance request no longer needs instructions.

## Known limits

- Model context, request-size and rate limits still apply.
- Evaluation evidence is limited to 128 KiB; very large batches leave out some failing fields and say how many.
- Simulated model tests do not qualify live model routes, Google sign-in or Cloudflare email delivery.
