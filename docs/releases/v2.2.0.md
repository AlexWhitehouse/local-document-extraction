# v2.2.0 — Consistent interface

This release brings the Studio interface onto one set of shared components, design tokens and copy rules ([#64](https://github.com/AlexWhitehouse/local-document-extraction/issues/64)). It also fixes extraction failures on Markdown-fenced model JSON and stops instruction-only Template edits from asking you to review saved Evaluation answers again.

## Interface changes

- **Dialogs and feedback:** confirmations and modals use the same in-app dialogs, and a page never shows a native browser dialog. Outcomes appear as toasts at the top centre of the page, and form errors stay beside their fields.
- **Undo:** removing something that only exists in a draft offers Undo instead of asking for confirmation.
- **Page states:** loading, error and empty states look and behave the same on every page. A list that fails to load offers **Try again** instead of showing the empty state.
- **Shared components:** every page uses one page header, with breadcrumbs, a one-line description and an overflow menu. Buttons, icons, status labels, tabs, form fields, tables, tooltips, drop zones and paging are shared, and dropdown chevrons use the same inset everywhere.
- **Small screens:** layouts work on narrow windows, and the sidebar becomes a drawer.
- **Copy:** UI text follows one set of guidelines, with lowercase domain nouns and UK spelling.
- **Live updates:** the live-updates banner appears only for a sustained outage, not for brief reconnects.
- **Packets:** switching documents no longer reloads the packet page. The page doesn't flash, the tab list keeps its scroll position, and the header stays the same height.
- **Uploads:** the upload modal closes once every file is queued. It stays open only to show failures.
- **Model gateway:** **Test connection** sits beside **Edit**. The edit form mirrors the read-only view: the same rows and columns, and model names in the same mono font.
- **Costs:** table headers line up with their numeric columns, and the Documents tab toolbar no longer squeezes its filters. In documents and packets, the cost breakdown lists amounts in one column and stays open while the pointer is over it.
- **Evaluations:** the setup screen no longer has stray dividers. **Used in this workspace** lists models by most recent use.
- **Sign-in:** password fields show a masked placeholder.

## Processing changes

- Extraction accepts valid JSON wrapped in one complete Markdown code fence, labelled `json` or unlabelled. Some models, including Haiku, return this format, which previously failed every attempt. Malformed responses are still rejected and retried. Evaluations now show a fixed response-format error without exposing model output.
- Editing only a Template's field or column instructions reuses verified Evaluation answers. It no longer opens the change-review flow or creates duplicate Expected answer Template choices. Structural changes still require review.
- The Workspace model list (`/v1/jobs/filter-options`) now returns models ordered by most recent use instead of alphabetically. The Documents model filter still sorts its options alphabetically.

## Upgrading and compatibility

Bun remains pinned to **1.4.2**. The release workflow checks **Ubuntu 24.04 x64 and arm64, and macOS 15 arm64**. Intel macOS binaries are bundled but not qualified by the CI matrix.

Stop the application. Back up its configuration and state. Then run:

```bash
document-extraction update v2.2.0
```

This release adds no database migrations, and state remains compatible with v2.1.1. Configuration settings and defaults are unchanged.

## Known limits

- Model context, request-size and rate limits still apply.
- Simulated model tests do not qualify live model routes, Google sign-in or Cloudflare email delivery.
