# v1.1.0 — Extraction throughput and interface reliability

This release increases default extraction concurrency. It also stabilizes document previews during interface updates and clarifies actions that require browser sign-in.

## Extraction throughput

- Extraction starts with **16 simultaneous jobs**, increased from 8. Adaptive concurrency stays enabled by default with a ceiling of **32**. It responds to resource pressure and model throttling.
- Explicit `EXTRACTION_MAX_CONCURRENCY` settings remain unchanged. Installations set to `8` keep that value. To use the new default, remove or change the override and restart. The starting value must not exceed `EXTRACTION_MAX_CONCURRENCY_LIMIT`.
- If only `EXTRACTION_MAX_CONCURRENCY_LIMIT` is configured below 16, set `EXTRACTION_MAX_CONCURRENCY` at or below that limit before the upgrade. Otherwise, the new default exceeds the limit and validation prevents startup.

## Interface and integration fixes

- Document and packet previews remain loaded during unrelated actions, such as opening Upload or changing a Template selection.
- Packet tables scroll within a fixed maximum height. Large packets no longer expand the complete page.
- Template footer text explains unsaved changes and save actions more clearly. The duplicate Documents toolbar upload action is removed. Evaluation mode diagrams match their descriptions.
- The Postman collection removes duplicate slashes from submission polling URLs.

## Browser assistance and review

Workspace members use **Templates → Assistant** for explanations and proposed edits. They use **Documents** to confirm page groups or select a Template for held work. These actions require app sign-in. Workspace API keys cannot perform them.

Integrations can still submit documents and poll packets and jobs with Workspace API keys. For `awaiting_review` or `awaiting_template`, a user must resolve the hold in the frontend. Sample-based generation through `/v1/templates/generate` remains available to API clients. Before upgrading, adapt integrations that used API keys for assistance or manual review.

## Upgrading and compatibility

Bun remains pinned to **1.4.2**. Automated qualification covers **Ubuntu 24.04 x64 and arm64, and macOS 15 arm64**. The installer recognizes Intel macOS. This release's CI does not qualify Intel macOS or older operating systems.

Stop the application. Back up its configuration and state. Then run:

```bash
document-extraction update v1.1.0
```

This release adds no database migrations or required environment variables relative to v1.0.0. The installer keeps configuration, accounts, documents, and generated secrets. It backs up local state before migration checks. Back up S3 buckets separately. Before a downgrade, restore the backup from before the upgrade.

## Known limits and validation

- Higher concurrency can increase simultaneous model calls and memory use. Explicit overrides and existing resource controls remain available.
- Automatic processing can require user review. Model capability, context, and request-size limits still apply.
- S3 buckets must not use object versioning or Object Lock. Local backups exclude S3 originals. Source downloads do not support byte ranges.

The release workflow validates the exact tagged commit before publishing `install.sh`, `document-extraction.tar.gz`, and its SHA256 checksum. Automated checks do not qualify live Google sign-in, Cloudflare email delivery, or every third-party model route.
