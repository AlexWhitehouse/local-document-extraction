# v1.1.0 — Extraction throughput and interface reliability

This release raises the default extraction concurrency, keeps document previews stable during other interface updates, and clarifies which operations require a signed-in user.

## Extraction throughput

- Extraction now starts with **16 simultaneous jobs**, up from 8. Adaptive concurrency remains enabled by default with a ceiling of **32** and continues to respond to resource pressure and model throttling.
- Explicit `EXTRACTION_MAX_CONCURRENCY` settings are preserved. Existing installations that set it to `8` keep that value; remove or change the override and restart to use the new default. The starting value must not exceed `EXTRACTION_MAX_CONCURRENCY_LIMIT`.
- If you configured only `EXTRACTION_MAX_CONCURRENCY_LIMIT` below 16, set an explicit `EXTRACTION_MAX_CONCURRENCY` at or below that limit before upgrading. Otherwise, the new starting default exceeds your limit and configuration validation prevents startup.

## Interface and integration fixes

- Document and packet source previews no longer reload during unrelated interface interactions, such as opening an upload dialog or changing a template selection.
- Packet overview tables scroll within a bounded height so large packets do not expand the entire page.
- Template footer text makes unsaved changes and save actions clearer. The duplicate Documents toolbar upload action is removed, and Evaluation mode diagrams align with their descriptions.
- The Postman collection fixes duplicated slashes in submission polling URLs.

## Browser assistance and review

Workspace members now use **Templates → Assistant** for explanations and proposed edits, and **Documents** to confirm page groups or choose a Template for held work. These actions require signing in to the app and are unavailable to Workspace API keys.

Integrations can still submit documents and poll packets and jobs using Workspace API keys. When processing reaches `awaiting_review` or `awaiting_template`, a user must resolve it in the frontend. Sample-based template generation through `/v1/templates/generate` remains available to Workspace API clients. Integrations that previously used API keys for assistance or manual review must adapt before upgrading.

## Upgrading and compatibility

Bun remains pinned to **1.4.2**. Automated release qualification covers **Ubuntu 24.04 x64 and arm64, and macOS 15 arm64**. Intel macOS is recognized by the installer but is not qualified by this release's CI; older operating systems are also outside that qualification.

Stop the application and back up its configuration and state before running:

```bash
document-extraction update v1.1.0
```

There are no new database migrations or required environment variables relative to v1.0.0. The installer preserves configuration, accounts, documents, and generated secrets, and backs up local state before migration checks. Back up any S3 bucket separately. Restore the pre-upgrade backup before downgrading.

## Known limits and validation

- Higher default concurrency can increase simultaneous model requests and memory use; explicit concurrency overrides and existing resource controls remain available.
- Automatic document processing can require user review, and model capability, context, and request-size limits still apply.
- Existing source-storage limits remain: S3 buckets must not use object versioning or Object Lock, S3 originals are not included in local backups, and source downloads do not support byte ranges.

The release workflow validates the exact tagged commit before publishing `install.sh`, `document-extraction.tar.gz`, and its SHA256 checksum. Automated tests do not qualify live Google sign-in, Cloudflare email delivery, or every third-party model route.
