# Delegated MCP access in the existing local runtime

Issue 71 extends browser-only Workspace operations with explicit OAuth delegation. It preserves ADR-0005's single Bun runtime, ADR-0008's Workspace-owned Model gateway, ADR-0011's portable installation configuration and ADR-0015's temporary Evaluation boundary. Application admin and account management remain outside delegation.

Use Better Auth's MCP plugin, which includes the OAuth provider, with the JWT plugin and official TypeScript server SDK. Do not mount a second OAuth provider or turn on bearer-to-session authentication. Better Auth and its extensions are 1.7.7; the server SDK is 2.3.1. OAuth tables and application grant bindings live in control SQLite. Discovery uses the configured canonical origin. The SDK serves modern requests and stateless legacy traffic; no persistent subscriptions or distributed state are introduced.

A grant binds one user, one OAuth client, one accepted Workspace and a scope ceiling. Each authorization creates a distinct grant. A verified token identifies that grant; tool arguments cannot select an actor or Workspace. Token/grant scope intersection, live account eligibility, membership/role and installation policy apply independently of tool discovery. Browser context switching is irrelevant. Short-lived JWTs still require a live grant lookup, so revocation takes effect immediately.

Access tokens last five minutes, signed consent/code requests ten minutes, approvals ten minutes, uploads fifteen minutes and grants at most thirty days. Refresh rotation does not extend the grant ceiling. Session-bound grants end with their authorizing session; expressly approved offline grants survive normal logout. Password reset revokes grants. Impersonated sessions cannot create or exercise delegated approvals. Bounded dynamic client registration is available whenever MCP is enabled; self-registered client identity is unverified. CIMD and arbitrary file URL fetching are excluded.

Revised on 2026-10-11 at the installation owner's request: remove the operator-managed callback allowlist so clients can register without deployment changes. Accept one to eight HTTPS callbacks per client, with HTTP restricted to loopback, and reject credentials, fragments, wildcards, whitespace and control characters. Authorization still requires an exact registered callback and PKCE; sign-in and Workspace consent remain mandatory. Keep registration rate limits and the 1,000-client installation cap. The former `MCP_ALLOWED_REDIRECT_URIS` setting has no effect.

Routine reads, submissions and explicit Template saves can execute directly within scopes. All Workspace administration, Model gateway changes/tests and deletions use exact-action browser approval, including invitations and single-item deletion. Approval binds canonical input and target state and is consumed atomically. Execution rechecks current session/role/grant and target revision at commit. Raw API keys and gateway credentials are confined to authenticated browser entry/one-time response; MCP receives only non-secret results.

Reuse domain validation, shared product-store access, submission admission, reservations, lifecycle fences, retained-source boundaries and Go processing. The authenticated app upload page provides file transfer independent of any client's attachment mechanism. Previously admitted extraction is durable work and is not cancelled by disconnecting a client or grant.

Idempotency is scoped by grant, Workspace, action and input hash. Control mutations, completion and activity are one transaction. Product mutations and a recovery receipt are one product transaction; retry/status lookup reconciles control completion and audit after a crash. Deterministic submission IDs recover already-admitted work. An external gateway test has no atomic remote receipt: interrupted outcomes are explicit and are never automatically retried. Workspace deletion retains its existing durable erase intent.

Security activity is operator-only control data, distinct from product analytics. It stores identity/action references and outcomes without credentials, filenames or contents. Activity and inactive operation/grant data have ninety-day retention. Cleanup runs on request activity; upload cleanup is bounded. Complete backups include databases and matching machine keys. Restoring old state requires disabling MCP and revoking restored grants before exposure, because an older backup cannot know later revocations.

MCP and sensitive administration default off separately. Claude Desktop and ChatGPT are the selected release targets. Local OAuth, negative-permission, durability and real-browser tests support the implementation; they do not establish real-client compatibility. The installation owner will complete the public HTTPS client checklist in `docs/mcp.md` before rollout.
