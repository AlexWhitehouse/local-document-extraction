# Durable template routing and document packets

Automatic template selection defers the Template binding until document assessment, and Smart splitting introduces a packet that owns its original separately from child extraction jobs. These are durable product states in the existing Workspace queue, so interruption cannot silently repeat model decisions, change page boundaries, lose a held source, or create duplicate children.

The request must supply an explicit Template ID or nonempty canonical tags. An explicit ID pins its version at acceptance; otherwise any matching tag defines the complete eligible candidate pool. Classification receives the document and candidate IDs, names, and descriptions only. The stored candidate snapshot additionally captures current version and tag membership; automatic binding revalidates that snapshot atomically before pinning a version. An empty or unsuitable pool never widens silently. Authorized manual resolution may select another usable Template.

Splitting and blank exclusion are authoritative Workspace switches, both disabled by default, captured with accepted work. Exclusion is part of splitting and cannot run independently. A split plan exactly covers selected physical pages with groups or explicit exclusions. Automatic blank exclusions require conservative independent verification: no extracted text, annotations, or nonwhite rendered pixels. All-blank packets complete successfully without child jobs. Manual review uses a revision precondition, and empty manual plans still require server verification.

Each packet split decision and each child's classification has one initial assessment plus up to two targeted reassessments. Consumed rounds survive restart and configuration changes; transport retries are separately bounded. The shared Document classification & splitting model role inherits Extraction unless explicitly configured, and honors the Workspace gateway, credential, capability flags, and sequencing policy. Final field extraction continues to use Extraction. A committed plan and Template binding survive later extraction retries.

A committed plan reserves stable child identities before materialization. Each child owns an independent derived PDF and original-page map, so native PDF and rendered-image requests contain only its pages. Child deletion leaves a tombstone; packet deletion prevents late work from creating children. Packet S3 originals have a distinct manifest owner kind, preserving independent cleanup and recovery across control/product databases. Held work retains necessary sources regardless of completed-original retention. Failed packet cleanup follows the existing failed-source grace period; terminal materialization failure records cleanup intents for abandoned reserved artifacts while preserving accepted children.

This extends ADR-0006/0009's durable scheduling, ADR-0008's Workspace configuration, ADR-0010's shared preparation memory, ADR-0012's disposable guarded PDF parser, and ADR-0013's retention ownership. PDF subsets are created after memory and sequencing admission; fan-out holds a shared reservation until derivatives are persisted. Materialization/preview processes have cancellable deadlines and source/output/concurrency bounds. Bounds produce actionable holds or errors, never arbitrary page/candidate truncation. This implementation uses bounded direct assessment rather than an OCR index, full extraction against every candidate, or unlimited model reassessment; configured-model decision quality still needs representative document evaluation.
