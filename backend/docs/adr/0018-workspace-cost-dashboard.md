# Workspace cost dashboard

The dashboard covers document processing only: Smart split, automatic Template selection and Extraction, including retries. Costs belong to the original upload's UTC date, including child Documents created later and subsequent calls. All models contributing to a Document remain together. Gateway-reported USD costs remain authoritative; unknown costs are neither estimated nor treated as free.

Support 100,000 Documents per month and queries spanning up to 366 days. Retain full history, selectable in bounded windows; the range limit is not a retention limit. Hourly queries span at most 24 whole UTC hours. Presets include the current UTC hour/day. The dashboard requires an accepted owner/admin user session on every endpoint. API keys and ordinary members cannot read dashboard endpoints; existing Document/packet API cost visibility remains unchanged.

Document/packet deletion retains accounting snapshots and receipts, including names, Template names, page counts, original page numbers and packet lineage. Capture snapshots transactionally before deleting product metadata, even before historical backfill reaches the record. Late receipt finalization can update retained costs but cannot recreate product records. Workspace erasure removes the entire accounting history. Accounting metadata is Workspace product data, not the privacy-filtered analytics log. Older records already erased under the previous policy cannot be recovered.

Reserved split children resolve Template names from the selected Template before their jobs exist. Refreshes replace unresolved name placeholders when Template metadata is available and preserve already resolved historical names. An incremental repair walks retained uploads before resuming the normal historical backfill, so deleted records can also recover missing names without rebuilding accounting history during startup.

Workspace totals count each packet's split cost once and include excluded-page overhead. Per-document/per-page averages and distributions use terminal (completed or failed), fully reported Documents with known positive page counts; queued and partially reported Documents are excluded. Document figures include their allocated split shares. Excluded pages remain packet overhead and do not enter document averages. Zero-cost completed work is valid. Unknown totals and incomplete known subtotals remain distinct. Comparisons require complete costs and available prior history.

SQLite receipts stay separate from rebuildable hourly/daily summaries and indexed upload/Document accounting snapshots. Relevant product and receipt mutations enqueue one durable dirty upload ID in the original transaction. A shared, round-robin background scheduler updates at most 50 uploads or roughly 8 ms per transaction, with a 50 ms scheduling interval and one global budget across open stores. Each upload refresh aggregates only that upload's calls and children, then applies a delta to its two time buckets. This avoids scans of all receipts on dashboard reads. One large upload remains the minimum indivisible work unit. Store closure stops its scheduled work.

Historical backfill uses durable rowid cursors in bounded transactions. It resumes after restart, prioritizes current dirty uploads, and exposes an incomplete-history state. Never perform the full historical backfill during a migration or HTTP request. Snapshot updates, bucket deltas and queue/cursor progress commit together. A failed batch stays pending; it never repeats model transport.

Overview reads at most 366 current and 366 prior daily summaries (24 each for hourly ranges). Distributions return at most 512 deterministic bottom-hash samples, stratified by time bucket and weighted by exact bucket populations. Percentiles are labelled estimates whenever sampled. Template groups are capped at 12, including Other templates, and their table shows sample counts and percentile estimates rather than presenting sample spend as a Workspace total.

The Documents list returns at most 50 uploads. Recent order uses a date/ID index. Cost and per-page order merge bounded daily or hourly index walks rather than sorting the full range. Trigram search probes up to eight single-trigram posting lists, capped at 2,001 candidates each; a selective candidate set is then verified against the whole literal and sorted. Avoid full-phrase FTS queries: LIMIT bounds returned matches but not the work needed to find them. Broad or short literal searches inspect up to 200 ordered candidates per request and return a continuation even when none match. Cursor parameters are tied to the date range and filters. Packet details load separately. Frontend reads abort on scope changes and refresh every 30 seconds only while visible. Access errors remove previously shown data.

Validate accounting, restart/rollback, deleted metadata, late calls, role enforcement, cursor traversal and range bounds with focused tests; exercise real application navigation and deletion in the browser. `bun --no-env-file backend/benchmarks/workspaceCosts.bench.ts` seeds 1.2 million completed accounting snapshots and measures summaries, samples, searches, sorted pagination and serialization while interleaving actual job/receipt/completion writes. This is a synthetic local-store benchmark, not a network or gateway throughput claim.
